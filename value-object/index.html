Value Object

CreationNot in the book

A banknote: any 100-pound note equals any other, and nobody can edit what’s printed on it.

The rule to rememberA value with rules (money, email, date range) → a small immutable class that checks itself and is compared by value.

Without it: the pain

Money as float: 0.1 + 0.2 ≠ 0.3, EGP added to USD, negative totals, and the same checks copied everywhere.

With it: the fix

Money stores integer piastres, refuses bad input, and add() returns a NEW Money. It can never be invalid.

Reach for it when you see

  • float for money
  • The same validation of a value (email, phone, range) in many places
  • Arrays like ['amount' => …, 'currency' => …] passed around

Real job where it fits

Invoices with prices, shipping and discounts, in more than one currency.

Before: the code that hurts

$total = $price + $shipping;           // 0.1 + 0.2 = 0.30000000000000004
$total = $priceEgp + $feeUsd;          // EGP + USD, no error
if ($total < 0) { /* this check is copied in 6 places, and missing in 2 */ }

Build it yourself: the full Value Object pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

Value objectMoney
Rule 1, can't changeevery property is readonly
Rule 2, checks itselfthe constructor refuses bad values
Rule 3, equal by valueequals() compares amounts, not object identity
Rule 4, returns new objectsadd() never changes $this
<?php

declare(strict_types=1);

final class Money  // Value object
{
    public function __construct(
        public readonly int $amount,  // rule 1: readonly. Stored in piastres, never a float
        public readonly string $currency,
    ) {
        if ($amount < 0) {  // rule 2: an invalid Money can never exist
            throw new InvalidArgumentException('Money cannot be negative.');
        }
        if (strlen($currency) !== 3) {
            throw new InvalidArgumentException("Invalid currency [{$currency}].");
        }
    }

    public static function egp(int $pounds): Money
    {
        return new Money($pounds * 100, 'EGP');
    }

    public function add(Money $other): Money
    {
        if ($other->currency !== $this->currency) {
            throw new LogicException("Cannot add {$other->currency} to {$this->currency}.");
        }

        return new Money($this->amount + $other->amount, $this->currency);  // rule 4: a NEW object
    }

    public function equals(Money $other): bool  // rule 3: same value = equal
    {
        return $this->amount === $other->amount && $this->currency === $other->currency;
    }

    public function format(): string
    {
        return number_format($this->amount / 100, 2) . ' ' . $this->currency;
    }
}

// ── Why integers: floats can't store some decimals exactly ──
var_dump(0.1 + 0.2 === 0.3);                               // bool(false)

// ── Rule 4 in action: always keep the returned object ──
$price = Money::egp(100);
$price->add(Money::egp(20));                                // ✗ the result is thrown away
echo $price->format() . "\n";                              // still 100.00 EGP

$price = $price->add(Money::egp(20));                       // ✓ keep the new object
echo $price->format() . "\n";                              // 120.00 EGP

// ── Rule 3: two different objects, same value ──
var_dump(Money::egp(5)->equals(new Money(500, 'EGP')));     // bool(true)

// ── Rule 2: mistakes are caught immediately ──
try {
    Money::egp(10)->add(new Money(500, 'USD'));
} catch (LogicException $e) {
    echo $e->getMessage() . "\n";
}

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

final class Money
{
    public function __construct(
        public readonly int $amount,  // smallest unit (piastres): exact math
        public readonly string $currency,
    ) {
        if ($amount < 0) {
            throw new InvalidArgumentException('Money cannot be negative.');  // can't exist invalid
        }
        if (! preg_match('/^[A-Z]{3}$/', $currency)) {
            throw new InvalidArgumentException("Invalid currency [{$currency}].");
        }
    }

    public function add(Money $other): self
    {
        if ($other->currency !== $this->currency) {
            throw new LogicException("Cannot add {$other->currency} to {$this->currency}.");
        }

        return new self($this->amount + $other->amount, $this->currency);  // a NEW object
    }

    public function equals(Money $other): bool
    {
        return $this->amount === $other->amount && $this->currency === $other->currency;
    }
}

// Eloquent cast: the column stays an integer, your code only ever sees Money
final class MoneyCast implements \Illuminate\Contracts\Database\Eloquent\CastsAttributes
{
    public function get(Model $model, string $key, mixed $value, array $attributes): Money
    {
        return new Money((int) $value, $attributes['currency']);
    }

    public function set(Model $model, string $key, mixed $value, array $attributes): array
    {
        return [$key => $value->amount, 'currency' => $value->currency];
    }
}

$total = $total->add($shipping);  // always keep the return value

How Laravel builds it inside: Str::of('text') returns a Stringable: each method like upper() returns a NEW Stringable and leaves the original unchanged. CarbonImmutable does the same for dates. A custom Eloquent cast turns a database column into your own value object and back.
