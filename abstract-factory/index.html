Abstract Factory

CreationGoF book

An IKEA collection: pick one style, and the table, chair and lamp all match.

The rule to rememberSeveral objects must come from the same family → one factory creates the whole family, so they can never be mixed.

Without it: the pain

S3 storage with a database queue and a log mailer: pieces from different setups, wired by hand, easy to mix.

With it: the fix

Pick one kit (AWS or Local). Storage, queue and mailer all come from that kit and always match.

Reach for it when you see

  • Several new X() calls that must "go together"
  • Bugs from mixing a production piece with a dev piece
  • The same if ($env) repeated for 3+ related objects

Real job where it fits

Production runs on AWS (S3, SQS, SES). Local dev uses disk, database queue and log mailer.

Before: the code that hurts

$storage = app()->isProduction() ? new S3Storage(...)  : new DiskStorage(...);
$queue   = app()->isProduction() ? new SqsQueue(...)   : new DatabaseQueue(...);
$mailer  = app()->isProduction() ? new LogMailer(...)  : new SesMailer(...);   // ← swapped by mistake

Build it yourself: the full Abstract Factory pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

Abstract factoryInfrastructureKit one create method per product in the family
Concrete factoriesCloudKit, LocalKit each makes a whole matching family
Abstract productsFileStorage, MessageQueue
Concrete productsBucketStorage + RemoteQueue cloud family), DiskStorage + MemoryQueue (local family
ClientReportPublisher uses a kit; can never mix families
<?php

declare(strict_types=1);

interface FileStorage  // Abstract product A
{
    public function put(string $path, string $contents): string;
}

interface MessageQueue  // Abstract product B
{
    public function push(string $message): void;
}

interface InfrastructureKit  // Abstract factory
{
    public function storage(): FileStorage;

    public function queue(): MessageQueue;
}

// ── Family 1: cloud ─────────────────────────────────────────────────────
final class BucketStorage implements FileStorage
{
    public function __construct(private readonly string $bucket) {}

    public function put(string $path, string $contents): string
    {
        return "https://{$this->bucket}.storage.example.com/{$path}";   // pretend upload
    }
}

final class RemoteQueue implements MessageQueue
{
    public function push(string $message): void
    {
        echo "  [remote queue] {$message}", PHP_EOL;
    }
}

final class CloudKit implements InfrastructureKit  // Concrete factory: cloud family
{
    public function __construct(private readonly string $bucket) {}

    public function storage(): FileStorage
    {
        return new BucketStorage($this->bucket);
    }

    public function queue(): MessageQueue
    {
        return new RemoteQueue();
    }
}

// ── Family 2: local development ─────────────────────────────────────────
final class DiskStorage implements FileStorage
{
    public function __construct(private readonly string $dir) {}

    public function put(string $path, string $contents): string
    {
        $file = $this->dir . '/' . basename($path);
        if (file_put_contents($file, $contents) === false) {
            throw new RuntimeException("Cannot write {$file}");
        }

        return $file;
    }
}

final class MemoryQueue implements MessageQueue
{
    /** @var list<string> */
    public array $messages = [];

    public function push(string $message): void
    {
        $this->messages[] = $message;
        echo "  [memory queue] {$message}", PHP_EOL;
    }
}

final class LocalKit implements InfrastructureKit  // Concrete factory: local family
{
    public function storage(): FileStorage
    {
        return new DiskStorage(sys_get_temp_dir());
    }

    public function queue(): MessageQueue
    {
        return new MemoryQueue();
    }
}

// ── Client: only knows the abstract factory ─────────────────────────────
final class ReportPublisher  // Client
{
    public function __construct(private readonly InfrastructureKit $kit) {}

    public function publish(int $reportId, string $pdf): void
    {
        $location = $this->kit->storage()->put("report-{$reportId}.pdf", $pdf);  // both products...
        $this->kit->queue()->push("report {$reportId} ready at {$location}");  // ...from the SAME family
    }
}

// ── The ONE decision ────────────────────────────────────────────────────
$production = getenv('APP_ENV') === 'production';
$kit = $production ? new CloudKit('school-reports') : new LocalKit();

echo $production ? 'Production:' : 'Local:', PHP_EOL;
(new ReportPublisher($kit))->publish(42, '%PDF-1.7 ...');
@unlink(sys_get_temp_dir() . '/report-42.pdf');               // tidy up the demo file

echo 'Cloud:', PHP_EOL;
(new ReportPublisher(new CloudKit('school-reports')))->publish(43, '%PDF-1.7 ...');

Highlighted lines are the ones that make it this pattern. Run it: php examples/abstract-factory.php · Open the file on GitHub

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

interface CloudKit  // one method per family member
{
    public function storage(): FileStorage;
    public function queue(): MessageQueue;
    public function mailer(): Mailer;
}

final class AwsKit implements CloudKit
{
    public function __construct(private \Aws\Sdk $aws) {}

    public function storage(): FileStorage { return new S3Storage($this->aws->createS3()); }
    public function queue(): MessageQueue  { return new SqsQueue($this->aws->createSqs()); }
    public function mailer(): Mailer       { return new SesMailer($this->aws->createSesV2()); }
}

final class LocalKit implements CloudKit
{
    public function storage(): FileStorage { return new DiskStorage(storage_path('app')); }
    public function queue(): MessageQueue  { return new DatabaseQueue(DB::connection()); }
    public function mailer(): Mailer       { return new LogMailer(Log::channel('mail')); }
}

// AppServiceProvider: the ONE decision
$this->app->singleton(CloudKit::class, fn ($app) => $app->isProduction()
    ? new AwsKit(new \Aws\Sdk(['region' => config('services.aws.region'), 'version' => 'latest']))
    : new LocalKit());  // everything below matches

$kit = app(CloudKit::class);
$kit->storage()->put('reports/42.pdf', $pdf);
$kit->queue()->push(new ReportReady(42));

How Laravel builds it inside: Database connections: each Connection class makes its own matching family through getDefaultQueryGrammar(), getDefaultSchemaGrammar() and getDefaultPostProcessor(). A MySqlConnection always comes with MySQL grammars, a SQLiteConnection with SQLite ones, so SQL written for one database is never sent to another.
