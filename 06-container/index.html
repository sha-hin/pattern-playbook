New ticket

"Make Database a Singleton so we stop passing PDO around"

From Code review, pull request #212

TermReport now needs five objects, each repository needs the connection, and the top of every script is 30 lines of new. This PR adds Database::connection() so any class can grab the connection itself. Approve?

Why the quick fix is a trap

The pull request uses the classic Singleton from the Gang of Four book: a private constructor and a static method that always returns the same instance.

the quick fix (we won’t do this)
final class Database
{
    private static ?PDO $connection = null;

    private function __construct() {}           // nobody else can create one

    public static function connection(): PDO
    {
        return self::$connection ??= new PDO('sqlite:/var/lib/evalu8.db');
    }
}

// ...inside SqliteResponseRepository:
$select = Database::connection()->prepare('SELECT ...');

It does remove the wiring, and that is why Singletons are tempting. But it costs a lot:

Hidden dependency. Reading SqliteResponseRepository’s constructor no longer tells you it needs a database. You find out by reading every line.

One connection, forever. The nightly Ministry export should read from a replica database. With Database::connection() hard-coded inside every repository, there is no way to give one script a different connection.

Global state. Anything any class does to the shared connection (a transaction left open, a changed setting) leaks into every other class.

The real need is: "build each object once, and hand it to the classes that need it". That is a job for one object that knows how to build everything: a container.

The pattern: Dependency Injection Container

Remember itClasses ask for what they need in their constructor and never build it themselves → one container knows how to build everything, and keeps one shared instance where you ask it to.

Our classes already follow dependency injection: TermReport receives its repositories in its constructor instead of creating them. The container only automates the wiring: $app->make(TermReport::class) reads the constructor, sees it needs a TeacherRepository, a ResponseRepository and so on, and builds each of those the same way.

Interfaces can’t be built, so we tell the container once which class to use for each (TeacherRepository → SqliteTeacherRepository). Everything else is automatic.

singleton() gives us what the Singleton pattern promised (one shared PDO) without the static global: the classes still receive the connection in their constructor, and a different script can bind a different connection.

Singleton is in the Gang of Four book; the DI container is not (the term was popularised by Martin Fowler in 2004). Most modern PHP code uses the container’s singleton instead of the Singleton pattern.

  2. 2The container

    bind() and singleton() register a function that builds something. make() uses that function if there is one; otherwise it autowires: it reads the class’s constructor with PHP’s Reflection API and builds each typed parameter by calling make() again.

    It refuses loudly instead of guessing: an interface with no binding, a parameter like string $dsn with no default, a binding that returns the wrong type, or two classes that need each other (a circular dependency) all throw a ContainerException with the reason.

    src/Container/Container.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Container;

use Closure;
use ReflectionClass;
use ReflectionNamedType;

/**
 * A small dependency injection container.
 *
 * - bind():      "to build X, run this function" (a new object every time)
 * - singleton(): the same, but build it once and share it for the life of the app
 * - make():      build X; classes with no binding are built automatically by reading
 *                their constructor and building each typed parameter the same way
 */
final class Container
{
    /** @var array<string, Closure(self): object> */
    private array $factories = [];

    /** @var array<string, true> ids registered with singleton() */
    private array $shared = [];

    /** @var array<string, object> singletons already built */
    private array $instances = [];

    /** @var array<string, true> what is being built right now, to catch circular dependencies */
    private array $building = [];

    /** @param Closure(self): object $factory */
    public function bind(string $id, Closure $factory): void
    {
        $this->factories[$id] = $factory;
        unset($this->shared[$id], $this->instances[$id]);
    }

    /** @param Closure(self): object $factory */
    public function singleton(string $id, Closure $factory): void
    {
        $this->bind($id, $factory);
        $this->shared[$id] = true;
    }

    /**
     * @template T of object
     * @param class-string<T> $id
     * @return T
     */
    public function make(string $id): object
    {
        if (isset($this->instances[$id])) {
            /** @var T */
            return $this->instances[$id];
        }

        if (isset($this->building[$id])) {
            $chain = implode(' → ', [...array_keys($this->building), $id]);
            throw new ContainerException("Circular dependency: {$chain}.");
        }

        $this->building[$id] = true;
        try {
            $object = isset($this->factories[$id]) ? ($this->factories[$id])($this) : $this->autowire($id);
        } finally {
            unset($this->building[$id]);
        }

        if (!$object instanceof $id) {
            throw new ContainerException("The binding for {$id} returned " . $object::class . ', which is not a ' . $id . '.');
        }

        if (isset($this->shared[$id])) {
            $this->instances[$id] = $object;
        }

        return $object;
    }

    /**
     * @template T of object
     * @param class-string<T> $class
     * @return T
     */
    private function autowire(string $class): object
    {
        if (!class_exists($class) && !interface_exists($class)) {
            throw new ContainerException("Can't build [{$class}]: no binding, and no class with that name.");
        }

        $reflection = new ReflectionClass($class);
        if (!$reflection->isInstantiable()) {
            throw new ContainerException("Can't build [{$class}]: it is an interface or abstract class. Bind it to a class first.");
        }

        $constructor = $reflection->getConstructor();
        if ($constructor === null) {
            return $reflection->newInstance();
        }

        $arguments = [];
        foreach ($constructor->getParameters() as $parameter) {
            $type = $parameter->getType();

            if ($type instanceof ReflectionNamedType && !$type->isBuiltin()) {
                /** @var class-string $dependency */
                $dependency = $type->getName();
                $arguments[] = $this->make($dependency);
            } elseif ($parameter->isDefaultValueAvailable()) {
                $arguments[] = $parameter->getDefaultValue();
            } else {
                throw new ContainerException(
                    "Can't build [{$class}]: parameter \${$parameter->getName()} has no class type and no default. Bind {$class} with a factory."
                );
            }
        }

        return $reflection->newInstanceArgs($arguments);
    }
}

  4. 4The one place that wires the app

    The database connection is a singleton: built the first time something needs it, then shared. Its DSN comes from the EVALU8_DSN environment variable, so a nightly export can point at a replica without changing any class.

    Then four lines map interfaces to implementations. That is all the configuration this app needs; everything else is autowired.

    bootstrap/app.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * The ONE place that decides how the app's objects are built and connected.
 * Every entry script (bin/*.php) starts with: $app = require __DIR__ . '/../bootstrap/app.php';
 */

use Evalu8\Analysis\CommentAnalyzer;
use Evalu8\Analysis\KeywordCommentAnalyzer;
use Evalu8\Container\Container;
use Evalu8\Demo\SampleData;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Domain\SchoolRepository;
use Evalu8\Domain\TeacherRepository;
use Evalu8\Infrastructure\Sqlite\Schema;
use Evalu8\Infrastructure\Sqlite\SqliteResponseRepository;
use Evalu8\Infrastructure\Sqlite\SqliteSchoolRepository;
use Evalu8\Infrastructure\Sqlite\SqliteTeacherRepository;

require __DIR__ . '/../vendor/autoload.php';

$app = new Container();

// One database connection for the whole run, built the first time something needs it.
$app->singleton(PDO::class, function (): PDO {
    $db = new PDO(getenv('EVALU8_DSN') ?: 'sqlite::memory:');
    $db->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
    Schema::create($db);
    SampleData::load($db);

    return $db;
});

// Interfaces → the classes that implement them. Everything else is built automatically.
$app->singleton(TeacherRepository::class, fn (Container $c) => $c->make(SqliteTeacherRepository::class));
$app->singleton(ResponseRepository::class, fn (Container $c) => $c->make(SqliteResponseRepository::class));
$app->singleton(SchoolRepository::class, fn (Container $c) => $c->make(SqliteSchoolRepository::class));
$app->singleton(CommentAnalyzer::class, fn (Container $c) => $c->make(KeywordCommentAnalyzer::class));

return $app;

How Laravel does it

This is Laravel’s service container in miniature. $this->app->singleton() and bind() work like ours, and make() autowires with Reflection the same way. That is why you can type-hint a class in a controller’s constructor and it just arrives.

Laravel apps rarely need hand-written Singletons: singleton() in a service provider gives one shared instance without a global.

Laravel
// app/Providers/AppServiceProvider.php
public function register(): void
{
    $this->app->singleton(TeacherRepository::class, SqliteTeacherRepository::class);
    $this->app->singleton(ResponseRepository::class, SqliteResponseRepository::class);
    $this->app->bind(CommentAnalyzer::class, KeywordCommentAnalyzer::class);
}

// Any controller, job or command:
public function __construct(private TermReport $report) {}   // built by the container

Check yourself

Answer in your head, then open the answer.

What does the Singleton pattern hide that dependency injection shows?

What a class depends on. With injection, the constructor lists every dependency; with Database::connection() it is buried inside the methods.

How does the container know how to build TermReport?

It reads the constructor with Reflection and builds each typed parameter with make(), using a binding when there is one (for interfaces) and autowiring otherwise.

The nightly export must use a read replica. What changes?

Nothing in the classes. The export script sets EVALU8_DSN (or binds a different PDO), and every repository receives that connection.
