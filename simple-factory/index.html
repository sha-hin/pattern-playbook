Simple Factory

CreationNot in the book

A vending machine: press B4 and it hands you the right snack.

The rule to rememberTurning raw input (a string, a payload) into the right object is copied around → put that decision and the building in ONE place.

Without it: the pain

The if/else that turns a webhook "type" into an event object is copied in the controller and a replay command. The copy forgot refunds, so they were silently skipped.

With it: the fix

WebhookEventFactory::fromPayload() is the only place that reads the type and builds the event. An unknown type throws instead of being ignored.

Reach for it when you see

  • A switch where each branch only says new X(), and it is copied in 2+ places
  • Objects built from raw arrays, with the field names repeated everywhere
  • A default branch that silently ignores or guesses

Real job where it fits

A payment provider sends webhooks: payment succeeded, payment failed, refund created. A controller, a replay command and the tests all turn them into event objects.

Before: the code that hurts

// WebhookController:
if ($payload['type'] === 'payment.succeeded') {
    $event = new PaymentSucceeded($payload['data']['id'], $payload['data']['amount']);
} elseif ($payload['type'] === 'payment.failed') {
    $event = new PaymentFailed($payload['data']['id'], $payload['data']['failure_message']);
}
// ReplayWebhooksCommand: the same if/else, copied... and it forgot 'refund.created',
// so replayed refunds were silently skipped.

Build it yourself: the full Simple Factory pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

FactoryWebhookEventFactory the ONE place that decides which class to build, and builds it
ProductWebhookEvent what every built object has in common
Concrete productsPaymentSucceeded, PaymentFailed different data, not interchangeable
Clientsthe webhook endpoint and the replay script, which only call the factory
<?php

declare(strict_types=1);

// ── Step 1: the Product. What every object the factory builds has in common. ──
interface WebhookEvent  // Product
{
    public function summary(): string;
}

// ── Step 2: concrete products. Different classes with different data. ──
class PaymentSucceeded implements WebhookEvent
{
    public function __construct(public string $paymentId, public int $amountInPiastres)
    {
    }

    public function summary(): string
    {
        return "Payment {$this->paymentId} succeeded: " . ($this->amountInPiastres / 100) . ' EGP';
    }
}

class PaymentFailed implements WebhookEvent
{
    public function __construct(public string $paymentId, public string $reason)
    {
    }

    public function summary(): string
    {
        return "Payment {$this->paymentId} failed: {$this->reason}";
    }
}

// ── Step 3: the Factory. The ONE place that reads the input and builds the right object. ──
class WebhookEventFactory  // Factory
{
    public static function fromPayload(array $payload): WebhookEvent
    {
        $type = $payload['type'] ?? 'missing';
        $data = $payload['data'] ?? [];

        if ($type === 'payment.succeeded') {  // decide which class...
            return new PaymentSucceeded($data['id'], (int) $data['amount']);  // ...and build it
        }

        if ($type === 'payment.failed') {
            return new PaymentFailed($data['id'], $data['failure_message'] ?? 'unknown');
        }

        throw new InvalidArgumentException("Unknown webhook type [{$type}].");  // never silently ignored
    }
}

// ── Using it: the webhook endpoint, the replay script and the tests all use the same line ──
$incoming = [
    ['type' => 'payment.succeeded', 'data' => ['id' => 'pay_1', 'amount' => 15750]],
    ['type' => 'payment.failed', 'data' => ['id' => 'pay_2', 'failure_message' => 'card declined']],
    ['type' => 'payment.teleported', 'data' => ['id' => 'pay_3']],
];

foreach ($incoming as $payload) {
    try {
        $event = WebhookEventFactory::fromPayload($payload);
        echo $event->summary() . "\n";
    } catch (InvalidArgumentException $e) {
        echo 'Rejected: ' . $e->getMessage() . "\n";       // a real app logs it and answers 422
    }
}

Highlighted lines are the ones that make it this pattern. Run it: php examples/simple-factory.php · Open the file on GitHub

Payment pay_2 failed: card declined

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

class WebhookEventFactory
{
    public static function fromPayload(array $payload): WebhookEvent
    {
        if (!isset($payload['data'])) {
            throw new InvalidWebhook('Payload has no data.');
        }
        $data = $payload['data'];

        return match ($payload['type'] ?? null) {  // the ONE place that decides
            'payment.succeeded' => new PaymentSucceeded(  // and knows how to build each one
                paymentId: $data['id'],
                amount: new Money((int) $data['amount'], strtoupper($data['currency'])),
            ),
            'payment.failed' => new PaymentFailed(
                paymentId: $data['id'],
                reason: $data['failure_message'] ?? 'unknown',
            ),
            'refund.created' => new RefundCreated(
                refundId: $data['id'],
                paymentId: $data['payment_id'],
            ),
            default => throw new UnknownWebhookType(  // never silently ignored
                'Unknown webhook type [' . ($payload['type'] ?? 'missing') . '].'
            ),
        };
    }
}

// WebhookController, ReplayWebhooksCommand and the tests: the same line
$event = WebhookEventFactory::fromPayload($request->json()->all());
event($event);

// Note: PaymentSucceeded and RefundCreated are NOT interchangeable strategies.
// They hold different data. The pattern here is only about building the right one.

How Laravel builds it inside: The database layer picks its connector with a Simple Factory: a match on the configured driver ('mysql', 'pgsql', 'sqlite'...) builds the right connector class, and an unknown driver throws "Unsupported driver".
