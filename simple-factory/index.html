Simple Factory

CreationNot in the book

A vending machine: press B4 and it hands you the right snack.

The rule to rememberThe decision "which class do I create for this value?" is copied around → put it in ONE class with ONE match.

Without it: the pain

The same match on $format is copied in the controller, the API and the scheduled job. One copy silently falls back to CSV.

With it: the fix

ExporterFactory::for($format) is the only place that decides. An unknown value throws instead of guessing.

Reach for it when you see

  • The same switch / match that creates objects appears in 2+ places
  • Adding a type means hunting for every copy
  • A "default" branch that silently picks something

Real job where it fits

The export format comes from the web form, the API, and a scheduled email. All three must create the same exporter.

Before: the code that hurts

// in ReportController, Api\ReportController and SendWeeklyReport job:
$exporter = match ($format) {
    'csv' => new CsvExporter(),
    'pdf' => new PdfExporter(),
    default => new CsvExporter(),   // ← silent guess: a typo gives the wrong file
};

After: how you implement the Simple Factory pattern in PHP

final class ExporterFactory
{
    public static function for(string $format): Exporter
    {
        return match (strtolower(trim($format))) {  // the ONLY place that decides
            'csv'  => new CsvExporter(),
            'xlsx' => new ExcelExporter(),
            'pdf'  => new PdfExporter(),
            default => throw new UnsupportedFormat(  // never a silent fallback
                "No exporter for [{$format}]. Use csv, xlsx or pdf."
            ),
        };
    }
}

// ReportController, Api\ReportController, SendWeeklyReport job — the same line:
$path = ExporterFactory::for($format)->export($rows);

// Adding JSON = one new line in the match + one JsonExporter class.

Highlighted lines are the ones that make it this pattern.
