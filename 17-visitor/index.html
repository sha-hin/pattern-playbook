Count, check and print our surveys

From Mona Saleh, Head of Quality

We need three things before term starts: how many questions each survey has, a check that catches design mistakes (two questions with the same code, empty sections), and a printable handout for schools without tablets. Next term we will probably ask for a PDF and an accessibility check too.

Why the quick fix is a trap

The obvious way adds a method per request to both node classes:

the quick fix (we won’t do this)
interface SurveyNode
{
    public function score(AnswerSheet $answers): ?float;
    public function countQuestions(): int;
    public function validate(array &$errors, array &$codesSeen): void;
    public function toMarkdown(int $depth): string;
    // next term: toPdf(), accessibilityIssues(), ...
}

Question and Section were small and stable. Now they grow with every report request, they mix scoring with printing and checking, and all the code for "printing a survey" is split across two classes.

The tree’s structure rarely changes (there are only questions and sections). The operations on it keep growing. We want to add operations without editing the node classes.

The pattern: Visitor

Remember itA stable set of node types needs a growing list of operations → put each operation in its own visitor class with one method per node type; the nodes only accept visitors.

Each node gets one method, accept(SurveyVisitor $visitor), and calls back the visitor method for its own type: a question calls visitQuestion($this), a section calls visitSection($this). This is double dispatch: the right method is chosen by both the visitor and the node, without any instanceof.

Each operation is now one class: QuestionCounter, SurveyValidator, MarkdownExporter. Everything about printing is in one file, and a new operation never touches Question or Section.

The trade-off: adding a new node type (say, a free-text question) means adding a method to every visitor. Use Visitor when the types are stable and the operations change, not the other way round.

  5. 5Visitor 1: count

    src/Survey/Visitor/QuestionCounter.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey\Visitor;

use Evalu8\Survey\Question;
use Evalu8\Survey\Section;
use Evalu8\Survey\SurveyVisitor;

/**
 * Counts questions and sections, at any depth.
 */
final class QuestionCounter implements SurveyVisitor
{
    public int $questions = 0;
    public int $sections = 0;

    public function visitQuestion(Question $question): void
    {
        $this->questions++;
    }

    public function visitSection(Section $section): void
    {
        $this->sections++;
        foreach ($section->children() as $child) {
            $child->accept($this);
        }
    }
}

  6. 6Visitor 2: check for mistakes

    It remembers the codes it has seen while walking the tree, so it can spot a duplicate anywhere, at any depth.

    src/Survey/Visitor/SurveyValidator.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey\Visitor;

use Evalu8\Survey\Question;
use Evalu8\Survey\Section;
use Evalu8\Survey\SurveyVisitor;

/**
 * Finds mistakes a survey designer can make: duplicate question codes, empty sections,
 * and question texts that are too long for the phone layout.
 */
final class SurveyValidator implements SurveyVisitor
{
    private const MAX_QUESTION_LENGTH = 80;

    /** @var list<string> */
    public array $errors = [];

    /** @var array<string, true> */
    private array $codesSeen = [];

    public function visitQuestion(Question $question): void
    {
        if (isset($this->codesSeen[$question->code])) {
            $this->errors[] = "Question code \"{$question->code}\" is used twice; answers would be mixed up.";
        }
        $this->codesSeen[$question->code] = true;

        if (mb_strlen($question->text) > self::MAX_QUESTION_LENGTH) {
            $this->errors[] = "Question {$question->code} is longer than " . self::MAX_QUESTION_LENGTH . ' characters.';
        }
    }

    public function visitSection(Section $section): void
    {
        if (count($section->children()) === 0) {
            $this->errors[] = "Section \"{$section->title()}\" is empty.";
        }

        foreach ($section->children() as $child) {
            $child->accept($this);
        }
    }

    public function isValid(): bool
    {
        return count($this->errors) === 0;
    }
}

  7. 7Visitor 3: the printable handout

    Sections become headings and questions become lines with five boxes. When a sub-section ends and more questions follow, the parent’s heading is repeated with "(continued)", because Markdown can’t close a heading.

    src/Survey/Visitor/MarkdownExporter.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey\Visitor;

use Evalu8\Survey\Question;
use Evalu8\Survey\Section;
use Evalu8\Survey\SurveyVisitor;

/**
 * Writes the survey as Markdown, for the printed handout: sections become headings,
 * questions become lines with five boxes.
 */
final class MarkdownExporter implements SurveyVisitor
{
    private string $markdown = '';

    /** @var list<string> titles of the sections we are inside, outermost first */
    private array $open = [];

    /** true after a sub-section ends: the next question needs its section's heading again */
    private bool $resumeHeading = false;

    public function visitQuestion(Question $question): void
    {
        if ($this->resumeHeading) {
            $this->heading(end($this->open) . ' (continued)');
            $this->resumeHeading = false;
        }

        $this->markdown .= "- **{$question->code}.** {$question->text} ☐1 ☐2 ☐3 ☐4 ☐5\n";
    }

    public function visitSection(Section $section): void
    {
        $this->open[] = $section->title();
        $this->heading($section->title());
        $this->resumeHeading = false;

        foreach ($section->children() as $child) {
            $child->accept($this);
        }

        array_pop($this->open);
        $this->resumeHeading = true;
    }

    public function markdown(): string
    {
        return $this->markdown;
    }

    private function heading(string $title): void
    {
        $level = str_repeat('#', min(count($this->open), 6));
        $separator = $this->markdown === '' || str_ends_with($this->markdown, "\n\n") ? '' : "\n";
        $this->markdown .= "{$separator}{$level} {$title}\n\n";
    }
}

How Laravel does it

PHP-Parser (used by PHPStan, Rector and Laravel Pint’s tooling) is the best-known PHP visitor: a NodeVisitor walks a syntax tree that has many node types and few new ones. Laravel’s query grammars apply the same idea to queries: one grammar class per database "visits" each part of a query and turns it into SQL.

// With nikic/php-parser: one class per operation over PHP code
final class FindDdCalls extends NodeVisitorAbstract
{
    /** @var list<int> */
    public array $lines = [];

    public function enterNode(Node $node): null
    {
        if ($node instanceof Node\Expr\FuncCall && $node->name instanceof Node\Name && $node->name->toString() === 'dd') {
            $this->lines[] = $node->getStartLine();
        }

        return null;
    }
}

Check yourself

Answer in your head, then open the answer.

Next term needs a PDF export. Which classes change?

None. You add one class, PdfExporter implements SurveyVisitor.

A new node type, TextQuestion, is added. What changes?

The visitor interface gains visitTextQuestion(), and every existing visitor must implement it. That is Visitor’s cost.

What is double dispatch here?

The method that runs depends on two things: the visitor (which operation) and the node (which visit... method it calls back).

The quality team wants follow-up questions that appear only for some respondents, and they want to write those rules themselves, without waiting for a developer.
