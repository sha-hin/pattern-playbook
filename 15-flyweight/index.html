100,000 response objects repeat the same question data

Flyweight

New ticket

The statistics screen uses 27 MB per term

From Omar Hassan, DevOps

The distribution charts load a whole term into memory. When four schools open the screen at the same time, the PHP workers hit their memory limit. Most of the memory looks like the same few small objects repeated.

Why the quick fix is a trap

Look at what the repository creates for each row:

the quick fix (we won’t do this)
return new Response(
    (int) $row['teacher_id'],
    (string) $row['term'],                // a new copy of "2026-T1", 100,000 times
    RespondentRole::from($row['role']),
    new Score((int) $row['score']),       // a new Score object, 100,000 times
    (string) $row['comment'],
);

There are only five possible scores, yet the term holds 100,000 Score objects: 20,000 identical copies of Score(4). The same goes for the term name, copied into every row.

Streaming (chapter 14) doesn’t help here: this screen genuinely needs every answer at once. What we can change is how many objects those answers point to.

The pattern: Flyweight

Remember itHuge numbers of objects repeat the same small values → share one immutable object per value, handed out by a factory, instead of creating a copy each time.

A flyweight is a shared object. Score::of(4) always returns the same Score object for 4, created on first use. 100,000 answers now point to five Score objects.

The book splits state in two: intrinsic state lives inside the shared object (the number 4), and extrinsic state stays with whoever uses it (which teacher, which term, which comment live in Response).

Sharing is only safe because Score is immutable: its value is readonly. If any code could change a shared Score, it would change 20,000 answers at once. Never share mutable objects.

You already used a flyweight: each PHP enum case (RespondentRole::Student) is a single shared object.

    It loads the term twice: once rebuilding every answer the old way (a new Score and a new term string each), once as the repository now returns it, and measures both. Then it counts the distinct Score objects.

declare(strict_types=1);

/*
 * Evalu8, chapter 15: a whole term in memory, with shared Score objects.
 *
 *     composer dump-autoload
 *     php bin/statistics.php
 */

use Evalu8\Container\Container;
use Evalu8\Demo\SampleData;
use Evalu8\Domain\Response;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Domain\Score;

const BIG_TERM = '2026-T1';
const ANSWERS = 100_000;

/** @var Container $app */
$app = require __DIR__ . '/../bootstrap/app.php';
SampleData::loadManyAnswers($app->make(PDO::class), BIG_TERM, ANSWERS);
$responses = $app->make(ResponseRepository::class);

/**
 * Loads the whole term and returns [the answers, MB of memory they occupy].
 *
 * @param callable(Response): Response $copy
 * @return array{0: list<Response>, 1: float}
 */
function loadTerm(ResponseRepository $responses, callable $copy): array
{
    gc_collect_cycles();
    $before = memory_get_usage();

    $all = [];
    foreach ($responses->inTerm(BIG_TERM) as $response) {
        $all[] = $copy($response);
    }

    return [$all, round((memory_get_usage() - $before) / 1_048_576, 1)];
}

// What the mapper produced before this chapter: a new Score and a new term string for every row.
[$unshared, $unsharedMb] = loadTerm($responses, fn (Response $r): Response => new Response(
    $r->teacherId,
    str_repeat($r->term, 1),                                // a fresh copy, as PDO returns it
    $r->role,
    new Score($r->score->value),                            // a fresh object per answer
    $r->comment,
));
unset($unshared);

// What it produces now: shared Score objects and one shared term string.
[$all, $sharedMb] = loadTerm($responses, fn (Response $r): Response => $r);

echo 'Holding ' . number_format(count($all)) . " answers in memory
";
echo "  one Score object per answer: {$unsharedMb} MB
";
echo "  shared Score objects (now):  {$sharedMb} MB\n\n";

// How many different Score objects are there behind 100,000 answers?
$scoreObjects = [];
$distribution = [];
foreach ($all as $response) {
    $scoreObjects[spl_object_id($response->score)] = true;
    $distribution[$response->score->value] = ($distribution[$response->score->value] ?? 0) + 1;
}
ksort($distribution);

echo 'Distinct Score objects: ' . count($scoreObjects) . "\n";
echo 'Score::of(4) === Score::of(4): ' . (Score::of(4) === Score::of(4) ? 'yes, the same object' : 'no') . "\n\n";

echo "DISTRIBUTION\n";
foreach ($distribution as $score => $count) {
    echo "  {$score}: " . str_repeat('#', intdiv($count, 1000)) . " {$count}\n";
}

How Laravel does it

Laravel doesn’t ship a flyweight API, but PHP gives you two for free: enum cases are single shared instances, and identical string literals are interned. When Eloquent hydrates many models with a repeated small value object, a cast that returns a shared instance has the same effect:

Laravel
final class ScoreCast implements CastsAttributes
{
    public function get(Model $model, string $key, mixed $value, array $attributes): Score
    {
        return Score::of((int) $value);      // shared instance, not new Score()
    }

    public function set(Model $model, string $key, mixed $value, array $attributes): int
    {
        return $value->value;
    }
}

Check yourself

Answer in your head, then open the answer.

What is the intrinsic state of a Score, and what is extrinsic?

Intrinsic: the number (1 to 5), stored inside the shared object. Extrinsic: the teacher, term and comment, stored in each Response.

Why must a flyweight be immutable?

It is shared. Changing it would change every answer that points to it.

Should you use Flyweight for teachers?

No. Each teacher is a different object with its own data; there is nothing repeated to share. Flyweight pays off only for many copies of few values.
