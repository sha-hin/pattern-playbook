Pattern Playbook: design patterns for PHP & Laravel developers

25 patterns: 15 from the Gang of Four book and 10 modern ones every PHP framework relies on. Each one has a memory hook, a drawing of the pain and the fix, and real before/after code, so you know when to use it, not just what it is.

Use these every week

1StrategyBehaviourGoogle Maps: same trip, you pick Car, Walk or Bike.Same job, several ways to do it → one class per way, all behind one interface.2Simple FactoryCreationNot in the bookA vending machine: press B4 and it hands you the right snack.The decision "which class do I create for this value?" is copied around → put it in ONE class with ONE match.3Null ObjectBehaviourNot in the bookA muted microphone: the meeting runs normally, your mic just sends nothing."Nothing" is a NORMAL case (no coupon, no logger) → pass an object that safely does nothing, instead of null.4AdapterStructureA travel plug: your charger, their wall socket.A third-party class has the wrong shape and you can't edit it → wrap it in a class that speaks YOUR interface.5DecoratorStructureA phone case: it's still a phone, now it's also shockproof.Add behaviour (cache, log, retry) around a class without editing it → wrap it in a class with the SAME interface.6ObserverBehaviourYouTube subscribe: the channel uploads once, every subscriber gets notified.When one thing happens and many things must react → fire an event; each reaction is its own listener.7Event DispatcherBehaviourNot in the bookA post office: senders drop letters at one counter, and never meet the people who receive them.Many parts of the app send events and many listen → one shared middleman; events are small data classes.8FacadeStructureHotel reception: you talk to one desk, they call housekeeping, the kitchen and the taxi.A multi-step job that touches many services, needed from many places → one class with one method that runs it all.9Laravel Facade (static proxy)StructureNot in the bookA speed-dial button: one press, and it calls the real number for you.Cache::get() is a static shortcut that FORWARDS to one object in the container. It is a Proxy, not the GoF Facade.

Common in real projects

10Template MethodBehaviourA recipe card with blanks: the steps are printed, you fill in "filling".Several classes run the same steps in the same order, only some steps differ → parent locks the order, children fill the gaps.11BuilderCreationOrdering at Subway: bread, then fillings, then sauce; the cashier checks it at the end.An object with many optional parts and rules that involve several parts → set parts step by step, check everything once in build().12Value ObjectCreationNot in the bookA banknote: any 100-pound note equals any other, and nobody can edit what’s printed on it.A value with rules (money, email, date range) → a small immutable class that checks itself and is compared by value.13StateBehaviourA traffic light: what you may do depends on the colour, and the light changes itself.What an object is allowed to do depends on its status → one class per status; each knows its allowed moves.14CommandBehaviourA restaurant ticket: the order is written down, so it can wait in line, be retried, or be torn up.An action you want to run later, queue, retry, log or undo → turn the action into an object.15Command BusBehaviourNot in the bookA dispatch desk: you hand in a form, and the desk knows which department handles it.Split "what to do" (a data object) from "how" (a handler) → the same action runs from web, CLI or queue, with shared rules around it.16Transactional OutboxBehaviourNot in the bookA sealed envelope in the outgoing tray: it leaves only if the paperwork is filed, and the courier keeps trying until it’s delivered.Saving data AND calling an outside system must never get out of sync → write the message in the same DB transaction; a worker sends it and retries.17IteratorBehaviourA playlist's Next button: you don't care if songs are on disk, in the cloud or on a CD.Callers need to loop over data, but how it’s stored or fetched may change → give them items one at a time, hide the rest.18GeneratorsBehaviourNot in the bookA water tap: you get water as you need it, not a 10,000-litre tank delivered at once.Big data you loop over once → yield one item at a time; memory stays flat no matter the size.

Specialised: learn them last

19CompositeStructureFolders and files: a folder's size is the sum of what's inside, and folders can hold folders.Your data is a tree (parts inside wholes, any depth) → items and groups share one interface; a group asks its children.20DI ContainerCreationNot in the bookA wall socket: your laptop doesn't build a power plant, it just plugs in.A class needs services → ask for them in the constructor; one place (the container) decides what you get.21Factory MethodCreationA franchise: HQ owns the process, each branch decides its local product.A parent class runs a process that needs an object, but each child needs a different one → leave a create…() method for the child.22Manager / DriverCreationNot in the bookPhone settings: pick Wi-Fi calling once, and every call uses it.One service with interchangeable backends chosen by config → a manager builds the configured driver once and reuses it.23PrototypeCreation"Make a copy" of a Google Doc: start from a full copy, then change the title.You need "the same as this one, with small changes" → copy an existing object, deep-copy what it owns, share what it only points to.24BridgeStructureTV remotes and TVs: any remote works with any TV because they’re designed separately.A class varies in two independent ways (what × how) → two hierarchies, one holds the other. A + B classes, not A × B.25Abstract FactoryCreationAn IKEA collection: pick one style, and the table, chair and lamp all match.Several objects must come from the same family → one factory creates the whole family, so they can never be mixed.
