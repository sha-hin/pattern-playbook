Proxy

New ticket

Teachers can read each other’s comments, and the dashboard is slow

From Mona Saleh, Head of Quality, and the support desk

Hany changed the teacher id in the URL and read Nadia’s comments, including which ones came from the principal. Teachers may read their own comments, without knowing who wrote them; principals and the quality team may read everything. Separately: every dashboard page opens a connection to the comments archive, even when the comments panel is never opened.

Why the quick fix is a trap

The quick fix adds both checks to the reader itself:

the quick fix (we won’t do this)
final class SqliteCommentReader implements CommentReader
{
    public function __construct(private Viewer $viewer)
    {
        $this->archive = new PDO(ARCHIVE_DSN);      // still opened on every page
    }

    public function forTeacher(int $teacherId, string $term): array
    {
        if ($this->viewer->role === ViewerRole::Teacher && $this->viewer->teacherId !== $teacherId) {
            throw new AccessDenied('...');
        }
        // ...the query, plus hiding roles for teachers...
    }
}

The reader now mixes three concerns: reading the archive, permissions and when to connect. The nightly report (which runs as the system, with no viewer) can no longer use it, and the connection is still opened eagerly.

Both problems are about controlling access to the real reader: *who* may reach it, and *when* it is created.

The pattern: Proxy

Remember itYou need to control access to an object (who may use it, or when it is created) → put a stand-in with the same interface in front of it.

A proxy implements the same interface as the real object and holds (or will create) the real one. The caller can’t tell the difference.

A protection proxy (AccessControlledCommentReader) checks the viewer before passing the call on, and hides the respondent’s role from teachers. A virtual proxy (LazyCommentReader) delays creating the expensive real object until the first call.

The real SqliteCommentReader goes back to doing one thing: reading the archive. The nightly report can still use it directly.

Proxy vs Decorator

They are built the same way (same interface, holds another object), so the difference is the intent.

Proxy (this chapter)Decorator (chapter 9)
IntentControl access to the real objectAdd behaviour to the object
May skip the real object?Yes: it may refuse, or not create it yetRarely (a cache hit is the exception)
Who creates the real objectOften the proxy itself (virtual proxy)Always given from outside

  6. 6The real subject

    Only reads. No permissions, no laziness.

    src/Comments/SqliteCommentReader.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Comments;

use Evalu8\Domain\RespondentRole;
use PDO;

/**
 * The real subject: reads comments from the comments archive database.
 * Creating it means opening a connection to that archive, which is slow.
 */
final readonly class SqliteCommentReader implements CommentReader
{
    public function __construct(private PDO $archive)
    {
    }

    public function forTeacher(int $teacherId, string $term): array
    {
        $select = $this->archive->prepare(
            "SELECT role, comment FROM responses WHERE teacher_id = ? AND term = ? AND comment <> '' ORDER BY id"
        );
        $select->execute([$teacherId, $term]);

        $comments = [];
        foreach ($select->fetchAll(PDO::FETCH_ASSOC) as $row) {
            $comments[] = new Comment(RespondentRole::from((string) $row['role']), (string) $row['comment']);
        }

        return $comments;
    }
}

  7. 7The virtual proxy

    It holds a function that creates the real reader, and calls it on the first forTeacher(). After that it reuses the same reader.

    src/Comments/LazyCommentReader.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Comments;

use Closure;

/**
 * Virtual proxy: stands in for the real reader and only creates it (and opens the
 * archive connection) the first time comments are actually read.
 */
final class LazyCommentReader implements CommentReader
{
    private ?CommentReader $real = null;

    /** @param Closure(): CommentReader $createReal */
    public function __construct(private readonly Closure $createReal)
    {
    }

    public function forTeacher(int $teacherId, string $term): array
    {
        $this->real ??= ($this->createReal)();              // created on first use, then reused

        return $this->real->forTeacher($teacherId, $term);
    }
}

  8. 8The protection proxy

    It decides before the real reader is touched. A teacher asking about another teacher never reaches the archive at all.

    src/Comments/AccessControlledCommentReader.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Comments;

use Evalu8\Auth\AccessDenied;
use Evalu8\Auth\Viewer;
use Evalu8\Auth\ViewerRole;

/**
 * Protection proxy: decides whether the viewer may reach the real reader at all.
 *
 * - principals and the quality team read every comment, with the respondent's role
 * - a teacher reads only their own comments, with the role hidden (answers stay anonymous)
 * - anything else is refused before the real reader is touched
 */
final readonly class AccessControlledCommentReader implements CommentReader
{
    public function __construct(
        private CommentReader $inner,
        private Viewer $viewer,
    ) {
    }

    public function forTeacher(int $teacherId, string $term): array
    {
        if ($this->viewer->role === ViewerRole::Principal || $this->viewer->role === ViewerRole::Quality) {
            return $this->inner->forTeacher($teacherId, $term);
        }

        if ($this->viewer->role === ViewerRole::Teacher && $this->viewer->teacherId === $teacherId) {
            $comments = [];
            foreach ($this->inner->forTeacher($teacherId, $term) as $comment) {
                $comments[] = $comment->withoutRole();
            }

            return $comments;
        }

        throw new AccessDenied("{$this->viewer->name} may not read the comments about teacher #{$teacherId}.");
    }
}

  10. 10The dashboard

    Each viewer gets the protection proxy in front of the same lazy proxy. Building the pages doesn’t connect to the archive; the first read does.

    bin/dashboard.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * Evalu8, chapter 10: the teacher dashboard reads comments through two proxies.
 *
 *     composer dump-autoload
 *     php bin/dashboard.php
 */

use Evalu8\Auth\AccessDenied;
use Evalu8\Auth\Viewer;
use Evalu8\Auth\ViewerRole;
use Evalu8\Comments\AccessControlledCommentReader;
use Evalu8\Comments\Comment;
use Evalu8\Comments\CommentReader;
use Evalu8\Comments\LazyCommentReader;
use Evalu8\Comments\SqliteCommentReader;
use Evalu8\Container\Container;
use Evalu8\Demo\SampleData;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Logging\Logger;

const CURRENT_TERM = '2026-T1';

/** @var Container $app */
$app = require __DIR__ . '/../bootstrap/app.php';

SampleData::loadAnswers($app->make(ResponseRepository::class), CURRENT_TERM);
$logger = $app->make(Logger::class);

// The real reader would open a second connection, to the comments archive. That is the slow part.
// (In the demo the archive is the same in-memory database.)
$lazy = new LazyCommentReader(function () use ($app, $logger): CommentReader {
    $logger->info('opening the comments archive connection');

    return new SqliteCommentReader($app->make(PDO::class));
});

/** @param list<Comment> $comments */
function show(array $comments): void
{
    foreach ($comments as $comment) {
        echo '  - ' . ($comment->role !== null ? "[{$comment->role->value}] " : '') . $comment->text . "\n";
    }
}

echo "DASHBOARD PAGES BUILT (comments panel collapsed)\n";
$asPrincipal = new AccessControlledCommentReader($lazy, new Viewer('Mona Saleh', ViewerRole::Principal));
$asHany = new AccessControlledCommentReader($lazy, new Viewer('Hany Mostafa', ViewerRole::Teacher, teacherId: 1));
echo "  no archive connection yet\n";

echo "\nPRINCIPAL opens Hany's comments\n";
show($asPrincipal->forTeacher(1, CURRENT_TERM));

echo "\nHANY opens his own comments (roles hidden, connection reused)\n";
show($asHany->forTeacher(1, CURRENT_TERM));

echo "\nHANY tries to open Nadia's comments\n";
try {
    $asHany->forTeacher(2, CURRENT_TERM);
} catch (AccessDenied $e) {
    echo "  AccessDenied: {$e->getMessage()}\n";
}

How Laravel does it

For permissions, Laravel’s usual tools are Policies and Gates ($this->authorize('view', $teacher)): the same protection-proxy idea, applied at the controller. A proxy class like ours is useful when the rule must hold wherever the object is used.

Virtual proxies are everywhere in Laravel: Eloquent relations load lazily on first access, LazyCollection loads rows only when iterated, and PHP 8.4 adds native lazy objects (ReflectionClass::newLazyProxy()).

Laravel’s "facades" (Cache::get()) are also a kind of proxy: a static stand-in that forwards each call to the real object in the container.

Laravel
// A policy: the protection rule, checked before the controller reads anything
final class TeacherCommentsPolicy
{
    public function view(User $user, Teacher $teacher): bool
    {
        return $user->isPrincipal() || $user->isQuality() || $user->teacher_id === $teacher->id;
    }
}

// In the controller:
$this->authorize('view', $teacher);

Check yourself

Answer in your head, then open the answer.

Why does Hany’s request for Nadia’s comments not open the archive connection?

The protection proxy refuses before calling the inner reader, so the lazy proxy never creates the real one for that request.

The nightly report runs with no viewer. Which reader does it use?

The real SqliteCommentReader directly (or the lazy proxy). The permission rule lives in a separate class, so it doesn’t get in the way.

What is the difference between a virtual proxy and a protection proxy?

A virtual proxy controls *when* the real object is created. A protection proxy controls *who* may use it.
