Closing a survey takes six steps, and callers forget some

Facade

New ticket

Hany’s result changed after the term was closed

From Mona Saleh, Head of Quality

Terms are closed from the admin panel, from a CLI command, and by the scheduler on the last day. Last week the scheduler forgot to save the results snapshot, a late answer arrived, and Hany’s score changed after he had been emailed. Also, the admin panel emails teachers before saving, so a failed save leaves emails with results that don’t exist.

Why the quick fix is a trap

Each caller runs its own version of the process:

the quick fix (we won’t do this)
// AdminController::closeTerm()
$results = $report->results($term);
foreach ($results as $r) { $mailer->send(/* ... */); }      // emails first...
$store->saveAndClose($term, $results);                     // ...save second
$export->write($results, $path);

// bin/close-term (CLI): the same steps in another order
// Scheduler: forgot saveAndClose() entirely

Five subsystems (report, results store, mailer, Ministry export, logger) and a correct order that only lives in people’s heads. Every caller must know all of it, and each one is a chance to get it wrong.

The callers don’t want five subsystems. They want one thing: close this term.

The pattern: Facade

Remember itA job needs several subsystems in the right order → give it one simple front door that runs the whole job. Callers use the door; the subsystems stay available.

TermClosing::close($term) runs the steps in the only safe order: refuse if already closed → calculate → save the snapshot and mark the term closed in one transaction → email teachers → write the Ministry file. It returns a ClosingSummary every caller can display.

The admin panel, the CLI and the scheduler become one line each. The subsystems are not hidden away: other code can still use TermReport or MinistryExport directly.

Laravel developers: this is the Gang of Four Facade, which is not what Laravel calls a "facade" (Cache::get() is a static proxy; see chapter 10).

  5. 5Save and close in one transaction

    The snapshot and the "closed" mark are saved together or not at all.

    src/Infrastructure/Sqlite/SqliteTermResultStore.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Infrastructure\Sqlite;

use Evalu8\Reporting\TermResultStore;
use PDO;
use Throwable;

final readonly class SqliteTermResultStore implements TermResultStore
{
    public function __construct(private PDO $db)
    {
    }

    public function isClosed(string $term): bool
    {
        $select = $this->db->prepare('SELECT 1 FROM closed_terms WHERE term = ?');
        $select->execute([$term]);

        return $select->fetchColumn() !== false;
    }

    public function saveAndClose(string $term, array $results): void
    {
        $this->db->beginTransaction();                      // the snapshot and the "closed" mark: both or neither

        try {
            $insert = $this->db->prepare(
                'INSERT INTO term_results (term, teacher_id, responses, method, score) VALUES (?, ?, ?, ?, ?)'
            );
            foreach ($results as $result) {
                $insert->execute([$term, $result->teacher->id, $result->responseCount, $result->method, $result->score]);
            }

            $close = $this->db->prepare("INSERT INTO closed_terms (term, closed_at) VALUES (?, datetime('now'))");
            $close->execute([$term]);

            $this->db->commit();
        } catch (Throwable $e) {
            $this->db->rollBack();
            throw $e;
        }
    }
}

  6. 6The Ministry file, written properly

    The CSV used to be built with string concatenation; fputcsv() quotes names correctly. The explicit escape: '' avoids a deprecation in PHP 8.4.

    src/Reporting/MinistryExport.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting;

use RuntimeException;

/**
 * Writes the Ministry's CSV file. fputcsv() quotes names that contain commas or quotes.
 */
final readonly class MinistryExport
{
    /**
     * @param list<TeacherResult> $results
     * @return int the number of teacher rows written
     */
    public function write(array $results, string $path): int
    {
        $file = fopen($path, 'w');
        if ($file === false) {
            throw new RuntimeException("Can't write the Ministry export to {$path}.");
        }

        try {
            fputcsv($file, ['teacher', 'school', 'responses', 'method', 'score'], escape: '');
            foreach ($results as $result) {
                fputcsv($file, [
                    $result->teacher->name,
                    $result->teacher->school,
                    $result->responseCount,
                    $result->method,
                    $result->score === null ? '' : round($result->score, 2),
                ], escape: '');
            }
        } finally {
            fclose($file);
        }

        return count($results);
    }
}

  9. 9The facade

    The five steps, in the only safe order, with a comment on each. Teachers are emailed only after the results are frozen. A teacher without an email is logged as a warning and listed in the summary.

    src/Closing/TermClosing.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Closing;

use Evalu8\Logging\Logger;
use Evalu8\Mail\Mailer;
use Evalu8\Reporting\MinistryExport;
use Evalu8\Reporting\TermReport;
use Evalu8\Reporting\TermResultStore;

/**
 * The Facade: one method that closes a term, running every step in the right order.
 * The admin panel, the CLI command and the scheduler all call close(); none of them
 * needs to know the five subsystems behind it.
 */
final readonly class TermClosing
{
    public function __construct(
        private TermReport $report,
        private TermResultStore $store,
        private Mailer $mailer,
        private MinistryExport $ministry,
        private Logger $logger,
        private string $exportDirectory,
    ) {
    }

    public function close(string $term): ClosingSummary
    {
        if ($this->store->isClosed($term)) {                // 1. never close twice
            throw new TermAlreadyClosed("Term {$term} is already closed; its results can't change.");
        }

        $results = $this->report->results($term);           // 2. calculate
        $this->store->saveAndClose($term, $results);        // 3. freeze the results (one transaction)

        $emailed = 0;                                       // 4. tell every teacher, only after the results are frozen
        $notEmailed = [];
        foreach ($results as $result) {
            if ($result->teacher->email === null) {
                $notEmailed[] = $result->teacher->name;
                $this->logger->warning('result not emailed: no address', ['teacher' => $result->teacher->name]);
                continue;
            }

            $this->mailer->send(
                $result->teacher->email,
                "Your {$term} evaluation result",
                "Your {$result->method} score is {$result->formattedScore()}. Comments: {$result->commentSummary}",
            );
            $emailed++;
        }

        $path = "{$this->exportDirectory}/ministry-{$term}.csv";  // 5. the Ministry's file
        $this->ministry->write($results, $path);

        return new ClosingSummary($term, count($results), $emailed, $notEmailed, $path);
    }
}

declare(strict_types=1);

/*
 * Evalu8, chapter 11: closing a term is one call, wherever it is started from.
 *
 *     composer dump-autoload
 *     php bin/close-term.php
 */

use Evalu8\Closing\TermAlreadyClosed;
use Evalu8\Closing\TermClosing;
use Evalu8\Container\Container;
use Evalu8\Demo\SampleData;
use Evalu8\Domain\ResponseRepository;

const CURRENT_TERM = '2026-T1';

/** @var Container $app */
$app = require __DIR__ . '/../bootstrap/app.php';
SampleData::loadAnswers($app->make(ResponseRepository::class), CURRENT_TERM);

$closing = $app->make(TermClosing::class);

echo "CLOSING " . CURRENT_TERM . "\n";
$summary = $closing->close(CURRENT_TERM);                   // the whole process, in the right order

echo "\nSUMMARY\n";
echo "  teachers:    {$summary->teachers}\n";
echo "  emailed:     {$summary->emailed}\n";
echo '  not emailed: ' . implode(', ', $summary->notEmailed) . "\n";
echo '  export:      ' . basename($summary->exportPath) . "\n";
echo "\n" . file_get_contents($summary->exportPath);

echo "\nTHE SCHEDULER TRIES TO CLOSE IT AGAIN\n";
try {
    $closing->close(CURRENT_TERM);
} catch (TermAlreadyClosed $e) {
    echo "  refused: {$e->getMessage()}\n";
}

How Laravel does it

Laravel’s HTTP kernel is a facade over the whole framework: handle($request) boots config and providers, runs middleware, routes and reports errors. In applications, classes like TermClosing are often called actions or services.

Laravel
// A console command and a controller, both one line:
final class CloseTermCommand extends Command
{
    protected $signature = 'terms:close {term}';

    public function handle(TermClosing $closing): int
    {
        $summary = $closing->close($this->argument('term'));
        $this->info("Closed {$summary->term}: {$summary->emailed} teachers emailed.");

        return self::SUCCESS;
    }
}

// routes/console.php: the scheduler uses the same command
Schedule::command('terms:close 2026-T1')->yearlyOn(1, 31, '23:00');

A fourth caller (an API endpoint) needs to close terms. What does it contain?

One call: $closing->close($term). The order of the steps is already inside the facade.

Can other code still use MinistryExport directly?

Yes. A facade simplifies a common job; it doesn’t lock the subsystems away.

Why are teachers emailed after saveAndClose()?

If saving fails, no teacher receives a result that was never stored.
