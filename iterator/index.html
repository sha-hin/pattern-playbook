Iterator

BehaviourGoF book

A playlist's Next button: you don't care if songs are on disk, in the cloud or on a CD.

The rule to rememberCallers need to loop over data, but how it’s stored or fetched may change → give them items one at a time, hide the rest.

Without it: the pain

Every caller of the CRM API writes its own page=1, page=2, has_more loop, and loads everything into memory.

With it: the fix

One iterable class hides the pagination and yields one customer at a time. Callers just foreach.

Reach for it when you see

  • The same pagination / chunking loop copied in many places
  • Loading 100K rows into an array before processing
  • Callers know the internal shape of your collection

Real job where it fits

A CRM API returns 100 customers per page. You sync 80,000 customers every night.

Before: the code that hurts

// copied in 3 jobs:
$page = 1; $all = [];
do {
    $response = Http::get($crm.'/customers', ['page' => $page++]);
    $all = array_merge($all, $response->json('data'));   // 80,000 rows in memory
} while ($response->json('meta.has_more'));

Build it yourself: the full Iterator pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

IteratorPHP's built-in Iterator interface 5 methods: rewind, valid, current, key, next
Concrete iteratorCustomerIterator walks a paginated API one customer at a time
AggregatePHP's built-in IteratorAggregate an object that hands out an iterator
Concrete aggregateCrmCustomers what the caller loops over with foreach
<?php

declare(strict_types=1);

// ── A fake API that returns customers 3 at a time (like a real paginated API) ──
final class FakeCrmApi
{
    public int $requests = 0;

    /** @return list<string> */
    public function page(int $page): array
    {
        $this->requests++;
        $all = ['ali@x.com', 'mona@x.com', 'omar@x.com', 'laila@x.com', 'sara@x.com', 'adam@x.com', 'nour@x.com'];

        return array_slice($all, ($page - 1) * 3, 3);       // 3 customers per page
    }
}

// ── Step 1: the concrete iterator. PHP calls these 5 methods for you in foreach. ──
/** @implements Iterator<int, string> */
final class CustomerIterator implements Iterator  // Concrete iterator
{
    private int $page = 1;
    /** @var list<string> */
    private array $current = [];                            // the customers of the current page
    private int $index = 0;                                 // position inside the current page
    private int $position = 0;                              // position overall

    public function __construct(private readonly FakeCrmApi $api)
    {
    }

    public function rewind(): void  // 1. start from the beginning
    {
        $this->page = 1;
        $this->current = $this->api->page(1);
        $this->index = 0;
        $this->position = 0;
    }

    public function valid(): bool  // 2. is there a customer here?
    {
        if ($this->index >= count($this->current) && count($this->current) === 3) {
            $this->page++;                                  // page used up: fetch the next one now
            $this->current = $this->api->page($this->page);
            $this->index = 0;
        }

        return $this->index < count($this->current);
    }

    public function current(): string  // 3. give me the customer
    {
        return $this->current[$this->index];
    }

    public function key(): int  // 4. give me its position
    {
        return $this->position;
    }

    public function next(): void  // 5. move forward
    {
        $this->index++;
        $this->position++;
    }
}

// ── Step 2: the aggregate. What the caller loops over. ──
/** @implements IteratorAggregate<int, string> */
final class CrmCustomers implements IteratorAggregate  // Concrete aggregate
{
    public function __construct(private readonly FakeCrmApi $api)
    {
    }

    /** @return Iterator<int, string> */
    public function getIterator(): Iterator  // a fresh iterator for every foreach
    {
        return new CustomerIterator($this->api);
    }
}

// ── Using it: the caller never sees pages ──
$api = new FakeCrmApi();

foreach (new CrmCustomers($api) as $number => $email) {
    echo "{$number}: {$email}\n";
}
echo "API requests: {$api->requests}\n";

// It's lazy: stopping early means fewer requests.
$api->requests = 0;
foreach (new CrmCustomers($api) as $email) {
    if ($email === 'mona@x.com') {
        break;
    }
}
echo "Stopped at Mona after {$api->requests} request\n";

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

final class CrmCustomers implements IteratorAggregate  // hides HOW they're fetched
{
    public function __construct(private \Illuminate\Http\Client\PendingRequest $http) {}

    public function getIterator(): Generator
    {
        $page = 1;

        do {
            $response = $this->http
                ->get('/customers', ['page' => $page++, 'per_page' => 100])
                ->throw();                                     // 4xx/5xx = exception, not empty data

            foreach ($response->json('data') as $customer) {
                yield $customer;  // one at a time, flat memory
            }
        } while ($response->json('meta.has_more') === true);
    }
}

$customers = new CrmCustomers(
    Http::baseUrl(config('services.crm.url'))->withToken(config('services.crm.token'))->retry(3, 500),
);

foreach ($customers as $customer) {  // pagination is invisible here
    Customer::updateOrCreate(['crm_id' => $customer['id']], ['email' => $customer['email']]);
}

How Laravel builds it inside: Collection implements IteratorAggregate: its getIterator() returns a new ArrayIterator over its items, which is why foreach works on collections. Paginators do the same with the items of the current page.
