Each school scores teachers its own way

Strategy

New ticket

Smouha wants weighted scores, Miami wants the median

From Ahmed Nabil, Product Owner

Smouha: students count 50%, peers 20%, the principal 30%. Miami: use the median, so one angry student can’t sink a teacher. Every other school keeps the plain average. Two more schools are already asking for their own rules.

Why the quick fix is a trap

The quick fix is to teach averageOf() about schools:

the quick fix (we won’t do this)
function scoreFor(array $answers, string $school): float
{
    if ($school === 'Smouha') {
        // 15 lines of weighted maths
    } elseif ($school === 'Miami') {
        // 12 lines of median maths
    } else {
        // the average
    }
}

Every new school opens this function and adds a branch, risking the branches that already work. One function now knows every school’s private rules, and the only way to check the Miami maths is to run the whole thing with a Miami teacher.

Each branch is the same job (turn answers into one number) done a different way. That is the exact situation one pattern was made for.

The pattern: Strategy

Remember itThe same job can be done in several ways → put each way in its own class, behind one interface. The code that uses it gets one and never asks which.

We define one interface, ScoringMethod, with one method: score(array $responses): ?float. Then one class per way of scoring: AverageScoring, MedianScoring, WeightedScoring. These are the strategies.

The class that uses them, TermReport, is the context. It receives a scoring method and calls score(). It has no if about schools and doesn’t know which class it was given.

A new school with a new rule is now one new class. Nothing that already works is opened.

  1. 1The strategy interface

    One method, one job. It returns ?float: null means "no answers to score". Until now a teacher with no answers got 0.00, which looks like a real (terrible) score. null makes that case impossible to miss.

    src/Scoring/ScoringMethod.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Scoring;

use Evalu8\Domain\Response;

/**
 * The Strategy: one way of turning a teacher's answers into one number.
 * Every scoring method follows this interface, so the code that uses a
 * method never needs to know which one it has.
 */
interface ScoringMethod
{
    /**
     * @param list<Response> $responses
     * @return float|null null when there are no answers to score
     */
    public function score(array $responses): ?float;

    /** A short label for reports, e.g. "median". */
    public function name(): string;
}

  2. 2Strategy 1: the average

    The old averageOf() function, moved into its own class.

    src/Scoring/AverageScoring.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Scoring;

/**
 * Every answer counts the same. The method every school used until now.
 */
final readonly class AverageScoring implements ScoringMethod
{
    public function score(array $responses): ?float
    {
        if (count($responses) === 0) {
            return null;
        }

        $total = 0;
        foreach ($responses as $response) {
            $total += $response->score->value;
        }

        return $total / count($responses);
    }

    public function name(): string
    {
        return 'average';
    }
}

  3. 3Strategy 2: the median

    Sort the scores and take the middle one; with an even count, average the two middle ones.

    src/Scoring/MedianScoring.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Scoring;

/**
 * The middle answer. One extreme answer can't pull the result up or down.
 */
final readonly class MedianScoring implements ScoringMethod
{
    public function score(array $responses): ?float
    {
        $count = count($responses);
        if ($count === 0) {
            return null;
        }

        $values = [];
        foreach ($responses as $response) {
            $values[] = $response->score->value;
        }
        sort($values);

        $middle = intdiv($count, 2);
        if ($count % 2 === 1) {
            return (float) $values[$middle];
        }

        return ($values[$middle - 1] + $values[$middle]) / 2;   // even count: average of the two middle values
    }

    public function name(): string
    {
        return 'median';
    }
}

  4. 4Strategy 3: weighted by role

    The weights are checked once, in the constructor: every key must be a real role, and they must add up to 1.0. A wrong setup fails when the app starts, not halfway through a report.

    If a group gave no answers (no principal yet, for example), its share is spread over the groups that did, so the result stays on the 1–5 scale instead of silently dropping.

    src/Scoring/WeightedScoring.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Scoring;

use Evalu8\Domain\RespondentRole;
use InvalidArgumentException;

/**
 * Each group of respondents gets a share of the final score,
 * e.g. students 50%, peers 20%, principal 30%.
 *
 * The average of each group is weighted. If a group gave no answers,
 * its share is spread over the groups that did, so the result stays on the 1–5 scale.
 */
final readonly class WeightedScoring implements ScoringMethod
{
    /** @var array<string, float> role value => weight */
    private array $weights;

    /**
     * @param array<string, float> $weights role value => weight, must add up to 1.0
     */
    public function __construct(array $weights)
    {
        foreach (array_keys($weights) as $role) {
            if (RespondentRole::tryFrom($role) === null) {
                throw new InvalidArgumentException("Unknown role \"{$role}\" in scoring weights.");
            }
        }

        if (abs(array_sum($weights) - 1.0) > 0.0001) {
            throw new InvalidArgumentException('Scoring weights must add up to 1.0, got ' . array_sum($weights) . '.');
        }

        $this->weights = $weights;
    }

    public function score(array $responses): ?float
    {
        /** @var array<string, list<int>> $byRole role value => that group's scores */
        $byRole = [];
        foreach ($responses as $response) {
            $byRole[$response->role->value][] = $response->score->value;
        }

        $weightedTotal = 0.0;
        $usedWeight = 0.0;
        foreach ($byRole as $role => $scores) {
            $weight = $this->weights[$role] ?? 0.0;
            $weightedTotal += $weight * (array_sum($scores) / count($scores));
            $usedWeight += $weight;
        }

        if ($usedWeight === 0.0) {
            return null;                                    // no answers from any weighted group
        }

        return $weightedTotal / $usedWeight;
    }

    public function name(): string
    {
        return 'weighted';
    }
}

  5. 5One result per teacher

    The report, the emails and the CSV used to calculate the score three times. Now it is calculated once into a TeacherResult, and all three outputs read from it.

    src/Reporting/TeacherResult.phpnew fileGitHub

declare(strict_types=1);

namespace Evalu8\Reporting;

use Evalu8\Domain\Teacher;

/**
 * One line of the term report: calculated once, then printed, emailed and exported.
 */
final readonly class TeacherResult
{
    public function __construct(
        public Teacher $teacher,
        public int $responseCount,
        public ?float $score,                               // null = no answers this term
        public string $method,
    ) {
    }

    public function formattedScore(): string
    {
        return $this->score === null ? 'no answers' : number_format($this->score, 2);
    }
}

  6. 6The context: TermReport

    It looks up the scoring method for the teacher’s school, falls back to the default, and calls score(). Notice what is missing: any if about how scoring works.

    src/Reporting/TermReport.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting;

use Evalu8\Domain\ResponseRepository;
use Evalu8\Domain\TeacherRepository;
use Evalu8\Scoring\ScoringMethod;

/**
 * The Context: it uses a scoring method without knowing which one.
 */
final readonly class TermReport
{
    /**
     * @param array<string, ScoringMethod> $scoringBySchool school name => its scoring method
     */
    public function __construct(
        private TeacherRepository $teachers,
        private ResponseRepository $responses,
        private array $scoringBySchool,
        private ScoringMethod $defaultScoring,
    ) {
    }

    /** @return list<TeacherResult> */
    public function results(string $term): array
    {
        $results = [];

        foreach ($this->teachers->all() as $teacher) {
            $answers = $this->responses->forTeacherInTerm($teacher->id, $term);
            $method = $this->scoringBySchool[$teacher->school] ?? $this->defaultScoring;

            $results[] = new TeacherResult(
                $teacher,
                count($answers),
                $method->score($answers),  // no "if school is..." anywhere
                $method->name(),
            );
        }

        return $results;
    }
}

How Laravel does it

Laravel’s password hashing is a Strategy. The Hasher contract is the interface; BcryptHasher and ArgonHasher are the strategies. Your code only calls Hash::make() and never knows which one runs.

In your own app, type-hint the interface and let the container give you the right strategy:

Laravel
// AppServiceProvider::register()
$this->app->bind(ScoringMethod::class, AverageScoring::class);   // the default

// Any class that needs one just asks for the interface:
final class TermReport
{
    public function __construct(
        private ScoringMethod $defaultScoring,
        // ...
    ) {}
}

Check yourself

Answer in your head, then open the answer.

Victoria College wants "drop the highest and lowest score, then average". What do you change?

Add one class, for example TrimmedAverageScoring implements ScoringMethod, and give it to Victoria. TermReport and the other strategies don’t change.

How is Strategy different from the if/elseif version, if both produce the same numbers?

Each way of scoring is its own class: it can be read, changed and checked alone, and adding one doesn’t touch the others. The code that uses them has no branches.

Why does score() return ?float instead of float?

No answers is not a score of 0. Returning null forces the report to show "no answers" instead of a fake 0.00.
