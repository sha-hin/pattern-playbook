New ticket

Lists for the support program and the excellence award

From Mona Saleh, Head of Quality

Support program: score below 3.0, at least 3 answers (otherwise the score means nothing), not on leave. Excellence award: score of at least 4.0 and at least 4 answers. HR says nobody on leave can be in any program. Last term Karim got the award letter while he was on leave.

Why the quick fix is a trap

Each list is a function with its own conditions:

the quick fix (we won’t do this)
function supportList(array $results): array
{
    return array_filter($results, fn ($r) => $r->score < 3 && $r->responseCount >= 3 && !$r->teacher->onLeave);
}

function awardList(array $results): array
{
    return array_filter($results, fn ($r) => $r->score >= 4 && $r->responseCount >= 4);   // forgot "on leave"
}

The same rules ("enough answers", "not on leave") are written again in every list, and one copy forgot one of them. The rules have no names, so a screen can’t show which ones a teacher failed, and the next program ("mentors") will copy them a third time.

Each rule is a small yes/no question about a teacher. We want each one written once, with a name, and programs built by combining them.

The pattern: Specification

Remember itBusiness rules decide whether something qualifies, and the rules combine and repeat → make each rule an object with isSatisfiedBy(), and combine rules with and, or and not.

Each small rule is a class: ScoreBelow, ScoreAtLeast, HasAtLeastAnswers, OnLeave. Each answers one question with isSatisfiedBy($result) and can describe itself in words.

and(), or() and not() combine rules into new rules (AllOf, AnyOf, NotSatisfied), so a program reads like its definition: (new ScoreBelow(3.0))->and(new HasAtLeastAnswers(3))->and((new OnLeave())->not()).

It is a close cousin of the Interpreter from chapter 18 (small objects combined into a tree that evaluates itself), applied to business rules written by developers. Specification was described by Eric Evans and Martin Fowler; it is not in the Gang of Four book.

  5. 5The specification interface

    A rule answers yes or no, describes itself, and combines with others.

    src/Selection/Specification.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Selection;

use Evalu8\Reporting\TeacherResult;

/**
 * A business rule as an object: "is this teacher's result what we are looking for?"
 * Rules combine with and(), or() and not() into bigger rules.
 */
interface Specification
{
    public function isSatisfiedBy(TeacherResult $result): bool;

    /** The rule in words, for screens and audit logs. */
    public function describe(): string;

    public function and(Specification $other): Specification;

    public function or(Specification $other): Specification;

    public function not(): Specification;
}

  6. 6The combinators, written once

    Every rule extends this class and gets and(), or() and not().

    src/Selection/BaseSpecification.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Selection;

/**
 * Gives every specification the three combinators, so rules read like sentences:
 *     (new ScoreBelow(3.0))->and(new HasAtLeastAnswers(3))->and((new OnLeave())->not())
 */
abstract class BaseSpecification implements Specification
{
    public function and(Specification $other): Specification
    {
        return new AllOf($this, $other);
    }

    public function or(Specification $other): Specification
    {
        return new AnyOf($this, $other);
    }

    public function not(): Specification
    {
        return new NotSatisfied($this);
    }
}

  7. 7and

    src/Selection/AllOf.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Selection;

use Evalu8\Reporting\TeacherResult;

final class AllOf extends BaseSpecification
{
    /** @var list<Specification> */
    private readonly array $parts;

    public function __construct(Specification ...$parts)
    {
        $this->parts = array_values($parts);
    }

    public function isSatisfiedBy(TeacherResult $result): bool
    {
        foreach ($this->parts as $part) {
            if (!$part->isSatisfiedBy($result)) {
                return false;
            }
        }

        return true;
    }

    public function describe(): string
    {
        return implode(' and ', array_map(fn (Specification $s): string => $s->describe(), $this->parts));
    }
}

namespace Evalu8\Selection;

use Evalu8\Reporting\TeacherResult;

final class AnyOf extends BaseSpecification
{
    /** @var list<Specification> */
    private readonly array $parts;

    public function __construct(Specification ...$parts)
    {
        $this->parts = array_values($parts);
    }

    public function isSatisfiedBy(TeacherResult $result): bool
    {
        foreach ($this->parts as $part) {
            if ($part->isSatisfiedBy($result)) {
                return true;
            }
        }

        return false;
    }

    public function describe(): string
    {
        return '(' . implode(' or ', array_map(fn (Specification $s): string => $s->describe(), $this->parts)) . ')';
    }
}

namespace Evalu8\Selection;

use Evalu8\Reporting\TeacherResult;

final class NotSatisfied extends BaseSpecification
{
    public function __construct(private readonly Specification $inner)
    {
    }

    public function isSatisfiedBy(TeacherResult $result): bool
    {
        return !$this->inner->isSatisfiedBy($result);
    }

    public function describe(): string
    {
        return "not {$this->inner->describe()}";
    }
}

/** Enough answers for the score to mean something. */
final class HasAtLeastAnswers extends BaseSpecification
{
    public function __construct(private readonly int $minimum)

  11. 11Rule: score below a limit

    A teacher with no answers has no score, which is not a low score: null never matches.

    src/Selection/ScoreBelow.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Selection;

use Evalu8\Reporting\TeacherResult;

final class ScoreBelow extends BaseSpecification
{
    public function __construct(private readonly float $limit)
    {
    }

    public function isSatisfiedBy(TeacherResult $result): bool
    {
        return $result->score !== null && $result->score < $this->limit;   // no answers is not a low score
    }

    public function describe(): string
    {
        return sprintf('score below %.1f', $this->limit);
    }
}

  14. 14The programs, as combinations

    Each program is a sentence made of named rules. "Not on leave" is written once and used by both.

    src/Selection/Programs.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Selection;

/**
 * The school programs' entry rules, each written once, by combining small specifications.
 */
final class Programs
{
    public static function support(): Specification
    {
        return (new ScoreBelow(3.0))
            ->and(new HasAtLeastAnswers(3))
            ->and((new OnLeave())->not());
    }

    public static function excellenceAward(): Specification
    {
        return (new ScoreAtLeast(4.0))
            ->and(new HasAtLeastAnswers(4))
            ->and((new OnLeave())->not());
    }
}

    bin/programs.phpnew fileGitHub

declare(strict_types=1);

/*
 * Evalu8, chapter 26: who qualifies for which program, from rules written once and combined.
 *
 *     composer dump-autoload
 *     php bin/programs.php
 */

use Evalu8\Container\Container;
use Evalu8\Demo\SampleData;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Reporting\TermReport;
use Evalu8\Selection\Programs;

const CURRENT_TERM = '2026-T1';

/** @var Container $app */
$app = require __DIR__ . '/../bootstrap/app.php';
SampleData::loadAnswers($app->make(ResponseRepository::class), CURRENT_TERM);
$results = $app->make(TermReport::class)->results(CURRENT_TERM);

$programs = [
    'Support program' => Programs::support(),
    'Excellence award' => Programs::excellenceAward(),
];

foreach ($programs as $name => $rule) {
    echo "\n" . strtoupper($name) . "\n  rule: {$rule->describe()}\n";

    foreach ($results as $result) {
        $mark = $rule->isSatisfiedBy($result) ? 'yes' : ' - ';
        echo "  {$mark}  " . str_pad($result->teacher->name, 14)
            . "score {$result->formattedScore()}, {$result->responseCount} answers"
            . ($result->teacher->onLeave ? ', on leave' : '') . "\n";
    }
}

How Laravel does it

In Eloquent, the closest tool is query scopes: named, reusable conditions that combine by chaining (->onLeave(false)->scoreBelow(3)). The difference is where they run: scopes become SQL, specifications run on objects in PHP. Large lists should filter in SQL; Doctrine’s Criteria can do both.

Laravel
// Named, combinable rules that run in the database:
final class TermResult extends Model
{
    public function scopeScoreBelow(Builder $query, float $limit): void
    {
        $query->where('score', '<', $limit);
    }

    public function scopeWithAtLeastAnswers(Builder $query, int $minimum): void
    {
        $query->where('responses', '>=', $minimum);
    }
}

$support = TermResult::scoreBelow(3.0)->withAtLeastAnswers(3)->whereRelation('teacher', 'on_leave', false)->get();

Check yourself

Answer in your head, then open the answer.

HR adds "must have taught at least one full term". What changes?

One new rule class, added to each program with and(). The existing rules don’t change.

Why does ScoreBelow return false for a teacher with no answers?

No answers means no score, not a low one. Putting that teacher in the support program would be wrong.

How is Specification related to the Interpreter from chapter 18?

Both build a tree of small objects that evaluate themselves. Interpreter parses a user-typed language; Specification is built in code from named business rules.
