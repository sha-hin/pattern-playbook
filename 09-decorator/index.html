Chapter 9 of 30

AI calls are slow and expensive

Decorator

New ticket

The term report takes 30 minutes and sometimes dies on a timeout

From Omar Hassan, DevOps

With 600 teachers, the model takes about 3 seconds each, and the report runs twice a day on the same comments. The Ollama server is busy in the morning and times out now and then, which kills the whole run. We also have no record of which calls were made or how long they took.

Why the quick fix is a trap

The quick fix puts everything inside the adapter:

the quick fix (we won’t do this)
final class OllamaCommentAnalyzer implements CommentAnalyzer
{
    public function summarize(array $comments): string
    {
        // 1. look in the cache...
        // 2. call Ollama, retrying 3 times on timeouts...
        // 3. log the duration...
        // 4. save to the cache...
    }
}
// ...and the same four steps copied into OpenAiCommentAnalyzer.

The adapter’s one job was translating Ollama. Now it does four jobs, the OpenAI adapter needs a copy of the same code, and a test of the translation also runs the cache and the retry loop. Turning off the cache for one script means editing both adapters.

Caching, retrying and logging are not about Ollama at all. They are extra behaviour around any analyzer.

The pattern: Decorator

Remember itYou need extra behaviour around an object without changing it → wrap it in a class with the same interface that adds the behaviour and passes the call on. Wrappers stack.

Each decorator implements CommentAnalyzer and holds another CommentAnalyzer inside. CachingCommentAnalyzer checks the cache and only calls the inner analyzer on a miss. RetryingCommentAnalyzer calls the inner one again on temporary failures. LoggingCommentAnalyzer records each call that gets through.

Because every layer has the same interface, they stack in any order, like a phone in a case in a pouch: Caching( Logging( Retrying( Ollama ) ) ). Remove a layer by not wrapping it. The adapters don’t change.

Adapter vs Decorator

Both wrap an object, so they are easy to confuse. Ask what the wrapped object looks like.

  2. 2An in-memory cache

    src/Cache/ArrayCache.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Cache;

/**
 * An in-memory cache that lives as long as the PHP process. Good for demos and one-off scripts.
 */
final class ArrayCache implements Cache
{
    /** @var array<string, array{value: string, expires: int}> */
    private array $items = [];

    public function get(string $key): ?string
    {
        $item = $this->items[$key] ?? null;
        if ($item === null || $item['expires'] < time()) {
            return null;
        }

        return $item['value'];
    }

    public function set(string $key, string $value, int $ttlSeconds): void
    {
        $this->items[$key] = ['value' => $value, 'expires' => time() + $ttlSeconds];
    }
}

namespace Evalu8\Logging;

/**
 * Writes one line per log entry to a stream (a file, or STDOUT/STDERR).
 */
final readonly class StreamLogger implements Logger
{
    /** @param resource $stream */
    public function __construct(private mixed $stream)
    {
    }

    public function info(string $message, array $context = []): void
    {
        $this->write('info', $message, $context);
    }

    public function warning(string $message, array $context = []): void
    {
        $this->write('warning', $message, $context);
    }

    /** @param array<string, scalar> $context */
    private function write(string $level, string $message, array $context): void
    {
        $details = '';
        foreach ($context as $key => $value) {
            $details .= " {$key}=" . var_export($value, true);
        }

        fwrite($this->stream, "[{$level}] {$message}{$details}\n");
    }
}

  8. 8Decorator 1: caching

    The key is a hash of the comments, so the same comments always hit the same entry. A failure throws before set(), so failures are never cached.

    src/Analysis/CachingCommentAnalyzer.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Analysis;

use Evalu8\Cache\Cache;

/**
 * Decorator: remembers summaries, so the same comments are never analysed twice.
 * Failures are not cached: they throw before anything is stored.
 */
final readonly class CachingCommentAnalyzer implements CommentAnalyzer
{
    public function __construct(
        private CommentAnalyzer $inner,                     // the analyzer being wrapped
        private Cache $cache,
        private int $ttlSeconds = 7 * 24 * 3600,
    ) {
    }

    public function summarize(array $comments): string
    {
        $key = 'comment-summary:' . hash('sha256', implode("\n", $comments));

        $cached = $this->cache->get($key);
        if ($cached !== null) {
            return $cached;                                 // added behaviour: answer from the cache
        }

        $summary = $this->inner->summarize($comments);      // otherwise pass the call through
        $this->cache->set($key, $summary, $this->ttlSeconds);

        return $summary;
    }
}

  9. 9Decorator 2: retrying

    Only temporary failures are retried, with a delay that doubles each time. The last failure, or any permanent one, is rethrown unchanged. The sleep function can be replaced, so the demo doesn’t wait.

    src/Analysis/RetryingCommentAnalyzer.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Analysis;

use Closure;
use InvalidArgumentException;

/**
 * Decorator: retries temporary failures, waiting a little longer each time.
 * Permanent failures, and the last temporary one, are thrown as they are.
 */
final readonly class RetryingCommentAnalyzer implements CommentAnalyzer
{
    /** @var Closure(int): void */
    private Closure $sleep;

    /**
     * @param Closure(int): void|null $sleep receives milliseconds; replaceable so demos don't wait
     */
    public function __construct(
        private CommentAnalyzer $inner,
        private int $attempts = 3,
        private int $firstDelayMs = 500,
        ?Closure $sleep = null,
    ) {
        if ($attempts < 1) {
            throw new InvalidArgumentException('At least one attempt is needed.');
        }

        $this->sleep = $sleep ?? static function (int $ms): void {
            usleep($ms * 1000);
        };
    }

    public function summarize(array $comments): string
    {
        for ($attempt = 1; ; $attempt++) {
            try {
                return $this->inner->summarize($comments);
            } catch (AnalysisFailed $e) {
                if (!$e->temporary || $attempt >= $this->attempts) {
                    throw $e;                               // not worth retrying, or out of attempts
                }

                ($this->sleep)($this->firstDelayMs * 2 ** ($attempt - 1));   // 500 ms, 1 s, 2 s...
            }
        }
    }
}

  10. 10Decorator 3: logging

    Logs every call that reaches the provider and every failure, then lets the failure continue.

    src/Analysis/LoggingCommentAnalyzer.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Analysis;

use Evalu8\Logging\Logger;

/**
 * Decorator: logs every call that reaches the provider, with its duration, and every failure.
 */
final readonly class LoggingCommentAnalyzer implements CommentAnalyzer
{
    public function __construct(
        private CommentAnalyzer $inner,
        private Logger $logger,
    ) {
    }

    public function summarize(array $comments): string
    {
        $start = hrtime(true);

        try {
            $summary = $this->inner->summarize($comments);
        } catch (AnalysisFailed $e) {
            $this->logger->warning('comment analysis failed', ['error' => $e->getMessage(), 'temporary' => $e->temporary]);
            throw $e;
        }

        $this->logger->info('comment analysis', [
            'comments' => count($comments),
            'ms' => intdiv(hrtime(true) - $start, 1_000_000),
        ]);

        return $summary;
    }
}

How Laravel does it

The container can decorate a binding for you: $this->app->extend() receives the object that was going to be returned and lets you wrap it. Each extend() adds one layer.

Laravel also has the behaviours themselves: Cache::remember() and the retry() helper.

Laravel
// AppServiceProvider::register(): each extend() wraps what the container would return
$this->app->extend(CommentAnalyzer::class, fn (CommentAnalyzer $inner, Application $app) =>
    new RetryingCommentAnalyzer($inner)
);
$this->app->extend(CommentAnalyzer::class, fn (CommentAnalyzer $inner, Application $app) =>
    new CachingCommentAnalyzer($inner, $app->make(Cache::class))
);

Check yourself

Answer in your head, then open the answer.

A school wants analysis without caching, for privacy. What changes?

Only the wiring for that case: don’t wrap with CachingCommentAnalyzer. No analyzer class changes.

Why is the cache the outermost layer?

A cache hit should skip everything inside it: no log line, no retries, no call to the model.

Why doesn’t the retry layer retry "model not found"?

It is a permanent failure: retrying wastes time and gives the same error. The adapter marks only timeouts as temporary.
