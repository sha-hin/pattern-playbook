New ticket

Only this term’s answers must count

From Ahmed Nabil, Product Owner

From now on every answer belongs to a term, for example 2026-T1. The term report, the emails and the Ministry CSV must only count the current term. Last term’s answers are still in the database and must stay there.

Why the quick fix is a trap

The SELECT exists three times in the script, once per output:

the quick fix (we won’t do this)
$rows = $db->query('SELECT * FROM responses WHERE teacher_id = ' . $teacher['id'])->fetchAll();   // report
$rows = $db->query('SELECT * FROM responses WHERE teacher_id = ' . $teacher['id'])->fetchAll();   // emails
$rows = $db->query('SELECT score FROM responses WHERE teacher_id = ' . $teacher['id'])->fetchAll(); // CSV

Adding AND term = ... three times works today. Next month someone writes a fourth query for a dashboard, forgets the term, and the dashboard shows two terms mixed together. Nothing fails; the numbers are just wrong.

The deeper problem: every part of the app knows the table names, the column names and how a row is turned into data. The question "this teacher’s answers for this term" has no name and no home.

The pattern: Repository

Remember itOne class per kind of data that works like a collection: "add this", "give me these". All the SQL lives inside it, and the rest of the app only knows its interface.

The rest of the app asks $responses->forTeacherInTerm($teacherId, $term) and gets back a list of Response objects. How they are stored (SQLite today, MySQL tomorrow, an API one day) is the repository’s business only.

We first define the repository as an interface in the domain (ResponseRepository), then write one implementation for SQLite. Code that uses it depends on the interface, so it never sees SQL.

Repository is not in the Gang of Four book. It comes from Martin Fowler’s *Patterns of Enterprise Application Architecture* (2002) and Domain-Driven Design.

Data Mapper vs Active Record

There are two ways to connect objects to database rows, and you will meet both.

In Active Record, the object *is* a row: it knows its table and saves itself ($response->save()). Laravel’s Eloquent works this way. It is quick to write, but every model depends on the database.

In Data Mapper, the object is plain PHP and knows nothing about storage; a separate class copies data between rows and objects. Our Response has no save() method, and SqliteResponseRepository does the mapping in add() (object → row) and toResponse() (row → object). Doctrine ORM works this way.

Active Record (Eloquent)Data Mapper (this chapter, Doctrine)
Who saves?$response->save()$repository->add($response)
Object knows the table?YesNo
Good forCRUD-heavy apps, fast developmentRich business rules, swappable storage

  6. 6The SQLite repositories: all SQL lives here

    Every query uses a prepared statement. add() turns an object into a row, and toResponse() turns a row back into an object through the value objects, so a bad value that is already in the database fails loudly when it is read.

    src/Infrastructure/Sqlite/SqliteResponseRepository.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Infrastructure\Sqlite;

use Evalu8\Domain\RespondentRole;
use Evalu8\Domain\Response;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Domain\Score;
use PDO;

/**
 * The ONLY class that knows how responses are stored in SQL.
 */
final readonly class SqliteResponseRepository implements ResponseRepository
{
    public function __construct(private PDO $db)
    {
    }

    public function add(Response $response): void
    {
        $insert = $this->db->prepare(
            'INSERT INTO responses (teacher_id, term, role, score, comment) VALUES (?, ?, ?, ?, ?)'
        );

        $insert->execute([                                  // object → row
            $response->teacherId,
            $response->term,
            $response->role->value,
            $response->score->value,
            $response->comment,
        ]);
    }

    public function forTeacherInTerm(int $teacherId, string $term): array
    {
        $select = $this->db->prepare(
            'SELECT teacher_id, term, role, score, comment FROM responses WHERE teacher_id = ? AND term = ? ORDER BY id'
        );
        $select->execute([$teacherId, $term]);

        $responses = [];
        foreach ($select->fetchAll(PDO::FETCH_ASSOC) as $row) {
            $responses[] = $this->toResponse($row);
        }

        return $responses;
    }

    /**
     * Row → object. Rows are rebuilt through the value objects, so a bad
     * value already in the database fails loudly here instead of being used.
     *
     * @param array<string, mixed> $row
     */
    private function toResponse(array $row): Response
    {
        return new Response(
            (int) $row['teacher_id'],
            (string) $row['term'],
            RespondentRole::from((string) $row['role']),
            new Score((int) $row['score']),
            (string) $row['comment'],
        );
    }
}

  7. 7The teacher repository

    It maps an empty email column to null.

    src/Infrastructure/Sqlite/SqliteTeacherRepository.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Infrastructure\Sqlite;

use Evalu8\Domain\EmailAddress;
use Evalu8\Domain\Teacher;
use Evalu8\Domain\TeacherRepository;
use PDO;

final readonly class SqliteTeacherRepository implements TeacherRepository
{
    public function __construct(private PDO $db)
    {
    }

    public function all(): array
    {
        $rows = $this->db->query('SELECT id, name, email, school FROM teachers ORDER BY id')->fetchAll(PDO::FETCH_ASSOC);

        $teachers = [];
        foreach ($rows as $row) {
            $teachers[] = $this->toTeacher($row);
        }

        return $teachers;
    }

    /**
     * The "mapper" part: one database row → one Teacher object.
     *
     * @param array<string, mixed> $row
     */
    private function toTeacher(array $row): Teacher
    {
        $email = trim((string) $row['email']);

        return new Teacher(
            (int) $row['id'],
            (string) $row['name'],
            $email === '' ? null : new EmailAddress($email),
            (string) $row['school'],
        );
    }
}

How Laravel does it

Eloquent is Active Record, so most Laravel apps don’t add a repository: they give the repeated query a name with a local scope on the model. That already solves this ticket: the rule is written once.

Add a repository interface on top of Eloquent only when you need to: to keep business code free of Eloquent, to swap the storage, or to fake it in a test. Wrapping every model "just because" adds files without adding value.

Laravel
// The rule, written once, as a scope on the Response model:
public function scopeForTeacherInTerm(Builder $query, int $teacherId, string $term): void
{
    $query->where('teacher_id', $teacherId)->where('term', $term);
}

// Everywhere else:
$answers = Response::forTeacherInTerm($teacher->id, $term)->get();

// When you do need a repository, it implements the same interface with Eloquent inside:
final class EloquentResponseRepository implements ResponseRepository
{
    public function forTeacherInTerm(int $teacherId, string $term): array
    {
        return ResponseModel::forTeacherInTerm($teacherId, $term)
            ->get()
            ->map(fn (ResponseModel $row): Response => $row->toDomain())
            ->all();
    }

    // add() ...
}

Check yourself

Answer in your head, then open the answer.

A new dashboard needs this term’s answers for one teacher. What does its code look like now?

One call: $responses->forTeacherInTerm($teacherId, $term). It cannot forget the term rule, because the rule is inside the repository.

Why is ResponseRepository an interface and not just the SQLite class?

So the code that uses it depends on "something that stores responses", not on SQLite. Another implementation (MySQL, Eloquent, an in-memory fake) can replace it without changing that code.

Is Eloquent a Data Mapper or an Active Record?

Active Record: each model knows its table and saves itself with save().
