Exporting 100,000 responses runs out of memory

IteratorGenerators

New ticket

Send us every raw answer for 2026-T1

From Ministry of Education, data office

From this term we need the raw, anonymous answers (term, teacher, role, score), not only the averages. Nationally that is several hundred thousand rows. Our first test file failed on your side with "Allowed memory size of 134217728 bytes exhausted".

Why the quick fix is a trap

The first version loaded every answer, then wrote the file:

the quick fix (we won’t do this)
$all = $db->query("SELECT * FROM responses WHERE term = '2026-T1'")->fetchAll();   // every row, at once
foreach ($all as $row) {
    fputcsv($file, [/* ... */]);
}

Memory grows with the number of answers: twice the answers, twice the memory, until PHP’s limit stops the export half-way. Raising memory_limit only moves the wall.

The export never needs more than one answer at a time. It needs something it can loop over that fetches rows as the loop goes.

The pattern: Iterator (with Generators)

Remember itCode needs to go through a collection without caring how it is stored or fetched → give it something to loop over. In PHP, a generator (yield) is the easiest way to write one.

The Iterator pattern separates "going through the items" from "how the items are stored". In PHP it is built into the language: anything that implements Iterator or IteratorAggregate works in foreach, exactly like an array.

A generator is a function that contains yield. Calling it doesn’t run it; it returns a Generator object, which is an Iterator. Each time the loop asks for the next item, the function runs until the next yield, hands over one value, and pauses. Our inTerm() fetches 1,000 rows, yields them one by one, then fetches the next 1,000.

A generator can be looped over only once. TermResponses implements IteratorAggregate: every foreach calls its getIterator() and gets a fresh generator, so it behaves like a reusable collection.

Iterator is in the Gang of Four book. Generators are PHP’s built-in way to write iterators without the five methods of the Iterator interface.

  3. 3A collection you can loop over twice

    yield from passes every item of the repository’s generator through. Each foreach gets a new one.

    src/Reporting/TermResponses.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting;

use Evalu8\Domain\Response;
use Evalu8\Domain\ResponseRepository;
use IteratorAggregate;
use Traversable;

/**
 * "All answers of a term", as something you can loop over as often as you like.
 *
 * A generator can only be looped over once. IteratorAggregate fixes that: every foreach
 * calls getIterator() and gets a fresh generator, starting from the first row again.
 *
 * @implements IteratorAggregate<int, Response>
 */
final readonly class TermResponses implements IteratorAggregate
{
    public function __construct(
        private ResponseRepository $responses,
        private string $term,
    ) {
    }

    /** @return Traversable<int, Response> */
    public function getIterator(): Traversable
    {
        yield from $this->responses->inTerm($this->term);
    }
}

  4. 4The export accepts any iterable

    Typed as iterable, it works with an array or a stream. It never holds more than one answer.

    src/Reporting/RawAnswersExport.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting;

use Evalu8\Domain\Response;
use RuntimeException;

/**
 * The Ministry's raw file: one anonymous line per answer.
 * It accepts any iterable, so it works the same with an array or a stream.
 */
final readonly class RawAnswersExport
{
    /**
     * @param iterable<Response> $responses
     * @return int the number of answers written
     */
    public function write(iterable $responses, string $path): int
    {
        $file = fopen($path, 'w');
        if ($file === false) {
            throw new RuntimeException("Can't write the raw answers export to {$path}.");
        }

        $count = 0;
        try {
            fputcsv($file, ['term', 'teacher_id', 'role', 'score'], escape: '');
            foreach ($responses as $response) {            // one answer in memory at a time
                fputcsv($file, [$response->term, $response->teacherId, $response->role->value, $response->score->value], escape: '');
                $count++;
            }
        } finally {
            fclose($file);
        }

        return $count;
    }
}

  6. 6Measure both ways

    memory_reset_peak_usage() (PHP 8.2) starts a fresh measurement before each approach, so the setup isn’t counted.

    bin/export-raw.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * Evalu8, chapter 14: export every answer of a big term with flat memory.
 *
 *     composer dump-autoload
 *     php bin/export-raw.php
 */

use Evalu8\Container\Container;
use Evalu8\Demo\SampleData;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Reporting\RawAnswersExport;
use Evalu8\Reporting\TermResponses;

const BIG_TERM = '2026-T1';
const ANSWERS = 100_000;

/** @var Container $app */
$app = require __DIR__ . '/../bootstrap/app.php';
SampleData::loadManyAnswers($app->make(PDO::class), BIG_TERM, ANSWERS);

$responses = $app->make(ResponseRepository::class);
$export = new RawAnswersExport();
$path = sys_get_temp_dir() . '/evalu8-raw-answers.csv';

/** Runs $work and returns how many MB of extra memory it needed at its peak. */
function peakMb(callable $work): float
{
    gc_collect_cycles();
    memory_reset_peak_usage();
    $before = memory_get_usage();
    $work();

    return round((memory_get_peak_usage() - $before) / 1_048_576, 1);
}

echo 'Exporting ' . number_format(ANSWERS) . " answers\n\n";

$asArray = peakMb(function () use ($responses, $export, $path): void {
    $all = iterator_to_array($responses->inTerm(BIG_TERM), false);   // the old way: load everything first
    $export->write($all, $path);
});
echo "Load everything into an array, then write: {$asArray} MB\n";

$streamed = peakMb(function () use ($responses, $export, $path): void {
    $export->write($responses->inTerm(BIG_TERM), $path);             // stream: one batch at a time
});
echo "Stream with a generator:                   {$streamed} MB\n";

// TermResponses can be looped over more than once; a bare generator can't.
$term = new TermResponses($responses, BIG_TERM);
$first = 0;
foreach ($term as $response) {
    $first++;
}
$second = 0;
foreach ($term as $response) {
    $second++;
}
echo "\nLooped twice over TermResponses: {$first} and {$second} answers\n";

$generator = $responses->inTerm(BIG_TERM);
foreach ($generator as $index => $response) {
    if ($index === 1) {
        break;                                              // read two answers...
    }
}
try {
    foreach ($generator as $response) {                     // ...and try to loop over it again
    }
} catch (Exception $e) {
    echo "Looping twice over a bare generator: {$e->getMessage()}\n";
}

unlink($path);

How Laravel does it

Eloquent has the same tool built in: lazyById() returns a LazyCollection backed by a generator, querying in chunks with keyset pagination. cursor() streams too, but keeps one database cursor open.

Every Laravel Collection implements IteratorAggregate, which is why foreach works on it.

Laravel
// Streams the whole term in chunks of 1,000, using WHERE id > ? (keyset), not OFFSET:
$file = fopen($path, 'w');
Response::where('term', '2026-T1')
    ->lazyById(1000)
    ->each(fn (Response $r) => fputcsv($file, [$r->term, $r->teacher_id, $r->role, $r->score], escape: ''));

Check yourself

Answer in your head, then open the answer.

What happens when a function containing yield is called?

It doesn’t run yet. It returns a Generator object; the body runs step by step as a loop asks for the next value.

Why keyset pagination (id > ?) instead of LIMIT 1000 OFFSET 50000?

OFFSET makes the database skip all earlier rows on every page, so it gets slower, and rows added during the export can shift pages. Keyset jumps straight to the next id.

Why does TermResponses implement IteratorAggregate instead of being a generator itself?

A generator can only be looped over once. getIterator() creates a fresh generator for every foreach.

The statistics screen really does need a whole term in memory at once. 100,000 answers mean 100,000 Score objects, but there are only five possible scores.
