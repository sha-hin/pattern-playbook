Strategy

BehaviourGoF book

Google Maps: same trip, you pick Car, Walk or Bike.

The rule to rememberSame job, several ways to do it → one class per way, all behind one interface.

Without it: the pain

One method with a growing switch. Adding JSON means editing (and risking) the CSV, Excel and PDF code.

With it: the fix

Each format is its own class behind one interface. The code that uses it gets one and never asks which. Adding JSON is one new class.

Reach for it when you see

  • A switch on a "type" or "format" where each branch contains the actual WORK (many lines)
  • Every branch does the same job in a different way
  • You fear touching one branch because it could break another

Real job where it fits

Users download a report as CSV, Excel or PDF from a dropdown. Next month: JSON.

Before: the code that hurts

public function export(array $rows, string $format): string
{
    switch ($format) {
        case 'csv':   /* 30 lines */ break;
        case 'excel': /* 40 lines */ break;
        case 'pdf':   /* 50 lines */ break;   // JSON next month = edit this again
    }
}

Build it yourself: the full Strategy pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

StrategyExporter the interface every way of doing the job signs
Concrete strategiesCsvExporter, JsonExporter one class per way
ContextReportService uses whichever strategy it is given, never asks which
<?php

declare(strict_types=1);

interface Exporter  // Strategy: one contract for every way
{
    /** @param list<array<string, scalar>> $rows */
    public function export(array $rows): string;
}

final class CsvExporter implements Exporter  // Concrete strategy #1
{
    public function export(array $rows): string
    {
        if ($rows === []) {
            return '';
        }

        $out = fopen('php://temp', 'r+') ?: throw new RuntimeException('Cannot open a memory stream.');
        fputcsv($out, array_keys($rows[0]), ',', '"', '');
        foreach ($rows as $row) {
            fputcsv($out, array_values($row), ',', '"', '');
        }
        rewind($out);
        $csv = (string) stream_get_contents($out);
        fclose($out);

        return $csv;
    }
}

final class JsonExporter implements Exporter  // Concrete strategy #2
{
    public function export(array $rows): string
    {
        return json_encode($rows, JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR) . PHP_EOL;
    }
}

final class ReportService  // Context
{
    /** @param list<array<string, scalar>> $rows */
    public function __construct(private readonly array $rows) {}

    public function export(Exporter $exporter): string  // accepts ANY strategy
    {
        return $exporter->export($this->rows);  // never checks which one it got
    }
}

// ── Using it ────────────────────────────────────────────────────────────
$report = new ReportService([
    ['school' => 'Smouha', 'average' => 81],
    ['school' => 'Miami', 'average' => 77],
]);

echo $report->export(new CsvExporter());
echo $report->export(new JsonExporter());

// Adding XML later = one new class that implements Exporter. ReportService never changes.

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

interface Exporter
{
    public function export(iterable $rows): string;   // returns the file path
    public function extension(): string;
}

final class CsvExporter implements Exporter
{
    public function export(iterable $rows): string
    {
        $path = tempnam(sys_get_temp_dir(), 'report');
        $out = fopen($path, 'w') ?: throw new RuntimeException("Cannot write {$path}");
        foreach ($rows as $row) {
            fputcsv($out, $row);
        }
        fclose($out);
        return $path;
    }

    public function extension(): string { return 'csv'; }
}

final class PdfExporter implements Exporter { /* same two methods, uses Dompdf */ }

final class ReportService
{
    public function __construct(private ReportRepository $reports) {}

    public function export(Exporter $exporter): string  // receives ANY strategy
    {
        return $exporter->export($this->reports->rows());  // never asks which one it got
    }
}

// The strategies are swappable: ReportService never changes.
$service->export(new CsvExporter());
$service->export(new PdfExporter());
$service->export(new JsonExporter());   // next month: one new class, zero edits

// In a test: no real files at all
$service->export(new InMemoryExporter());

// Note what is NOT here: deciding which exporter matches the user's "pdf" string.
// That is a different job, with its own pattern: see Simple Factory.

How Laravel builds it inside: Hashing is built this way. Illuminate\Contracts\Hashing\Hasher is the Strategy interface, BcryptHasher and ArgonHasher are the concrete strategies, and your code only ever calls make() and check() on the interface. Which one runs is decided by config('hashing.driver').
