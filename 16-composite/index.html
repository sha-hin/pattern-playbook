Sections inside sections: score the whole tree

Composite

New ticket

The 2026-T2 survey has sections inside sections

From Mona Saleh, Head of Quality

Until now each answer was one score. From next term the survey has sections (Teaching, Classroom), Classroom contains a sub-section (Time management), and some parts count more than others: Teaching ×3, Classroom ×2. We need a score for every section and for the whole survey, and next year there may be a third level.

Why the quick fix is a trap

The first attempt loops over sections, then over their questions:

the quick fix (we won’t do this)
$total = 0;
foreach ($survey->sections as $section) {
    foreach ($section->questions as $question) {
        $total += $answers[$question->code] * $question->weight;
    }
    // ...and if $section contains another section? Another foreach.
    // And a third level next year? Another one.
}

The code hard-wires the depth of the tree. Every new level means another nested loop, and code that walks the tree (scoring, printing, counting) needs instanceof checks to know whether it is holding a question or a section.

A section and a question look different, but the report asks both the same thing: what is your score?

The pattern: Composite

Remember itItems and groups of items must be treated the same way, in a tree of any depth → give both one interface; a group answers by asking its children.

SurveyNode is the shared interface (the component). Question is a leaf: it answers score() from the answer sheet. Section is a composite: it holds any SurveyNodes, questions or sections, and answers score() by asking each child and taking the weighted average.

Nothing checks what kind of node it has. A section inside a section inside a section works automatically, because each level makes the same call.

Unanswered questions return null and are left out of the average instead of counting as zero, the same rule as the weighted scoring in chapter 3.

  1. 1One respondent’s answers

    Question code → Score (the flyweight from chapter 15). Building it validates every value.

    src/Survey/AnswerSheet.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey;

use Evalu8\Domain\Score;

/**
 * One respondent's answers to a survey: question code => score.
 */
final readonly class AnswerSheet
{
    /** @param array<string, Score> $scores */
    private function __construct(private array $scores)
    {
    }

    /** @param array<string, int> $answers e.g. ['q1' => 5, 'q2' => 4]; values are validated by Score */
    public static function fromArray(array $answers): self
    {
        $scores = [];
        foreach ($answers as $code => $value) {
            $scores[$code] = Score::of($value);
        }

        return new self($scores);
    }

    public function scoreFor(string $questionCode): ?Score
    {
        return $this->scores[$questionCode] ?? null;       // null = not answered
    }
}

  2. 2The component interface

    What a question and a section have in common.

    src/Survey/SurveyNode.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey;

/**
 * The Component: what a single question and a whole section have in common.
 * Code that works with the survey treats both the same way.
 */
interface SurveyNode
{
    public function title(): string;

    /** How much this node counts inside its parent section. */
    public function weight(): float;

    /** @return float|null null when nothing inside this node was answered */
    public function score(AnswerSheet $answers): ?float;

    /** @return list<SurveyNode> empty for a question */
    public function children(): array;
}

  3. 3The leaf: a question

    It answers from the answer sheet and has no children. It is readonly: once created, a question never changes.

    src/Survey/Question.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey;

use InvalidArgumentException;

/**
 * The Leaf: one question, answered with a 1–5 score. It has no children.
 */
final readonly class Question implements SurveyNode
{
    public function __construct(
        public string $code,                                // e.g. "q1"; how answers refer to it
        public string $text,
        private float $weight = 1.0,
    ) {
        if ($weight <= 0) {
            throw new InvalidArgumentException("Question {$code} must have a positive weight.");
        }
    }

    public function title(): string
    {
        return $this->text;
    }

    public function weight(): float
    {
        return $this->weight;
    }

    public function score(AnswerSheet $answers): ?float
    {
        $score = $answers->scoreFor($this->code);

        return $score === null ? null : (float) $score->value;   // a leaf simply answers
    }

    public function children(): array
    {
        return [];
    }
}

  4. 4The composite: a section

    add() accepts any SurveyNode. score() calls score() on each child, whatever it is, and returns the weighted average of the answered ones.

    src/Survey/Section.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey;

use InvalidArgumentException;

/**
 * The Composite: a section holds questions AND other sections, to any depth.
 * Its score is the weighted average of its children's scores; it never asks what a child is.
 */
final class Section implements SurveyNode
{
    /** @var list<SurveyNode> */
    private array $children = [];

    public function __construct(
        private readonly string $title,
        private readonly float $weight = 1.0,
    ) {
        if ($weight <= 0) {
            throw new InvalidArgumentException("Section \"{$title}\" must have a positive weight.");
        }
    }

    public function add(SurveyNode $child): self
    {
        $this->children[] = $child;

        return $this;
    }

    public function title(): string
    {
        return $this->title;
    }

    public function weight(): float
    {
        return $this->weight;
    }

    public function score(AnswerSheet $answers): ?float
    {
        $weightedTotal = 0.0;
        $usedWeight = 0.0;

        foreach ($this->children as $child) {
            $score = $child->score($answers);               // a question or a whole section: same call
            if ($score === null) {
                continue;                                   // unanswered parts don't drag the score down
            }

            $weightedTotal += $score * $child->weight();
            $usedWeight += $child->weight();
        }

        return $usedWeight > 0 ? $weightedTotal / $usedWeight : null;
    }

    public function children(): array
    {
        return $this->children;
    }
}

  5. 5The real survey

    Three levels deep. Time management sits inside Classroom.

    src/Survey/TeacherEvaluationSurvey.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey;

/**
 * The 2026-T2 teacher evaluation survey, as designed by the quality team.
 */
final class TeacherEvaluationSurvey
{
    public static function create(): Section
    {
        $timeManagement = (new Section('Time management'))
            ->add(new Question('q4', 'Starts lessons on time'))
            ->add(new Question('q5', 'Finishes the lesson plan'));

        $classroom = (new Section('Classroom', weight: 2))
            ->add(new Question('q3', 'Keeps the class focused'))
            ->add($timeManagement);                         // a section inside a section

        $teaching = (new Section('Teaching', weight: 3))
            ->add(new Question('q1', 'Explains clearly'))
            ->add(new Question('q2', 'Checks that we understood', weight: 2));

        return (new Section('Teacher evaluation 2026-T2'))
            ->add($teaching)
            ->add($classroom)
            ->add(new Question('q6', 'Overall, I would recommend this teacher'));
    }
}

  6. 6Score every node

    show() calls score() and recurses through children(). It never asks whether it holds a question or a section.

    bin/survey.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * Evalu8, chapter 16: score a survey tree of any depth.
 *
 *     composer dump-autoload
 *     php bin/survey.php
 */

require __DIR__ . '/../vendor/autoload.php';

use Evalu8\Survey\AnswerSheet;
use Evalu8\Survey\SurveyNode;
use Evalu8\Survey\TeacherEvaluationSurvey;

$survey = TeacherEvaluationSurvey::create();

// One student's answers. They skipped q5.
$answers = AnswerSheet::fromArray(['q1' => 5, 'q2' => 4, 'q3' => 3, 'q4' => 2, 'q6' => 4]);

function show(SurveyNode $node, AnswerSheet $answers, int $depth = 0): void
{
    $score = $node->score($answers);                        // the same call at every level
    echo str_repeat('    ', $depth)
        . str_pad($node->title(), 44 - 4 * $depth)
        . ($score === null ? 'not answered' : number_format($score, 2))
        . ($node->weight() !== 1.0 ? "   (weight {$node->weight()})" : '')
        . "\n";

    foreach ($node->children() as $child) {
        show($child, $answers, $depth + 1);
    }
}

show($survey, $answers);

How Laravel does it

Laravel’s query builder uses Composite for nested conditions: where(function ($q) { ... }) stores a whole group as one condition, and when SQL is generated, a group compiles its own conditions inside brackets, to any depth.

In your app, a self-referencing Eloquent relation stores the same tree in one table:

Laravel
// survey_nodes: id, parent_id, type ('section' | 'question'), title, code, weight
final class SurveyNode extends Model
{
    public function children(): HasMany
    {
        return $this->hasMany(self::class, 'parent_id');
    }
}

// Nested where groups: a group of conditions treated as one condition.
Response::where('term', '2026-T1')
    ->where(fn ($q) => $q->where('score', '<=', 2)->orWhere(fn ($q) => $q->whereNull('score')->where('role', 'peer')))
    ->get();

Check yourself

Answer in your head, then open the answer.

A fourth level of sections is added. What changes in the scoring code?

Nothing. Each section asks its children; depth doesn’t matter.

Why does an unanswered question return null and not 0?

A skipped question is not a score of zero. Returning null lets the section leave it out of the average.

Which class is the leaf and which is the composite?

Question is the leaf (no children). Section is the composite (holds other nodes).
