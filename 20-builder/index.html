New ticket

Surveys are hard to read, and the report must come in two formats

From Mona Saleh, Head of Quality, and the Ministry inspector

Our survey designers can’t read the nested code that defines a survey, and mistakes (a duplicate code) are found only when students answer. Separately: principals want the term report as a web page, the inspector wants it as plain text in an email, and the first two versions we got didn’t even sort the schools the same way.

Why the quick fix is a trap

Two report functions, each with its own copy of the structure:

the quick fix (we won’t do this)
function htmlReport(array $results): string
{
    // group by school, sort schools, write <h2> and <tr>...
}

function textReport(array $results): string
{
    // group by school (but forgot to sort), write lines...
}

The structure of the report (title, then each school with its teachers, then a note) is copied into each format, and the copies already disagree. Survey definitions have a similar problem: the order of construction is buried in nested calls, and nothing checks the whole survey when it is created.

Both problems are about building something complex step by step. The Builder pattern has two forms, and this chapter uses both.

The pattern: Builder

Remember itA complex object is assembled step by step → let a builder collect the steps and produce the result at the end; to get different products from the same steps, give each product its own builder.

The modern, fluent form (what most PHP code calls a builder): SurveyBuilder collects sections and questions in reading order, with end() closing a section. Nothing is final until build(), which checks the whole survey (unclosed sections, plus the validator from chapter 17) and either returns it or throws with every problem listed. Laravel’s query builder works this way.

The book’s form: a ReportBuilder interface defines the steps of a report document. HtmlReportBuilder and PlainTextReportBuilder implement those steps to produce two different products. The director, TermReportWriter, knows the order of the steps (title, schools sorted, teachers, footnote) and drives any builder. Grouping and sorting are written once.

  2. 2The fluent survey builder

    It keeps a stack of open sections: section() pushes one, end() pops it, question() adds to the innermost. Rules are given as text and parsed with the interpreter from chapter 18, so a typo fails at build time.

    build() collects every problem before throwing, so the designer fixes them all in one go.

    src/Survey/SurveyBuilder.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey;

use Evalu8\Survey\Rules\RuleParser;
use Evalu8\Survey\Visitor\SurveyValidator;
use LogicException;

/**
 * Builder: assembles a survey step by step, in the order you read it, and checks the
 * whole result in build(). You get a valid survey, or an exception listing every problem.
 *
 *     SurveyBuilder::survey('Teacher evaluation')
 *         ->section('Teaching', weight: 3)
 *             ->question('q1', 'Explains clearly')
 *         ->end()
 *         ->build();
 */
final class SurveyBuilder
{
    /** @var list<Section> the root and every section still open, innermost last */
    private array $open;

    private function __construct(string $title, private readonly RuleParser $rules)
    {
        $this->open = [new Section($title)];
    }

    public static function survey(string $title): self
    {
        return new self($title, new RuleParser());
    }

    /** Opens a section inside the current one. Close it with end(). */
    public function section(string $title, float $weight = 1.0): self
    {
        $section = new Section($title, $weight);
        $this->current()->add($section);
        $this->open[] = $section;

        return $this;
    }

    /** Adds a question to the current section. $visibleIf uses the rule language from chapter 18. */
    public function question(string $code, string $text, float $weight = 1.0, ?string $visibleIf = null): self
    {
        $this->current()->add(new Question(
            $code,
            $text,
            $weight,
            $visibleIf === null ? null : $this->rules->parse($visibleIf),
        ));

        return $this;
    }

    /** Closes the current section. */
    public function end(): self
    {
        if (count($this->open) === 1) {
            throw new LogicException('end() called with no open section.');
        }
        array_pop($this->open);

        return $this;
    }

    /** The last step: checks everything, then hands over the finished survey. */
    public function build(): Section
    {
        $problems = [];
        if (count($this->open) > 1) {
            $problems[] = 'Section "' . $this->current()->title() . '" was never closed with end().';
        }

        $validator = new SurveyValidator();                 // the visitor from chapter 17
        $this->open[0]->accept($validator);
        $problems = [...$problems, ...$validator->errors];

        if (count($problems) > 0) {
            throw new InvalidSurvey($problems);
        }

        return $this->open[0];
    }

    private function current(): Section
    {
        return $this->open[count($this->open) - 1];
    }
}

namespace Evalu8\Reporting\Document;

use Evalu8\Reporting\TeacherResult;

/**
 * Builder (the book's form): the steps every term report document is made of.
 * Each concrete builder turns the same steps into a different kind of document.
 */
interface ReportBuilder
{
    public function title(string $title): void;

    public function schoolHeading(string $school): void;

    public function teacherRow(TeacherResult $result): void;

    public function footnote(string $text): void;
}

  5. 5Builder 1: HTML

    Every value goes through htmlspecialchars(). Each builder has its own result method (html(), text()), because the products don’t share a type.

    src/Reporting/Document/HtmlReportBuilder.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting\Document;

use Evalu8\Reporting\TeacherResult;

/**
 * Builds the report as an HTML page, for the principal's dashboard.
 */
final class HtmlReportBuilder implements ReportBuilder
{
    private string $html = '';
    private bool $tableOpen = false;

    public function title(string $title): void
    {
        $this->html .= '<h1>' . $this->e($title) . "</h1>\n";
    }

    public function schoolHeading(string $school): void
    {
        $this->closeTable();
        $this->html .= '<h2>' . $this->e($school) . "</h2>\n<table>\n<tr><th>Teacher</th><th>Method</th><th>Score</th></tr>\n";
        $this->tableOpen = true;
    }

    public function teacherRow(TeacherResult $result): void
    {
        $this->html .= '<tr><td>' . $this->e($result->teacher->name) . '</td><td>' . $this->e($result->method)
            . '</td><td>' . $this->e($result->formattedScore()) . "</td></tr>\n";
    }

    public function footnote(string $text): void
    {
        $this->closeTable();
        $this->html .= '<p><small>' . $this->e($text) . "</small></p>\n";
    }

    /** The finished product. Each builder has its own result method, because products differ. */
    public function html(): string
    {
        $this->closeTable();

        return $this->html;
    }

    private function closeTable(): void
    {
        if ($this->tableOpen) {
            $this->html .= "</table>\n";
            $this->tableOpen = false;
        }
    }

    private function e(string $text): string
    {
        return htmlspecialchars($text, ENT_QUOTES | ENT_HTML5, 'UTF-8');
    }
}

  6. 6Builder 2: plain text

    src/Reporting/Document/PlainTextReportBuilder.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting\Document;

use Evalu8\Reporting\TeacherResult;

/**
 * Builds the report as plain text, for the email to the Ministry inspector.
 */
final class PlainTextReportBuilder implements ReportBuilder
{
    /** @var list<string> */
    private array $lines = [];

    public function title(string $title): void
    {
        $this->lines[] = mb_strtoupper($title);
        $this->lines[] = str_repeat('=', mb_strlen($title));
    }

    public function schoolHeading(string $school): void
    {
        $this->lines[] = '';
        $this->lines[] = $school;
    }

    public function teacherRow(TeacherResult $result): void
    {
        $this->lines[] = '  ' . str_pad($result->teacher->name, 16) . str_pad($result->method, 10) . $result->formattedScore();
    }

    public function footnote(string $text): void
    {
        $this->lines[] = '';
        $this->lines[] = "* {$text}";
    }

    public function text(): string
    {
        return implode("\n", $this->lines) . "\n";
    }
}

  7. 7The director

    Grouping and sorting by school are written here, once.

    src/Reporting/Document/TermReportWriter.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Reporting\Document;

use Evalu8\Reporting\TeacherResult;

/**
 * The Director: knows the ORDER of the steps (title, then each school with its teachers,
 * then the footnote), but not what document is being made. Any ReportBuilder works.
 */
final readonly class TermReportWriter
{
    /** @param list<TeacherResult> $results */
    public function write(ReportBuilder $builder, string $term, array $results): void
    {
        $builder->title("Teacher evaluation results {$term}");

        $bySchool = [];
        foreach ($results as $result) {
            $bySchool[$result->teacher->school][] = $result;
        }
        ksort($bySchool);

        foreach ($bySchool as $school => $schoolResults) {
            $builder->schoolHeading($school);
            foreach ($schoolResults as $result) {
                $builder->teacherRow($result);
            }
        }

        $builder->footnote('Each school chooses its own scoring method; scores are on the 1–5 scale.');
    }
}

const CURRENT_TERM = '2026-T1';

/** @var Container $app */

// ── Part 1: the fluent builder ──

        ->section('Teaching')
            ->question('q1', 'Explains clearly')

$html = new HtmlReportBuilder();
$writer->write($html, CURRENT_TERM, $results);
echo $html->html();

How Laravel does it

The query builder is the fluent form: where(), orderBy() and limit() collect parts, and nothing touches the database until get(). The HTTP client is another: Http::withToken()->timeout(10)->retry(3)->post().

The book’s form appears in Laravel’s mail: MailMessage is built with steps (subject(), line(), action()), and the same message is rendered to HTML and to plain text by different renderers.

Laravel
// Fluent builders you already use every day:
$teachers = Teacher::query()
    ->where('school', 'Smouha')
    ->whereHas('responses', fn ($q) => $q->where('term', '2026-T1'))
    ->orderBy('name')
    ->get();                    // the only step that runs SQL

return (new MailMessage)
    ->subject('Your 2026-T1 evaluation result')
    ->line('Your weighted score is 4.13.')
    ->action('Open your dashboard', url('/dashboard'));   // rendered as HTML and as text

Check yourself

Answer in your head, then open the answer.

Why does SurveyBuilder::build() validate, instead of each question() call?

Some problems only exist in the whole survey: a duplicate code, an empty or unclosed section. build() is the first moment the whole survey exists.

In the book’s form, which class knows the order of the steps?

The director (TermReportWriter). The builders only know how to write each step in their format.

The inspector now wants a CSV version of the report. What do you add?

One class, CsvReportBuilder implements ReportBuilder. The director and the other builders don’t change.
