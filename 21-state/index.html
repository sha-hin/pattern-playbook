Survey lifecycle: draft, open, closed, archived

State

New ticket

A school reopened an archived survey, and answers arrived in a draft

From Support desk

Survey runs have a lifecycle: draft (being designed), open (collecting answers), closed (no more answers, can be reopened for a week if a school closed it too early) and archived (read-only forever). Last week an archived survey was reopened, and a draft received answers through an old link.

Why the quick fix is a trap

Every action checks the status itself:

the quick fix (we won’t do this)
public function reopen(DateTimeImmutable $at): void
{
    if ($this->status === 'draft')    { throw new LogicException('Open it first.'); }
    if ($this->status === 'open')     { throw new LogicException('Already open.'); }
    if ($this->status === 'archived') { /* forgotten: archived surveys were reopened */ }
    if ($this->status === 'closed' && $this->closedAt->diff($at)->days > 7) { throw ... }
    $this->status = 'open';
}
// ...and the same ladder in open(), submitAnswer(), close(), archive()

Four statuses × five actions = twenty decisions, spread across five methods. Each method must remember every status, and the bug came from the one combination nobody wrote. Adding a status ("paused") means editing every method.

Look at it the other way: each status knows exactly which actions it allows. If each status were a class, the rules for "closed" would all be in one place.

The pattern: State

Remember itAn object behaves differently depending on its status, and every method checks the status → make each status a class that allows only its own actions; the object delegates to its current status.

RunStatus is the base state: every action throws by default. Draft, Open, Closed and Archived override only the actions they allow, and an allowed action returns the next status. Archived overrides nothing, so everything is refused, which is exactly the bug fix.

SurveyRun is the context: each method asks the current status and switches to whatever it returns, through one private method. Nothing outside can set the status directly, so the rules can’t be skipped.

Data that belongs to one status lives in that status: only Closed knows when it was closed, so the seven-day reopen rule sits next to the date it needs.

  2. 2The base state: everything is refused

    Each action returns the next status. The defaults all throw, so a status only has to write the actions it allows.

    src/Lifecycle/RunStatus.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Lifecycle;

use DateTimeImmutable;

/**
 * The State: what a survey run may do in its current status.
 * Every action is refused here; each concrete status allows only its own moves,
 * and an allowed move returns the NEXT status.
 */
abstract class RunStatus
{
    abstract public function name(): string;

    public function open(): RunStatus
    {
        throw $this->refuse('open');
    }

    public function acceptAnswer(): void
    {
        throw new TransitionNotAllowed("This survey is {$this->name()}; it doesn't accept answers.");
    }

    public function close(DateTimeImmutable $at): RunStatus
    {
        throw $this->refuse('close');
    }

    public function reopen(DateTimeImmutable $at): RunStatus
    {
        throw $this->refuse('reopen');
    }

    public function archive(): RunStatus
    {
        throw $this->refuse('archive');
    }

    protected function refuse(string $action): TransitionNotAllowed
    {
        return new TransitionNotAllowed("Can't {$action} a survey that is {$this->name()}.");
    }
}

  5. 5Closed: reopen within a week, or archive

    The closing date is stored in this status, because only this status needs it.

    src/Lifecycle/Closed.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Lifecycle;

use DateTimeImmutable;

/**
 * No more answers. It can be reopened for a week (a school closed it too early),
 * then only archived.
 */
final class Closed extends RunStatus
{
    public const REOPEN_WITHIN_DAYS = 7;

    public function __construct(public readonly DateTimeImmutable $closedAt)
    {
    }

    public function name(): string
    {
        return 'closed';
    }

    public function reopen(DateTimeImmutable $at): RunStatus
    {
        $days = $this->closedAt->diff($at)->days;
        if ($days > self::REOPEN_WITHIN_DAYS) {
            throw new TransitionNotAllowed(
                "Can't reopen: it was closed {$days} days ago, and the limit is " . self::REOPEN_WITHIN_DAYS . ' days.'
            );
        }

        return new Open();
    }

    public function archive(): RunStatus
    {
        return new Archived();
    }
}

  7. 7The context: SurveyRun

    No if about statuses. switchTo() is private, so only an allowed move can change the status. Dates are passed in, so the rules are easy to check with any date.

    src/Lifecycle/SurveyRun.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Lifecycle;

use DateTimeImmutable;

/**
 * The Context: one survey being run in one term. It has no if/else about its status:
 * it asks the current status, and only it can switch to the next one.
 */
final class SurveyRun
{
    private RunStatus $status;
    private int $answers = 0;

    /** @var list<string> */
    private array $history = [];

    public function __construct(public readonly string $title)
    {
        $this->status = new Draft();
    }

    public function open(): void
    {
        $this->switchTo($this->status->open());
    }

    public function submitAnswer(): void
    {
        $this->status->acceptAnswer();                      // throws unless the run is open
        $this->answers++;
    }

    public function close(DateTimeImmutable $at): void
    {
        $this->switchTo($this->status->close($at));
    }

    public function reopen(DateTimeImmutable $at): void
    {
        $this->switchTo($this->status->reopen($at));
    }

    public function archive(): void
    {
        $this->switchTo($this->status->archive());
    }

    public function status(): string
    {
        return $this->status->name();
    }

    public function answers(): int
    {
        return $this->answers;
    }

    /** @return list<string> */
    public function history(): array
    {
        return $this->history;
    }

    private function switchTo(RunStatus $next): void
    {
        $this->history[] = "{$this->status->name()} → {$next->name()}";
        $this->status = $next;
    }
}

  8. 8A survey’s life, step by step

    bin/lifecycle.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * Evalu8, chapter 21: a survey run moves through its statuses, and each status decides what is allowed.
 *
 *     composer dump-autoload
 *     php bin/lifecycle.php
 */

require __DIR__ . '/../vendor/autoload.php';

use Evalu8\Lifecycle\SurveyRun;
use Evalu8\Lifecycle\TransitionNotAllowed;

$run = new SurveyRun('Teacher evaluation 2026-T2, Smouha');
$day = fn (int $n): DateTimeImmutable => new DateTimeImmutable("2026-06-01 +{$n} days");

/** @param callable(): void $action */
function attempt(string $label, callable $action, SurveyRun $run): void
{
    try {
        $action();
        echo str_pad($label, 34) . "ok, now {$run->status()}\n";
    } catch (TransitionNotAllowed $e) {
        echo str_pad($label, 34) . "refused: {$e->getMessage()}\n";
    }
}

attempt('Student answers the draft', fn () => $run->submitAnswer(), $run);
attempt('Principal opens it', fn () => $run->open(), $run);
attempt('Student answers', fn () => $run->submitAnswer(), $run);
attempt('Student answers', fn () => $run->submitAnswer(), $run);
attempt('Closed on day 10', fn () => $run->close($day(10)), $run);
attempt('Late student answers', fn () => $run->submitAnswer(), $run);
attempt('Reopened on day 12', fn () => $run->reopen($day(12)), $run);
attempt('Late student answers', fn () => $run->submitAnswer(), $run);
attempt('Closed again on day 14', fn () => $run->close($day(14)), $run);
attempt('Reopen attempt on day 30', fn () => $run->reopen($day(30)), $run);
attempt('Archived', fn () => $run->archive(), $run);
attempt('Reopen the archive', fn () => $run->reopen($day(31)), $run);

echo "\n{$run->answers()} answers accepted\n";
echo 'History: ' . implode(', ', $run->history()) . "\n";

How Laravel does it

Laravel’s core has no State class: a status is usually a string or enum column. When each status needs its own behaviour, the spatie/laravel-model-states package adds exactly this structure: each state is a class, the column stores which one, and only the transitions you register are allowed.

Laravel
// With spatie/laravel-model-states
abstract class RunStatus extends State
{
    public static function config(): StateConfig
    {
        return parent::config()
            ->default(Draft::class)
            ->allowTransition(Draft::class, Open::class)
            ->allowTransition(Open::class, Closed::class)
            ->allowTransition(Closed::class, Open::class, ReopenWithinAWeek::class)
            ->allowTransition(Closed::class, Archived::class);
    }
}

$run->status->transitionTo(Archived::class);   // throws for a transition that isn't allowed

Check yourself

Answer in your head, then open the answer.

A new status "paused" (no answers, can resume) is added. What changes?

One new class, Paused, and the transitions that lead to it (for example Open::pause()). The other statuses don’t change.

Why does each action return the next status instead of setting it?

So only the context can change its status, through its private switchTo(). No code can jump to "archived" without going through the rules.

Why does Closed store $closedAt, and not SurveyRun?

Only the closed status needs it (for the seven-day rule). Data that belongs to one status lives in that status.
