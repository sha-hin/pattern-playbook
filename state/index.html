State

BehaviourGoF book

A traffic light: what you may do depends on the colour, and the light changes itself.

The rule to rememberWhat an object is allowed to do depends on its status → one class per status; each knows its allowed moves.

Without it: the pain

submit(), approve(), reject(), publish() each start with the same if ($status === …) ladder.

With it: the fix

Draft, Submitted, Approved are classes. The report asks its current state; no ifs anywhere.

Reach for it when you see

  • if ($this->status === …) repeated in many methods
  • Bugs like "approved a draft" or "edited a published report"
  • A status flow diagram exists on a whiteboard

Real job where it fits

A report goes Draft → Submitted → Approved, or back to Draft when rejected with a reason.

Before: the code that hurts

public function approve(): void
{
    if ($this->status === 'draft')     { throw new LogicException('Submit it first.'); }
    if ($this->status === 'approved')  { throw new LogicException('Already approved.'); }
    if ($this->status === 'submitted') { $this->status = 'approved'; }
    // ...and the same ladder in submit(), reject(), publish()
}

Build it yourself: the full State pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

ContextReport holds its current state; ONLY the report can change it
StateReportState base class: every action is refused unless a child allows it
Concrete statesDraft, Submitted, Approved each allows only its own moves

Each action on a state returns the NEXT state, and the report switches to it.

Nothing outside the report can jump to a state directly, so the rules can't be skipped.

<?php

declare(strict_types=1);

final class TransitionNotAllowed extends LogicException
{
}

// ── Step 1: the State base class. Everything is refused by default. ──
abstract class ReportState  // State
{
    abstract public function name(): string;

    public function submit(): ReportState
    {
        throw $this->refuse('submit');
    }

    public function approve(): ReportState
    {
        throw $this->refuse('approve');
    }

    public function reject(): ReportState
    {
        throw $this->refuse('reject');
    }

    private function refuse(string $action): TransitionNotAllowed
    {
        return new TransitionNotAllowed("Cannot {$action} a report that is {$this->name()}.");
    }
}

// ── Step 2: concrete states. Each one allows only its own moves. ──
final class Draft extends ReportState  // Concrete state
{
    public function name(): string
    {
        return 'draft';
    }

    public function submit(): ReportState                   // a draft CAN be submitted
    {
        return new Submitted();  // the state decides what comes next
    }
}

final class Submitted extends ReportState  // Concrete state
{
    public function name(): string
    {
        return 'submitted';
    }

    public function approve(): ReportState
    {
        return new Approved();
    }

    public function reject(): ReportState
    {
        return new Draft();                                 // rejected reports go back to draft
    }
}

final class Approved extends ReportState  // Concrete state: allows nothing more
{
    public function name(): string
    {
        return 'approved';
    }
}

// ── Step 3: the Context. No if statements, and no public way to set the state. ──
final class Report  // Context
{
    private ReportState $state;
    private ?string $rejectionReason = null;

    /** @var list<string> */
    private array $history = [];

    public function __construct()
    {
        $this->state = new Draft();                         // every report starts as a draft
    }

    public function submit(): void
    {
        $this->switchTo($this->state->submit());  // ask the current state for the next one
    }

    public function approve(): void
    {
        $this->switchTo($this->state->approve());
    }

    public function reject(string $reason): void
    {
        $this->switchTo($this->state->reject());
        $this->rejectionReason = $reason;                   // only saved if the move was allowed
    }

    public function status(): string
    {
        return $this->state->name();
    }

    public function rejectionReason(): ?string
    {
        return $this->rejectionReason;
    }

    /** @return list<string> */
    public function history(): array
    {
        return $this->history;
    }

    private function switchTo(ReportState $next): void  // private: the only place the state changes
    {
        $this->history[] = $this->state->name() . ' -> ' . $next->name();
        $this->state = $next;
    }
}

// ── Using it ──
$report = new Report();
$report->submit();
$report->reject('Missing the science scores.');
$report->submit();
$report->approve();

echo implode("\n", $report->history()) . "\n";
echo "Status: {$report->status()}\n";

try {
    $report->submit();                                      // approved reports are locked
} catch (TransitionNotAllowed $e) {
    echo 'Refused: ' . $e->getMessage() . "\n";
}

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

abstract class ReportState                          // default: everything forbidden
{
    abstract public function name(): string;

    public function submit(): ReportState  { throw $this->deny('submit'); }
    public function approve(): ReportState { throw $this->deny('approve'); }
    public function reject(): ReportState  { throw $this->deny('reject'); }

    private function deny(string $action): IllegalTransition
    {
        return new IllegalTransition("Cannot {$action} a {$this->name()} report.");
    }
}

final class Draft extends ReportState
{
    public function name(): string { return 'draft'; }
    public function submit(): ReportState { return new Submitted(); }  // allowed here: returns the next state
}

final class Submitted extends ReportState
{
    public function name(): string { return 'submitted'; }
    public function approve(): ReportState { return new Approved(); }
    public function reject(): ReportState { return new Draft(); }
}

final class Approved extends ReportState
{
    public function name(): string { return 'approved'; }
}

final class Report
{
    private ?string $rejectionReason = null;

    public function __construct(private ReportState $state = new Draft()) {}

    public function submit(): void  { $this->state = $this->state->submit(); }  // no if anywhere
    public function approve(): void { $this->state = $this->state->approve(); }

    public function reject(string $why): void
    {
        $this->state = $this->state->reject();
        $this->rejectionReason = $why;                  // only saved if the move was allowed
    }
}

How Laravel builds it inside: Laravel's core has no State class: a status is usually a string or enum column. When each status also needs its own behaviour, the spatie/laravel-model-states package adds exactly this structure: it saves the state class in the column, gives each state its own class, and only allows the transitions you register.
