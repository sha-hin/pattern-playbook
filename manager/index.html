Manager / Driver

CreationNot in the book

Phone settings: pick Wi-Fi calling once, and every call uses it.

The rule to rememberOne service with interchangeable backends chosen by config → a manager builds the configured driver once and reuses it.

Without it: the pain

if (app()->isLocal()) new Ollama… else new Anthropic… is copied in every place that needs AI.

With it: the fix

config('ai.default') names the driver. The manager builds it once. Code just asks for driver().

Reach for it when you see

  • if ($env === …) new X else new Y in several places
  • A service with a "provider" setting in .env
  • Different backends in local, staging and production

Real job where it fits

Local development uses a local LLM (Ollama). Production uses a hosted API. Same code everywhere.

Before: the code that hurts

// in 6 different services:
$ai = app()->isLocal()
    ? new OllamaClient('http://localhost:11434')
    : new AnthropicClient(config('services.anthropic.key'));

After: how you implement the Manager / Driver pattern in PHP

final class AiManager extends \Illuminate\Support\Manager   // Laravel's own base class
{
    public function getDefaultDriver(): string
    {
        return $this->config->get('ai.default');  // .env: AI_DRIVER=ollama
    }

    protected function createOllamaDriver(): AiClient  // one method per driver
    {
        return new OllamaClient($this->config->get('ai.ollama.url'));
    }

    protected function createAnthropicDriver(): AiClient
    {
        return new AnthropicClient($this->config->get('ai.anthropic.key'));
    }
}

// AppServiceProvider
$this->app->singleton(AiManager::class, fn ($app) => new AiManager($app));

// Anywhere:
$summary = app(AiManager::class)->driver()->summarize($text);  // config decides, built once
$check   = app(AiManager::class)->driver('anthropic')->summarize($text);   // or by name
