Foundation: everything the course stands on

Every table, model, factory and test helper, ready before lesson 1

This course teaches design patterns inside the business logic of a vacation-rental PMS (property management system): the software hosts use to run their rentals. Hosts list properties, guests book stays directly or through Airbnb and Booking.com, payments go through Stripe, guests get automatic messages, and cleaners get a task between every two stays.

This page holds everything the lessons stand on: the setup, every table, enum, model, factory and test helper. Nothing in it is created later. Lessons only add the pattern code, and link back here when they use a column or a factory state, with a line on why the decision was made.

Three rules apply everywhere: money is an integer in the smallest unit with its currency next to it; dates are dates (check_in is a DATE), read in the property’s timezone, and instants are stored in UTC; and every rule the database can enforce is enforced there too (unique indexes, foreign keys).

Redis: one connection per job

Four logical databases on the same server. The queue never shares a connection with the cache, so flushing the cache can’t delete jobs, and each one can later move to its own server.

config/database.php (redis section)
<?php

return [
    'redis' => [
        'client' => env('REDIS_CLIENT', 'phpredis'),

        'default' => ['host' => env('REDIS_HOST'), 'port' => 6379, 'database' => 0],
        'cache' => ['host' => env('REDIS_HOST'), 'port' => 6379, 'database' => 1],
        'queue' => ['host' => env('REDIS_HOST'), 'port' => 6379, 'database' => 2],
        'locks' => ['host' => env('REDIS_HOST'), 'port' => 6379, 'database' => 3],
        'sessions' => ['host' => env('REDIS_HOST'), 'port' => 6379, 'database' => 4],
    ],
];

// config/cache.php    'redis' => ['driver' => 'redis', 'connection' => 'cache', 'lock_connection' => 'locks']
// config/queue.php    'redis' => ['driver' => 'redis', 'connection' => 'queue', 'queue' => 'default',
//                                 'retry_after' => 120, 'block_for' => 5, 'after_commit' => true]
// config/session.php  'connection' => 'sessions'

after_commit => true: a job dispatched inside a transaction is only pushed once the transaction commits, so a worker never picks up a job for a booking that was rolled back. retry_after must be longer than the slowest job, or Redis hands the job to a second worker while the first is still running.

Migrations: every table of the course

Laravel’s default tables stay as they are: users, password_reset_tokens, sessions, cache, jobs, job_batches, failed_jobs, plus personal_access_tokens (Sanctum) and notifications (database notifications). Below are the PMS tables.

Three rules apply everywhere. Money is an unsigned integer in the currency’s minor unit, with a currency column next to it. Calendar dates (check_in, date) are DATE columns; moments (send_at, due_at) are UTC datetimes, converted from the property timezone. Every rule the database can enforce, it enforces: unique indexes and foreign keys are the last line of defence behind the code.

Accounts, memberships, invitations

One account owns the properties; users work in it through a membership that carries their role. A user can belong to several accounts and has one current account.

        });
    }
};

Properties, calendar days, rate rules, checklists

calendar_days stores only the days that differ from the property’s defaults (blocked, a custom price, a longer minimum stay), so a year of an untouched property is zero rows.

rate_rules is a tree: a rule can be a group (a season) holding other rules through parent_id. Basis points (_bps, 1/100 of a percent) keep percentages as integers: 2500 bps = 25%.

<?php

use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

            $table->string('name');
            $table->date('starts_on')->nullable();                    // groups: the season
            $table->date('ends_on')->nullable();
            $table->json('settings');                                 // e.g. {"price_cents": 18000} or {"nights": 7, "discount_bps": 1000}
            $table->unsignedSmallInteger('position')->default(0);

Bookings, line items, payments

A stay is [check_in, check_out): the guest leaves on the check-out day, so the next guest can arrive the same day. The composite index serves the overlap query every booking runs. Channel bookings keep the channel’s id and version, so the same reservation is never imported twice and an older update can be recognised and ignored. The cancellation policy is copied onto the booking: changing the property’s policy later must not change what this guest agreed to.

booking_line_items is the folio: every amount the guest pays or gets back, line by line (nights, cleaning fee, discount, tax, refund).

database/migrations/2026_01_01_000003_create_booking_tables.php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('bookings', function (Blueprint $table) {
            $table->id();
            $table->foreignId('property_id')->constrained();
            $table->string('guest_name');
            $table->string('guest_email');
            $table->string('guest_phone')->nullable();
            $table->string('guest_channel')->default('mail');           // how the guest wants messages: mail, sms, whatsapp
            $table->string('guest_locale', 5)->default('en');
            $table->date('check_in');
            $table->date('check_out');                                 // exclusive: the guest leaves that day
            $table->unsignedTinyInteger('guests');
            $table->string('status');                                  // pending, confirmed, cancelled, expired
            $table->unsignedInteger('total_cents');
            $table->char('currency', 3);
            $table->string('cancellation_policy');                     // copied from the property at booking time
            $table->text('door_code')->nullable();                     // encrypted by the model; shown only close to check-in
            $table->string('source')->default('direct');               // direct, airbnb, booking_com, vrbo
            $table->string('external_id')->nullable();                 // the channel's reservation id
            $table->unsignedBigInteger('external_version')->nullable();
            $table->timestamp('expires_at')->nullable();               // unpaid holds expire
            $table->timestamp('confirmed_at')->nullable();
            $table->timestamp('cancelled_at')->nullable();
            $table->timestamps();
            $table->index(['property_id', 'status', 'check_in', 'check_out']);
            $table->unique(['source', 'external_id']);                 // NULLs never collide, so direct bookings are fine
            $table->index(['status', 'expires_at']);                   // the "expire unpaid holds" job
        });

        Schema::create('booking_line_items', function (Blueprint $table) {
            $table->id();
            $table->foreignId('booking_id')->constrained()->cascadeOnDelete();
            $table->string('type');                                    // night, cleaning_fee, discount, tax, refund
            $table->string('description');
            $table->date('night')->nullable();                         // for "night" lines
            $table->integer('amount_cents');                           // signed: discounts and refunds are negative
            $table->char('currency', 3);
            $table->timestamps();
        });

        Schema::create('payments', function (Blueprint $table) {
            $table->id();
            $table->foreignId('booking_id')->constrained();
            $table->string('kind');                                    // deposit, balance, refund
            $table->unsignedInteger('amount_cents');
            $table->char('currency', 3);
            $table->string('status');                                  // pending, succeeded, failed, cancelled
            $table->string('provider_payment_id')->nullable()->unique();   // Stripe PaymentIntent or Refund id
            $table->timestamp('due_at')->nullable();                   // when the balance is charged
            $table->string('failure_reason')->nullable();
            $table->timestamps();
            $table->index(['status', 'due_at']);
        });
    }

Channels, webhooks, reconciliation

A channel connection holds the account’s OAuth tokens for one channel (encrypted by the model). A listing maps one property to its id on one channel. Every incoming webhook is stored before it is processed (the inbox), and unique(provider, event_id) turns a duplicate delivery into a no-op. The nightly reconciliation writes what it finds into reconciliation_issues.

Cleaning tasks, outbox, idempotency keys

A cleaning task gets its own copy of the property’s checklist, so editing the template later doesn’t change tasks already planned. outbox_messages holds events for other systems until a relay publishes them; idempotency_keys stores the response of each POST so a retried request returns the same result instead of acting twice.

        Schema::create('outbox_messages', function (Blueprint $table) {
            $table->id();
            $table->uuid('message_id')->unique();                      // consumers deduplicate on it
            $table->string('type');                                    // e.g. booking.confirmed.v1
            $table->json('payload');
            $table->unsignedTinyInteger('attempts')->default(0);
            $table->text('last_error')->nullable();
            $table->timestamp('published_at')->nullable();
            $table->timestamps();
            $table->index(['published_at', 'id']);                     // the relay reads unpublished rows in order
        });

        Schema::create('idempotency_keys', function (Blueprint $table) {
            $table->id();
            $table->foreignId('user_id')->constrained()->cascadeOnDelete();
            $table->string('key');
            $table->char('request_hash', 64);                          // the same key with a different body is an error
            $table->unsignedSmallInteger('response_status')->nullable();   // null while the first request is running
            $table->json('response_body')->nullable();
            $table->timestamps();
            $table->unique(['user_id', 'key']);
        });
    }
};

Models

Models hold data, relations, casts and query scopes. Business rules don’t live here; they live in the classes the lessons build. For models a request can fill (properties, bookings, templates), $fillable lists only what a user may set: ownership columns (account_id, property_id) and statuses are set by code. Models that only our own code writes (payments, scheduled messages, outbox rows) list their columns, because no request ever reaches them.

Model::shouldBeStrict() (in the provider) turns a non-fillable key into an exception instead of a silently dropped value, so a mistake here shows up in the first test.

Factories

One factory per model. States read like the sentence a test needs: Booking::factory()->pending()->forStay('2027-07-01', 3). Defaults are valid on their own, so X::factory()->create() always works. Factories are unguarded, so they can set statuses and ownership columns that $fillable keeps away from requests.

Dates that matter to a rule (check-in, send_at, due_at) are always given by the test; random dates only appear where the value is irrelevant.

Pest configuration

The clock is frozen at 1 June 2027, 10:00 UTC before every test, so factory defaults ("four weeks from now") and rules like after_or_equal:today give the same answer on every run. A test that needs another moment (a DST night, an expired hold) calls $this->travelTo() itself.

Http::preventStrayRequests() makes any HTTP call without a matching Http::fake() throw, so a test can never reach Stripe or Airbnb by accident.

The states mean what the lessons assume

tests/Feature/BookingFactoryTest.php
<?php

use App\Enums\BookingStatus;
use App\Models\Booking;
use App\Models\CleaningTask;

it('creates a stay of the requested number of nights', function () {
    $booking = Booking::factory()->forStay('2027-07-01', 3)->create();

    expect($booking->check_in->toDateString())->toBe('2027-07-01')
        ->and($booking->check_out->toDateString())->toBe('2027-07-04');
});

it('creates pending bookings as holds that expire', function () {
    $booking = Booking::factory()->pending()->create();

    expect($booking->status)->toBe(BookingStatus::Pending)
        ->and($booking->confirmed_at)->toBeNull()
        ->and($booking->expires_at->isFuture())->toBeTrue();
});

it('treats only pending and confirmed bookings as occupying the calendar', function (BookingStatus $status, bool $blocks) {
    expect(in_array($status, BookingStatus::blocking(), true))->toBe($blocks);
})->with([
    [BookingStatus::Pending, true],
    [BookingStatus::Confirmed, true],
    [BookingStatus::Cancelled, false],
    [BookingStatus::Expired, false],
]);

it('stores the door code encrypted', function () {
    $booking = Booking::factory()->withDoorCode('4711')->create();

    expect($booking->getRawOriginal('door_code'))->not->toContain('4711')
        ->and($booking->fresh()->door_code)->toBe('4711');
});

it('puts a cleaning task on the property of its booking', function () {
    $task = CleaningTask::factory()->create();

    expect($task->property_id)->toBe($task->booking->property_id);
});
