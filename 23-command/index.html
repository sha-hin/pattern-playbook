The 40-second AI analysis times out the request

CommandCommand Bus

New ticket

"Close survey" spins for a minute, then shows an error

From Mona Saleh, Head of Quality

When I close a survey, the page loads for about a minute and then says "504 Gateway Timeout". The survey is closed, but the comment summaries are missing for half the teachers. Support also needs a way to re-run the analysis for one teacher.

Why the quick fix is a trap

The listener runs the analysis directly, inside the web request:

the quick fix (we won’t do this)
public function __invoke(SurveyClosed $event): void
{
    foreach ($this->teachersOf($event->school) as $teacher) {
        $summary = $this->analyzer->summarize(/* comments */);   // 3–40 seconds each
        $this->save($teacher, $summary);
    }
}   // the web server gives up after 60 seconds; whatever is left is lost

The principal waits for work she doesn’t need to wait for, the request dies half-way, and there is no record of what was left undone, so nothing retries it.

The request should only write down what needs to be done, answer at once, and let a background process do the work, retrying when it fails.

The pattern: Command and Command Bus

Remember itAn action must be queued, retried, logged or run elsewhere → turn the request into a plain data object (a command); a bus finds its handler and runs it now or queues it.

Command (from the book): AnalyzeTeacherComments is the request "analyse teacher 1 for 2026-T1" as an object. It holds only data, so it can be stored as JSON in the jobs table and rebuilt later by another process.

The handler holds the logic and receives its services from the container. Splitting them keeps the command serializable: a live database connection can’t be stored in a queue.

The command bus (not in the book) is the single door: dispatch($command) looks up the handler, and queues the command if it implements ShouldQueue. The worker takes jobs from the queue, runs them through the bus, retries failures and raises an alert when a job fails for good.

  9. 9A queue in the database

    A command is stored as its class name and its public values in JSON, and rebuilt with named arguments. rebuild() refuses any class that isn’t a queueable command, so the table can’t be used to create arbitrary objects.

    src/Bus/DatabaseQueue.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Bus;

use LogicException;
use PDO;
use Throwable;

/**
 * A queue in a database table. Commands are stored as JSON: their class and their constructor values.
 */
final readonly class DatabaseQueue implements Queue
{
    public function __construct(private PDO $db)
    {
    }

    public function push(ShouldQueue $command): int
    {
        $insert = $this->db->prepare('INSERT INTO jobs (command, payload) VALUES (?, ?)');
        $insert->execute([$command::class, json_encode(get_object_vars($command), JSON_THROW_ON_ERROR)]);

        return (int) $this->db->lastInsertId();
    }

    public function reserve(): ?Job
    {
        $row = $this->db->query("SELECT * FROM jobs WHERE status = 'pending' ORDER BY id LIMIT 1")->fetch(PDO::FETCH_ASSOC);
        if ($row === false) {
            return null;
        }

        // A real multi-worker queue marks the row as reserved in the same statement (UPDATE ... RETURNING
        // or SELECT ... FOR UPDATE SKIP LOCKED) so two workers never take the same job.
        $this->db->prepare("UPDATE jobs SET status = 'running' WHERE id = ?")->execute([$row['id']]);

        return new Job((int) $row['id'], $this->rebuild((string) $row['command'], (string) $row['payload']), (int) $row['attempts']);
    }

    public function complete(Job $job): void
    {
        $this->db->prepare("UPDATE jobs SET status = 'done', attempts = attempts + 1 WHERE id = ?")->execute([$job->id]);
    }

    public function release(Job $job, Throwable $error, bool $final): void
    {
        $update = $this->db->prepare('UPDATE jobs SET status = ?, attempts = attempts + 1, last_error = ? WHERE id = ?');
        $update->execute([$final ? 'failed' : 'pending', $error->getMessage(), $job->id]);
    }

    private function rebuild(string $class, string $payload): object
    {
        if (!class_exists($class) || !is_subclass_of($class, ShouldQueue::class)) {
            throw new LogicException("Refusing to rebuild [{$class}]: it is not a queueable command.");
        }

        /** @var array<string, mixed> $values */
        $values = json_decode($payload, true, flags: JSON_THROW_ON_ERROR);

        return new $class(...$values);                      // named arguments: payload keys = constructor parameters
    }
}

  10. 10The command bus

    dispatch() queues or runs; dispatchNow() always runs. Handlers are found by the command’s class.

    src/Bus/CommandBus.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Bus;

use Closure;
use Evalu8\Logging\Logger;
use LogicException;

/**
 * The Command Bus: one door for every command. It finds the command's handler, and decides
 * whether to run it now or put it on the queue.
 */
final class CommandBus
{
    /** @var array<class-string, class-string> command class => handler class */
    private array $handlers = [];

    /**
     * @param Closure(class-string): object $resolve builds handlers (the container's make())
     */
    public function __construct(
        private readonly Closure $resolve,
        private readonly Queue $queue,
        private readonly Logger $logger,
    ) {
    }

    /**
     * @param class-string $command
     * @param class-string $handler a class with a handle($command) method
     */
    public function register(string $command, string $handler): void
    {
        $this->handlers[$command] = $handler;
    }

    /** Runs the command now, or queues it if it implements ShouldQueue. */
    public function dispatch(object $command): mixed
    {
        if ($command instanceof ShouldQueue) {
            $id = $this->queue->push($command);
            $this->logger->info('queued', ['command' => $this->shortName($command), 'job' => $id]);

            return null;
        }

        return $this->dispatchNow($command);
    }

    /** Runs the command immediately, whatever it is. The worker uses this for queued jobs. */
    public function dispatchNow(object $command): mixed
    {
        if (!isset($this->handlers[$command::class])) {
            throw new LogicException('No handler registered for ' . $command::class . '.');
        }

        $handlerClass = $this->handlers[$command::class];
        $handler = ($this->resolve)($handlerClass);
        if (!method_exists($handler, 'handle')) {
            throw new LogicException("{$handlerClass} has no handle() method.");
        }

        return $handler->handle($command);
    }

    private function shortName(object $command): string
    {
        $parts = explode('\\', $command::class);

        return end($parts);
    }
}

  11. 11The worker

    It runs jobs until the queue is empty, retrying failures up to maxAttempts, then marks the job failed and logs an ALERT. A production worker would also skip retries for errors that can’t succeed (like an unknown teacher); Laravel does this with $this->fail().

    src/Bus/Worker.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Bus;

use Evalu8\Logging\Logger;
use Throwable;

/**
 * Runs queued commands in the background, retrying failures, and raising an alert when a
 * job fails for good. In production it runs forever under a process manager (systemd, Supervisor).
 */
final readonly class Worker
{
    public function __construct(
        private Queue $queue,
        private CommandBus $bus,
        private Logger $logger,
        private int $maxAttempts = 3,
    ) {
    }

    /** Works until the queue is empty. Returns how many jobs were handled (done or failed). */
    public function runUntilEmpty(): int
    {
        $handled = 0;

        while (($job = $this->queue->reserve()) !== null) {
            $attempt = $job->attempts + 1;

            try {
                $this->bus->dispatchNow($job->command);
                $this->queue->complete($job);
                $this->logger->info('job done', ['job' => $job->id, 'attempt' => $attempt]);
                $handled++;
            } catch (Throwable $e) {
                $final = $attempt >= $this->maxAttempts;
                $this->queue->release($job, $e, $final);

                if ($final) {
                    $this->logger->warning('ALERT job failed for good', ['job' => $job->id, 'attempts' => $attempt, 'error' => $e->getMessage()]);
                    $handled++;
                } else {
                    $this->logger->warning('job failed, will retry', ['job' => $job->id, 'attempt' => $attempt, 'error' => $e->getMessage()]);
                }
            }
        }

        return $handled;
    }
}

How Laravel does it

Laravel jobs are commands: a job class holds data, dispatch() serializes it to the queue, and php artisan queue:work runs it with $tries, $backoff and failed() for the end of the road. Since Laravel 11, a job’s handle() method receives its services by injection, the same split as our command and handler.

Laravel
final class AnalyzeTeacherComments implements ShouldQueue
{
    use Queueable;

    public int $tries = 3;
    public array $backoff = [10, 60];

    public function __construct(public int $teacherId, public string $term) {}

    public function handle(CommentAnalyzer $analyzer, ResponseRepository $responses): void
    {
        // ...the same logic as our handler
    }

    public function failed(Throwable $e): void
    {
        Log::critical('Comment analysis failed for good', ['teacher' => $this->teacherId, 'error' => $e->getMessage()]);
    }
}

Check yourself

Answer in your head, then open the answer.

Why can’t the command hold the CommentAnalyzer object?

It is stored as JSON in the queue. A service with connections and state can’t be stored; the handler receives services when it runs.

What does the bus add on top of calling the handler directly?

One door for every command: it finds the handler, decides between running now and queuing, and is the place to add logging or transactions for all commands.

What happens to a job that keeps failing?

The worker retries it up to maxAttempts, then marks it failed and logs an ALERT. It is never silently dropped.
