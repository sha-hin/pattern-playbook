New ticket

Online answers: checks, abuse and a script guessing links

From Mona Saleh, Head of Quality, and Omar Hassan, DevOps

Answers now come through personal invitation links. Every answer must be refused if the survey isn’t open, the link isn’t valid for that teacher, or the link was already used. A script tried hundreds of links from one machine last night. And harsh comments must be reviewed: obvious abuse rejected automatically, otherwise the school’s own moderator if it has one, otherwise our quality team.

Why the quick fix is a trap

Everything inside one controller method:

the quick fix (we won’t do this)
public function submit(Submission $s): Receipt
{
    if ($this->tooMany($s->ip))            { return refuse('Too many'); }
    if (!$this->run->isOpen())             { return refuse('Closed'); }
    if (!$this->validToken($s))            { return refuse('Bad link'); }
    $this->markTokenUsed($s);              // ...even if saving fails below
    if ($this->isHarsh($s->comment)) {
        if ($this->isAbusive($s->comment)) { /* reject */ }
        elseif ($this->hasModerator($school)) { /* send to school */ }
        else { /* send to quality team */ }
    }
    // validate and save...
}

Every rule lives in one method, in one fixed order. A new check (say, "one answer per student per teacher") means editing it, and the token is marked as used before the answer is saved, so a typo in the score burns the respondent’s only link.

There are really two different problems here. The checks form a sequence that every submission passes through. The moderation is a choice: hand the comment along until someone can deal with it.

The pattern: Pipeline and Chain of Responsibility

Remember itA request goes through a sequence of steps that may stop it → a pipeline of stages, each calling the next. A request must be handled by one of several handlers → a chain where each one handles it or passes it on.

Pipeline (not in the book; it is how middleware works): each stage receives the submission and a $next function. It can refuse and stop, or call $next, and it can act after $next returns. RequireValidInvitation uses that: it marks the link as used only when the rest of the pipeline accepted the answer, so a rejected answer can be corrected and resent.

Chain of Responsibility (from the book): AutoFilter, SchoolModerator and QualityTeam are linked with then(). Each asks "can I handle this?", and either decides or passes the comment to the next. The sender only knows the first link. The last link handles everything, and a chain that nobody handles throws instead of dropping the comment.

They look alike (objects passing something along), but a pipeline expects every stage to run, while a chain stops at the first handler that takes the request.

/**

interface SubmissionStage
{
    /** @param Closure(Submission): Receipt $next */
    public function handle(Submission $submission, Closure $next): Receipt;
}

  4. 4The pipeline

    It wraps the stages around each other from the inside out: the last stage wraps the destination, the first stage wraps everything. Calling the result runs the first stage.

    src/Submission/Pipeline.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Submission;

use Closure;

/**
 * Pipeline: passes a submission through a list of stages in order, then to the final action.
 * The stages are wrapped around each other like layers; each one decides whether to continue.
 */
final readonly class Pipeline
{
    /**
     * @param list<SubmissionStage> $stages in the order they run
     * @param Closure(Submission): Receipt $destination what happens when every stage lets it through
     */
    public function __construct(
        private array $stages,
        private Closure $destination,
    ) {
    }

    public function process(Submission $submission): Receipt
    {
        // Build from the inside out: the last stage wraps the destination, the first stage wraps everything.
        $next = $this->destination;
        foreach (array_reverse($this->stages) as $stage) {
            $next = fn (Submission $s): Receipt => $stage->handle($s, $next);
        }

        return $next($submission);
    }
}

  5. 5Stage: limit submissions per device

    It runs first: it is cheap, and it stops a script before any lookup.

    src/Submission/Stages/LimitRate.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Submission\Stages;

use Closure;
use Evalu8\Submission\Receipt;
use Evalu8\Submission\Submission;
use Evalu8\Submission\SubmissionStage;

/** At most N submissions per device; stops scripts that try invitation tokens. (Production: Redis.) */
final class LimitRate implements SubmissionStage
{
    /** @var array<string, int> */
    private array $counts = [];

    public function __construct(private readonly int $maxPerDevice = 3)
    {
    }

    public function handle(Submission $submission, Closure $next): Receipt
    {
        $count = ($this->counts[$submission->ipAddress] ?? 0) + 1;
        $this->counts[$submission->ipAddress] = $count;

        if ($count > $this->maxPerDevice) {
            return new Receipt(false, 'Too many submissions from this device. Try again later.');
        }

        return $next($submission);
    }
}

  8. 8Stage: a valid, unused invitation

    Code after $next() runs on the way back: the link is used up only if the answer was accepted.

    src/Submission/Stages/RequireValidInvitation.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Submission\Stages;

use Closure;
use Evalu8\Submission\Receipt;
use Evalu8\Submission\Submission;
use Evalu8\Submission\SubmissionStage;

/**
 * Each respondent gets one invitation link. The token is marked as used only AFTER the
 * rest of the pipeline accepted the answer, so a rejected answer can be corrected and resent.
 */
final class RequireValidInvitation implements SubmissionStage
{
    /** @var array<string, true> tokens already used */
    private array $used = [];

    /** @param array<string, int> $invitations token => teacher id it was issued for */
    public function __construct(private readonly array $invitations)
    {
    }

    public function handle(Submission $submission, Closure $next): Receipt
    {
        $token = $submission->invitationToken;

        if (($this->invitations[$token] ?? null) !== $submission->teacherId) {
            return new Receipt(false, 'This invitation link is not valid for this teacher.');
        }
        if (isset($this->used[$token])) {
            return new Receipt(false, 'This invitation has already been used.');
        }

        $receipt = $next($submission);                      // run the rest of the pipeline first...

        if ($receipt->accepted) {
            $this->used[$token] = true;                     // ...and only then use up the invitation
        }

        return $receipt;
    }
}

  10. 10The chain: the base handler

    review() handles the comment if this moderator can, otherwise passes it on. then() returns the next moderator, so a chain reads left to right.

    src/Moderation/Moderator.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Moderation;

use LogicException;

/**
 * Chain of Responsibility: each moderator either handles a flagged comment or passes it
 * to the next one in the chain. The sender doesn't know who will handle it.
 */
abstract class Moderator
{
    private ?Moderator $next = null;

    /** Sets who comes after this moderator, and returns it so chains read left to right. */
    public function then(Moderator $next): Moderator
    {
        $this->next = $next;

        return $next;
    }

    /** @return string what happened to the comment */
    public function review(FlaggedComment $comment): string
    {
        if ($this->canHandle($comment)) {
            return $this->handle($comment);
        }

        if ($this->next === null) {
            throw new LogicException('Nobody in the moderation chain handled the comment.');   // never silent
        }

        return $this->next->review($comment);
    }

    abstract protected function canHandle(FlaggedComment $comment): bool;

    abstract protected function handle(FlaggedComment $comment): string;
}

  11. 11Link 1: the automatic filter

    src/Moderation/AutoFilter.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Moderation;

/** Handles the obvious cases: comments with words that are never acceptable. */
final class AutoFilter extends Moderator
{
    /** @param list<string> $blockedWords */
    public function __construct(private readonly array $blockedWords)
    {
    }

    protected function canHandle(FlaggedComment $comment): bool
    {
        foreach ($this->blockedWords as $word) {
            if (preg_match('/\b' . preg_quote($word, '/') . '\b/iu', $comment->text) === 1) {
                return true;
            }
        }

        return false;
    }

    protected function handle(FlaggedComment $comment): string
    {
        return 'rejected automatically';
    }
}

  14. 14Stage: screen the comment

    The pipeline stage that uses the chain. The score is still saved; the comment is held and the respondent is told what happened to it.

    src/Submission/Stages/ScreenComment.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Submission\Stages;

use Closure;
use Evalu8\Domain\TeacherRepository;
use Evalu8\Moderation\FlaggedComment;
use Evalu8\Moderation\Moderator;
use Evalu8\Submission\Receipt;
use Evalu8\Submission\Submission;
use Evalu8\Submission\SubmissionStage;

/**
 * Comments with suspicious words are handed to the moderation chain. The score is still
 * saved; the comment is held until a person (or the filter) decides.
 */
final readonly class ScreenComment implements SubmissionStage
{
    /** @param list<string> $suspiciousWords */
    public function __construct(
        private array $suspiciousWords,
        private Moderator $moderation,
        private TeacherRepository $teachers,
    ) {
    }

    public function handle(Submission $submission, Closure $next): Receipt
    {
        if (!$this->isSuspicious($submission->comment)) {
            return $next($submission);
        }

        $school = $this->teachers->get($submission->teacherId)->school;
        $decision = $this->moderation->review(new FlaggedComment($school, $submission->comment));

        $withoutComment = new Submission(
            $submission->invitationToken,
            $submission->teacherId,
            $submission->role,
            $submission->score,
            '',
            $submission->ipAddress,
        );
        $receipt = $next($withoutComment);

        return $receipt->accepted
            ? new Receipt(true, "{$receipt->message} Your comment was {$decision}.")
            : $receipt;
    }

    private function isSuspicious(string $comment): bool
    {
        foreach ($this->suspiciousWords as $word) {
            if (preg_match('/\b' . preg_quote($word, '/') . '\b/iu', $comment) === 1) {
                return true;
            }
        }

        return false;
    }
}

How Laravel does it

HTTP middleware is a pipeline: each middleware gets the request and $next, may return early, and may work on the response after $next($request). Laravel exposes the same engine as Illuminate\Pipeline\Pipeline for your own objects.

Laravel
$receipt = app(Pipeline::class)
    ->send($submission)
    ->through([LimitRate::class, RequireOpenSurvey::class, RequireValidInvitation::class, ScreenComment::class])
    ->via('handle')
    ->then(fn (Submission $s) => $this->save($s));

// The rate limit, the Laravel way:
RateLimiter::for('answers', fn (Request $request) => Limit::perMinute(3)->by($request->ip()));

Check yourself

Answer in your head, then open the answer.

A new rule: "one answer per student per teacher". What changes?

One new stage class, added to the list. The other stages don’t change.

Why is the invitation marked as used after $next() returns?

So it is used up only when the answer was really accepted. A refused answer can be corrected and resent with the same link.

What is the main difference between the pipeline and the chain?

In the pipeline every stage runs unless one stops it. In the chain, the first handler that can take the request handles it and the rest never see it.

The quality team wants lists: who enters the support program, who gets the excellence award. Each list has its own rules, and the rules overlap.
