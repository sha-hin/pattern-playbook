Adapter

StructureGoF book

A travel plug: your charger, their wall socket.

The rule to rememberA third-party class has the wrong shape and you can't edit it → wrap it in a class that speaks YOUR interface.

Without it: the pain

The SMS provider SDK is called directly in 12 places. Switching provider means editing 12 files.

With it: the fix

Your app only knows SmsSender. One adapter class talks to the SDK. Switching = one new adapter.

Reach for it when you see

  • A vendor SDK is called directly all over your code
  • "We might switch provider" is said in a meeting
  • The SDK returns false / status arrays instead of throwing

Real job where it fits

You send SMS through Twilio today. Management wants to try Vonage next quarter.

Before: the code that hurts

// in 12 different controllers and jobs:
$twilio = new \Twilio\Rest\Client(config('services.twilio.sid'), config('services.twilio.token'));
$twilio->messages->create($phone, ['from' => '+1555...', 'body' => $text]);

Build it yourself: the full Adapter pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

TargetSmsSender the interface YOUR code wants
AdapteeAcmeSmsClient a third-party class with the wrong shape, which you cannot edit
AdapterAcmeSmsAdapter implements the Target, holds the Adaptee, translates between them
ClientOrderNotifier only knows the Target
<?php

declare(strict_types=1);

// ── The third-party class (pretend it came from Composer). You can't change it. ──
class AcmeSmsClient  // Adaptee
{
    public function dispatch(array $payload): array
    {
        if (!str_starts_with($payload['msisdn'], '+')) {
            return ['status' => 'rejected', 'error' => 'invalid msisdn'];
        }

        return ['status' => 'queued', 'id' => 'acme_' . rand(1000, 9999)];
    }
}

// ── Step 1: the Target. The simple interface YOUR code wants. ──
interface SmsSender  // Target
{
    public function send(string $phone, string $text): string;   // returns the message id
}

// ── Step 2: the Adapter. Your interface outside, their class inside. ──
class AcmeSmsAdapter implements SmsSender  // Adapter
{
    public function __construct(private AcmeSmsClient $client)  // holds the third-party object
    {
    }

    public function send(string $phone, string $text): string
    {
        $phone = str_replace(' ', '', $phone);
        if (str_starts_with($phone, '0')) {
            $phone = '+2' . $phone;                          // Egyptian 0100... becomes +20100...
        }

        $result = $this->client->dispatch([  // translate YOUR call into THEIR call
            'msisdn' => $phone,
            'text' => $text,
        ]);

        if ($result['status'] !== 'queued') {  // turn their "status" array into an exception
            throw new RuntimeException("SMS to {$phone} failed: {$result['error']}");
        }

        return $result['id'];
    }
}

// ── Step 3: the Client. It only knows SmsSender. ──
class OrderNotifier  // Client
{
    public function __construct(private SmsSender $sms)
    {
    }

    public function orderReady(string $phone, int $orderId): string
    {
        return $this->sms->send($phone, "Order #{$orderId} is ready.");
    }
}

// ── Using it ──
$notifier = new OrderNotifier(new AcmeSmsAdapter(new AcmeSmsClient()));

$id = $notifier->orderReady('0100 123 4567', 42);
echo 'Sent, id starts with: ' . substr($id, 0, 5) . "\n";

try {
    $notifier->orderReady('12', 43);
} catch (RuntimeException $e) {
    echo $e->getMessage() . "\n";
}

// Switching provider = one new adapter class. OrderNotifier never changes.

Highlighted lines are the ones that make it this pattern. Run it: php examples/adapter.php · Open the file on GitHub

Output
Sent, id starts with: acme_
SMS to 12 failed: invalid msisdn

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

interface SmsSender                                  // YOUR shape
{
    public function send(string $to, string $text): void;
}

class TwilioSmsSender implements SmsSender  // the adapter
{
    public function __construct(
        private \Twilio\Rest\Client $twilio,
        private string $from,
    ) {}

    public function send(string $to, string $text): void
    {
        $message = $this->twilio->messages->create($to, [  // translate the call
            'from' => $this->from,
            'body' => $text,
        ]);

        if ($message->status === 'failed') {  // translate failure into an exception
            throw new SmsFailed("SMS to {$to} failed: {$message->errorMessage}");
        }
    }
}

// AppServiceProvider: switching provider later = change this one binding
$this->app->bind(SmsSender::class, fn () => new TwilioSmsSender(
    new \Twilio\Rest\Client(config('services.twilio.sid'), config('services.twilio.token')),
    config('services.twilio.from'),
));

// Everywhere else:
public function __construct(private SmsSender $sms) {}
$this->sms->send($user->phone, 'Your report is ready.');

How Laravel builds it inside: Storage::put() works on S3, local disk or FTP because of adapters. Laravel's FilesystemAdapter translates Laravel's put() / exists() into the Flysystem library's write() / has(), and each Flysystem adapter translates those into one storage SDK.
