Null Object

New ticket

Miami’s term report crashes: "Call to a member function summarize() on null"

From Support desk

We released comment analysis for schools on the paid plan. Smouha and Victoria are fine. Miami is not on the plan, and its report now stops with a fatal error. Miami’s principal needs the report today.

Why the quick fix is a trap

The first version picked the analyzer like this:

the quick fix (we won’t do this)
$analyzer = $school->commentAnalysis ? new KeywordCommentAnalyzer() : null;

// ...and later, in the report:
$summary = $analyzer->summarize($comments);   // Miami: fatal error

The quick fix is if ($analyzer !== null) before every call. There are already three calls (report, email, export), and every future screen must remember the check. The first one that forgets brings the crash back.

For Miami, "no analysis" is not an error. It is a normal, expected case. So instead of representing it with null, we can represent it with an object.

The pattern: Null Object

Remember it"Nothing" is a normal case → represent it with an object that has the same interface and safely does nothing, so callers never check for null.

CommentAnalyzer gets a second implementation, NoCommentAnalysis. It has the same summarize() method, and it returns a neutral text instead of analysing anything. Every school gets a real CommentAnalyzer object, so ->summarize() always works.

The decision ("does this school get analysis?") is made once, in a small factory, and nowhere else.

When not to use it: only when "nothing" really is fine. A teacher with no email address is *not* a case for a "null mailer" that pretends to send: that would hide a real problem. The report still says "Not sent to Nadia" loudly.

Null Object is not in the Gang of Four book. It was described by Bobby Woolf in *Pattern Languages of Program Design 3* (1997).

  2. 2The real analyzer

    Evalu8’s built-in analysis counts recurring themes by keyword. It is simple on purpose; chapter 7 replaces it with a language model behind the same interface.

    src/Analysis/KeywordCommentAnalyzer.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Analysis;

/**
 * Evalu8's built-in analysis: finds recurring themes by keyword.
 * (Chapter 7 replaces it with a real language model; the interface stays the same.)
 */
final readonly class KeywordCommentAnalyzer implements CommentAnalyzer
{
    /** theme => words that point to it */
    private const THEMES = [
        'clarity' => ['clear', 'clearly', 'explains', 'understand'],
        'punctuality' => ['late', 'on time', 'starts'],
        'pace' => ['fast', 'slow', 'rushed'],
        'planning' => ['plan', 'planning', 'organised', 'organized'],
        'assessment' => ['test', 'exam', 'grade', 'failed'],
    ];

    public function summarize(array $comments): string
    {
        if (count($comments) === 0) {
            return 'no written comments';
        }

        $counts = [];
        foreach ($comments as $comment) {
            $text = strtolower($comment);
            foreach (self::THEMES as $theme => $words) {
                foreach ($words as $word) {
                    if (str_contains($text, $word)) {
                        $counts[$theme] = ($counts[$theme] ?? 0) + 1;
                        break;                              // count each theme once per comment
                    }
                }
            }
        }

        if (count($counts) === 0) {
            return 'no recurring themes in ' . count($comments) . ' comment(s)';
        }

        arsort($counts);
        $parts = [];
        foreach ($counts as $theme => $count) {
            $parts[] = "{$theme} ({$count})";
        }

        return 'themes: ' . implode(', ', $parts);
    }
}

  3. 3The Null Object

    Same interface, no work, no crash. It returns a neutral sentence the report can print as is.

    src/Analysis/NoCommentAnalysis.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Analysis;

/**
 * The Null Object: a real CommentAnalyzer that safely does nothing.
 * Used for schools whose plan doesn't include analysis, so no caller
 * ever needs to check "is there an analyzer?".
 */
final readonly class NoCommentAnalysis implements CommentAnalyzer
{
    public function summarize(array $comments): string
    {
        return 'not included in this school’s plan';
    }
}

  4. 4Decide once

    The factory receives the real analyzer from outside (so it can be swapped later) and returns the Null Object for schools without the feature.

    src/Analysis/CommentAnalyzerFactory.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Analysis;

use Evalu8\Domain\School;

/**
 * Decides ONCE, from the school's settings, which analyzer it gets.
 * "No analysis" is a normal choice here, so it is an object, not null.
 */
final readonly class CommentAnalyzerFactory
{
    public function __construct(private CommentAnalyzer $analyzer)
    {
    }

    public function forSchool(School $school): CommentAnalyzer
    {
        return $school->commentAnalysis ? $this->analyzer : new NoCommentAnalysis();
    }
}

How Laravel does it

Laravel ships several Null Objects you can choose in config: the null cache store (NullStore), the null broadcaster, the null queue connection and the null log channel (NullHandler). Choosing one turns a feature off without a single if in your code.

In your app, the binding decides once:

Laravel
// AppServiceProvider::register()
$this->app->bind(CommentAnalyzer::class, function (Application $app) {
    return config('features.comment_analysis')
        ? $app->make(KeywordCommentAnalyzer::class)
        : new NoCommentAnalysis();
});

Check yourself

Answer in your head, then open the answer.

Why is NoCommentAnalysis better than if ($analyzer !== null)?

The decision is made once. Every caller just calls summarize(), and a new screen can’t forget a check that doesn’t exist.

Should a missing teacher email use a "null mailer" that does nothing?

No. A missing email is a problem someone must fix. A Null Object would hide it. Use Null Object only when "nothing" is a correct result.

Where is the decision "analysis or not" made?

In CommentAnalyzerFactory::forSchool(), from the school’s setting. Nowhere else.
