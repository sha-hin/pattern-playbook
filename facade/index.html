Facade

StructureGoF book

Hotel reception: you talk to one desk, they call housekeeping, the kitchen and the taxi.

The rule to rememberA multi-step job that touches many services, needed from many places → one class with one method that runs it all.

Without it: the pain

Web, API and CSV import each repeat the same 4 steps. The import forgot step 3.

With it: the fix

One EnrollStudent class owns the steps. Every caller is one line, and can’t forget a step.

Reach for it when you see

  • The same 3–5 service calls are copied in several controllers/jobs
  • A bug where one copy forgot a step
  • New developers ask "what do I call to do X?"

Real job where it fits

Enrolling a student: create user, assign class, open billing, send welcome. From web, API and CSV import.

Before: the code that hurts

// WebController, ApiController and ImportStudentsJob each contain:
$user = $users->createStudent($name, $email);
$classes->assign($user, $classId);
$billing->openAccount($user, $plan);    // ← the import job forgot this line
$mailer->welcome($user);

Build it yourself: the full Facade pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

FacadeEnrollStudent one simple method that runs the whole job
SubsystemsUsers, Classes, Billing, Mailer still usable on their own
Clientsthe web form, the API and the CSV import all call the facade
<?php

declare(strict_types=1);

// ── The subsystems. Each does one small thing. ──
class Users
{
    public array $all = [];

    public function create(string $name): int
    {
        $id = count($this->all) + 1;
        $this->all[$id] = $name;

        return $id;
    }

    public function delete(int $id): void
    {
        unset($this->all[$id]);
    }
}

class Classes
{
    public array $assigned = [];

    public function assign(int $studentId, string $class): void
    {
        $this->assigned[$studentId] = $class;
    }

    public function unassign(int $studentId): void
    {
        unset($this->assigned[$studentId]);
    }
}

class Billing
{
    public function openAccount(int $studentId, string $plan): void
    {
        if ($plan !== 'monthly' && $plan !== 'yearly') {
            throw new InvalidArgumentException("Unknown plan [{$plan}].");
        }
    }
}

class Mailer
{
    public function welcome(string $name): void
    {
        echo "Welcome email sent to {$name}\n";
    }
}

// ── The Facade. One simple door that runs every step in the right order. ──
class EnrollStudent  // Facade
{
    public function __construct(
        private Users $users,
        private Classes $classes,
        private Billing $billing,
        private Mailer $mailer,
    ) {
    }

    public function handle(string $name, string $class, string $plan): int  // the one method callers use
    {
        $studentId = $this->users->create($name);  // step 1

        try {
            $this->classes->assign($studentId, $class);  // step 2
            $this->billing->openAccount($studentId, $plan);  // step 3
        } catch (Exception $e) {
            $this->classes->unassign($studentId);           // something failed: undo the earlier steps
            $this->users->delete($studentId);
            throw $e;
        }

        $this->mailer->welcome($name);  // step 4, only after everything worked

        return $studentId;
    }
}

// ── Using it: every caller is one line, and none of them can forget a step ──
$users = new Users();
$classes = new Classes();
$enroll = new EnrollStudent($users, $classes, new Billing(), new Mailer());

$enroll->handle('Mona', '3-B', 'monthly');                  // from the web form

try {
    $enroll->handle('Omar', '3-B', 'weekly');               // from the CSV import, with a bad plan
} catch (InvalidArgumentException $e) {
    echo 'Import row rejected: ' . $e->getMessage() . "\n";
}

echo 'Students: ' . implode(', ', $users->all) . ' | assigned to a class: ' . count($classes->assigned) . "\n";

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

class EnrollStudent  // the one front door
{
    public function __construct(
        private Users $users,
        private Classes $classes,
        private Billing $billing,
        private Mailer $mailer,
    ) {}

    public function handle(EnrollmentData $data): Student
    {
        return DB::transaction(function () use ($data) {
            $student = $this->users->createStudent($data->name, $data->email);
            $this->classes->assign($student, $data->classId);
            $this->billing->openAccount($student, $data->plan);

            DB::afterCommit(fn () => $this->mailer->welcome($student));  // only if all of it saved

            return $student;
        });
    }
}

// WebController, ApiController, ImportStudentsJob — all the same single line:
$student = $enrollStudent->handle($data);  // can't forget a step

How Laravel builds it inside: The HTTP Kernel is a Facade over the framework itself: one call, handle($request), sets up config and service providers, runs the middleware, calls the router and reports errors. In your own app, "action" classes like EnrollStudent are the same idea. (Laravel's Cache:: style "facades" are something else: see the Laravel Facade card.)
