Chapter 4 of 30

The scoring method must come from school settings

Simple Factory

New ticket

Schools must choose their scoring method in Settings

From Ahmed Nabil, Product Owner

Every time a school changes its scoring method we deploy code. Victoria wants to try the median next week, and new schools join every month. Put the choice in each school’s settings, and if a setting is wrong, tell us which school and what is wrong.

Why the quick fix is a trap

Chapter 3 left the choice in the script as a list of schools. The quick fix moves it into TermReport as a match on the setting:

the quick fix (we won’t do this)
$method = match ($school->scoringMethod) {
    'median' => new MedianScoring(),
    'weighted' => new WeightedScoring($school->scoringWeights),
    default => new AverageScoring(),
};

It works, until the email preview screen and the Ministry export need the same decision and copy the same match. The first copy that forgets 'trimmed' (or quietly falls back to the average for a typo like medain) produces a different score for the same teacher, and nobody notices because default hides the mistake.

The decision "which scoring class does this school get?" needs one home, and a wrong setting must fail loudly instead of falling back silently.

The pattern: Simple Factory

Remember itDeciding which class to create, from some input, happens in one place → put that decision in one class with one method. Everyone else just asks it.

ScoringMethodFactory::forSchool($school) reads the school’s settings and returns the right ScoringMethod. TermReport, a preview screen or an export all call the same method, so they always agree.

Notice how it fits with the previous chapter: the factory picks which strategy to use, and the strategy does the work. Inside the factory each branch is only new SomeClass(); inside a strategy is the real logic. If you find yourself writing scoring maths inside the match, you have mixed the two.

Simple Factory is not in the Gang of Four book; *Head First Design Patterns* calls it "more of a programming idiom". The book’s two factory patterns, Factory Method and Abstract Factory, come in chapters 13 and 27.

  5. 5The SQLite school repository

    The weights are stored as JSON. JSON_THROW_ON_ERROR makes broken JSON an exception instead of a silent null.

    src/Infrastructure/Sqlite/SqliteSchoolRepository.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Infrastructure\Sqlite;

use Evalu8\Domain\NotFound;
use Evalu8\Domain\School;
use Evalu8\Domain\SchoolRepository;
use JsonException;
use PDO;

final readonly class SqliteSchoolRepository implements SchoolRepository
{
    public function __construct(private PDO $db)
    {
    }

    public function get(string $name): School
    {
        $select = $this->db->prepare('SELECT name, scoring_method, scoring_weights FROM schools WHERE name = ?');
        $select->execute([$name]);
        $row = $select->fetch(PDO::FETCH_ASSOC);

        if ($row === false) {
            throw new NotFound("No school called \"{$name}\".");
        }

        return new School(
            (string) $row['name'],
            (string) $row['scoring_method'],
            $this->weights($row['scoring_weights']),
        );
    }

    /**
     * @return array<string, float>
     * @throws JsonException when the stored weights are not valid JSON
     */
    private function weights(mixed $json): array
    {
        if ($json === null || $json === '') {
            return [];
        }

        /** @var array<string, float> $weights */
        $weights = json_decode((string) $json, true, flags: JSON_THROW_ON_ERROR);

        return $weights;
    }
}

  7. 7The factory

    One match, one place. Each branch only creates an object. There is deliberately no fallback to the average: an unknown name throws, with the school and the valid options in the message.

    src/Scoring/ScoringMethodFactory.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Scoring;

use Evalu8\Domain\School;

/**
 * The Simple Factory: the ONE place that reads a school's settings and
 * decides which ScoringMethod to build. Every caller just asks for one.
 */
final readonly class ScoringMethodFactory
{
    public function forSchool(School $school): ScoringMethod
    {
        return match ($school->scoringMethod) {
            'average' => new AverageScoring(),
            'median' => new MedianScoring(),
            'weighted' => new WeightedScoring($school->scoringWeights),
            default => throw new UnknownScoringMethod(
                "School \"{$school->name}\" uses unknown scoring method \"{$school->scoringMethod}\". "
                . 'Expected one of: average, median, weighted.'
            ),
        };
    }
}

How Laravel does it

Laravel’s database layer picks its connector the same way: ConnectionFactory reads the driver from config/database.php and a match builds a MySqlConnector, PostgresConnector or SQLiteConnector. An unknown driver throws "Unsupported driver".

In your app, register the factory and inject it; its forSchool() stays exactly as in this chapter:

Laravel
// Anywhere that needs a school's scoring method:
public function __construct(private ScoringMethodFactory $scoringMethods) {}

$method = $this->scoringMethods->forSchool($school);

Check yourself

Answer in your head, then open the answer.

A new method, "trimmed average", is added. Which files change?

One new class (TrimmedAverageScoring) and one new line in the factory’s match. TermReport doesn’t change.

Why doesn’t the factory fall back to AverageScoring for an unknown name?

A typo would silently give a school the wrong scores. Throwing with the school name and the valid options makes the mistake visible immediately.

What is the difference between the factory and the strategy?

The factory decides which object to create (each branch is just new X()). The strategy does the work (the scoring maths).

Some schools also pay for comment analysis, and some don’t. The first attempt to support both crashes the report.
