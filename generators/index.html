Generators

BehaviourNot in the book

A water tap: you get water as you need it, not a 10,000-litre tank delivered at once.

The rule to rememberBig data you loop over once → yield one item at a time; memory stays flat no matter the size.

Without it: the pain

->get() loads 2 million rows into an array. The export dies at 60% with "Allowed memory size exhausted".

With it: the fix

A generator reads 1,000 rows at a time and yields them one by one. The loop looks the same; memory stays flat.

Reach for it when you see

  • "Allowed memory size … exhausted"
  • ->get() / fetchAll() on a huge table just to loop once
  • Building a giant array only to pass it to a loop

Real job where it fits

Every night, export 2 million evaluations to CSV.

Before: the code that hurts

$rows = DB::table('evaluations')->get();     // 2,000,000 rows into memory
foreach ($rows as $row) {
    fputcsv($out, (array) $row);
}
// PHP Fatal error: Allowed memory size of 536870912 bytes exhausted

Build it yourself: the full Generators pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

<?php

declare(strict_types=1);

// ── Setup: a table with 100,000 rows in an in-memory SQLite database ──
$db = new PDO('sqlite::memory:');
$db->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$db->exec('CREATE TABLE evaluations (id INTEGER PRIMARY KEY, school_id INTEGER, score INTEGER, notes TEXT)');

$db->beginTransaction();
$insert = $db->prepare('INSERT INTO evaluations (school_id, score, notes) VALUES (?, ?, ?)');
for ($i = 1; $i <= 100000; $i++) {
    $insert->execute([$i % 300, $i % 101, str_repeat('x', 60)]);
}
$db->commit();

// ── Step 1: a generator function. Notice "yield" instead of "return". ──
/** @return Generator<int, array<string, mixed>> */
function evaluations(PDO $db): Generator  // generator function
{
    $query = $db->prepare('SELECT * FROM evaluations WHERE id > ? ORDER BY id LIMIT 1000');
    $lastId = 0;

    while (true) {
        $query->execute([$lastId]);
        $rows = $query->fetchAll(PDO::FETCH_ASSOC);         // at most 1,000 rows in memory

        if (count($rows) === 0) {
            return;                                         // no more rows: the loop ends
        }

        foreach ($rows as $row) {
            yield $row;  // hand out one row, pause here
            $lastId = $row['id'];
        }
    }
}

// ── Step 2: a normal loop that works with arrays AND generators ──
/** @param iterable<array<string, mixed>> $rows */
function exportCsv(iterable $rows): int
{
    $file = fopen('php://memory', 'w');
    $count = 0;

    foreach ($rows as $row) {
        fwrite($file, implode(',', $row) . "\n");
        $count++;
    }

    fclose($file);

    return $count;
}

// ── Compare the memory used ──
$start = memory_get_usage();
$count = exportCsv(evaluations($db));  // looks like any other loop
$usedByGenerator = memory_get_peak_usage() - $start;

$start = memory_get_usage();
$allRows = $db->query('SELECT * FROM evaluations')->fetchAll(PDO::FETCH_ASSOC);   // everything at once
exportCsv($allRows);
$usedByFetchAll = memory_get_peak_usage() - $start;

echo "Exported {$count} rows\n";
echo 'Generator: about ' . round($usedByGenerator / 1048576) . " MB\n";
echo 'fetchAll:  about ' . round($usedByFetchAll / 1048576) . " MB\n";

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

function evaluations(PDO $pdo, int $chunk = 1000): Generator
{
    $lastId = 0;
    $query = $pdo->prepare(
        'SELECT id, school_id, score FROM evaluations WHERE id > :id ORDER BY id LIMIT :n'
    );

    do {
        $query->bindValue(':id', $lastId, PDO::PARAM_INT);
        $query->bindValue(':n', $chunk, PDO::PARAM_INT);
        $query->execute();
        $rows = $query->fetchAll(PDO::FETCH_ASSOC);        // at most 1,000 rows in memory

        foreach ($rows as $row) {
            yield $row;  // hand out one, pause here
            $lastId = $row['id'];
        }
    } while (count($rows) === $chunk);                      // WHERE id > ? stays fast at row 2,000,000
}

$out = fopen($path, 'w') ?: throw new RuntimeException("Cannot write {$path}");
foreach (evaluations($pdo) as $row) {  // looks like a normal loop
    fputcsv($out, $row);
}
fclose($out);

How Laravel builds it inside: Model::lazyById(1000) returns a LazyCollection built on a generator: it runs one "WHERE id > ? ORDER BY id LIMIT 1000" query at a time and yields each row, so memory stays small however big the table is.
