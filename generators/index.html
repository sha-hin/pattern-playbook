Generators

BehaviourNot in the book

A water tap: you get water as you need it, not a 10,000-litre tank delivered at once.

The rule to rememberBig data you loop over once → yield one item at a time; memory stays flat no matter the size.

Without it: the pain

->get() loads 2 million rows into an array. The export dies at 60% with "Allowed memory size exhausted".

With it: the fix

A generator reads 1,000 rows at a time and yields them one by one. The loop looks the same; memory stays flat.

Reach for it when you see

  • "Allowed memory size … exhausted"
  • ->get() / fetchAll() on a huge table just to loop once
  • Building a giant array only to pass it to a loop

Real job where it fits

Every night, export 2 million evaluations to CSV.

Before: the code that hurts

$rows = DB::table('evaluations')->get();     // 2,000,000 rows into memory
foreach ($rows as $row) {
    fputcsv($out, (array) $row);
}
// PHP Fatal error: Allowed memory size of 536870912 bytes exhausted

After: how you implement the Generators pattern in PHP

function evaluations(PDO $pdo, int $chunk = 1000): Generator
{
    $lastId = 0;
    $query = $pdo->prepare(
        'SELECT id, school_id, score FROM evaluations WHERE id > :id ORDER BY id LIMIT :n'
    );

    do {
        $query->bindValue(':id', $lastId, PDO::PARAM_INT);
        $query->bindValue(':n', $chunk, PDO::PARAM_INT);
        $query->execute();
        $rows = $query->fetchAll(PDO::FETCH_ASSOC);        // at most 1,000 rows in memory

        foreach ($rows as $row) {
            yield $row;  // hand out one, pause here
            $lastId = $row['id'];
        }
    } while (count($rows) === $chunk);                      // WHERE id > ? stays fast at row 2,000,000
}

$out = fopen($path, 'w') ?: throw new RuntimeException("Cannot write {$path}");
foreach (evaluations($pdo) as $row) {  // looks like a normal loop
    fputcsv($out, $row);
}
fclose($out);
