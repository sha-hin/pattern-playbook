Command Bus

BehaviourNot in the book

A dispatch desk: you hand in a form, and the desk knows which department handles it.

The rule to rememberSplit "what to do" (a data object) from "how" (a handler) → the same action runs from web, CLI or queue, with shared rules around it.

Without it: the pain

The business logic lives in a controller. The scheduler and the import need it too, so it gets copied or called through HTTP.

With it: the fix

RecalculateSchoolStats is data; its handler holds the logic. Any entry point dispatches the same command.

Reach for it when you see

  • The same business action needed from HTTP, CLI and queue
  • Fat controllers full of business logic
  • You want one place for transactions / logging around every action

Real job where it fits

"Recalculate school statistics" runs from an admin button, a nightly schedule, and after every import.

Before: the code that hurts

Build it yourself: the full Command Bus pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

CommandRecalculateSchoolStats only data: WHAT should happen
HandlerRecalculateSchoolStatsHandler the logic: HOW it happens
BusCommandBus finds the right handler and runs it
Shared ruleslogging and a database transaction, written once inside the bus
<?php

declare(strict_types=1);

// ── Step 1: the command. Only data. ──
final class RecalculateSchoolStats  // Command
{
    public function __construct(public readonly int $schoolId)
    {
    }
}

// ── Step 2: the handler. The logic, with what it needs. ──
final class RecalculateSchoolStatsHandler  // Handler
{
    public function __construct(private readonly PDO $db)
    {
    }

    public function handle(RecalculateSchoolStats $command): float
    {
        $query = $this->db->prepare('SELECT AVG(score) FROM evaluations WHERE school_id = ?');
        $query->execute([$command->schoolId]);
        $average = round((float) $query->fetchColumn(), 1);

        $save = $this->db->prepare('REPLACE INTO school_stats (school_id, average) VALUES (?, ?)');
        $save->execute([$command->schoolId, $average]);

        return $average;
    }
}

// ── Step 3: the bus. Finds the handler, and applies the shared rules to EVERY command. ──
final class CommandBus  // Bus
{
    /** @var array<class-string, object> command class => its handler */
    private array $handlers = [];

    public function __construct(private readonly PDO $db)
    {
    }

    public function register(string $commandClass, object $handler): void
    {
        $this->handlers[$commandClass] = $handler;
    }

    public function dispatch(object $command): mixed
    {
        $class = get_class($command);

        if (!isset($this->handlers[$class])) {
            throw new LogicException("No handler registered for {$class}.");
        }

        $handler = $this->handlers[$class];  // find the handler

        echo "-> {$class}\n";                               // shared rule 1: log every command

        $this->db->beginTransaction();                      // shared rule 2: all or nothing
        try {
            $result = $handler->handle($command);  // run it
            $this->db->commit();
        } catch (Throwable $e) {
            $this->db->rollBack();
            throw $e;
        }

        echo "<- done\n";

        return $result;
    }
}

// ── Setup: an in-memory SQLite database ──
$db = new PDO('sqlite::memory:');
$db->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$db->exec('CREATE TABLE evaluations (school_id INTEGER, score INTEGER)');
$db->exec('CREATE TABLE school_stats (school_id INTEGER PRIMARY KEY, average REAL)');
$db->exec('INSERT INTO evaluations VALUES (7, 80), (7, 91), (7, 74)');

$bus = new CommandBus($db);
$bus->register(RecalculateSchoolStats::class, new RecalculateSchoolStatsHandler($db));

// ── The admin button, the nightly schedule and the importer all use this one line ──
$average = $bus->dispatch(new RecalculateSchoolStats(7));
echo "Average: {$average}\n";

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

final class RecalculateSchoolStats  // the command: only data
{
    public function __construct(public readonly int $schoolId) {}
}

final class RecalculateSchoolStatsHandler  // the handler: logic + dependencies
{
    public function __construct(private StatsCalculator $calc, private StatsRepository $stats) {}

    public function handle(RecalculateSchoolStats $command): void
    {
        $this->stats->save($command->schoolId, $this->calc->forSchool($command->schoolId));
    }
}

final class CommandBus
{
    /** @param array<class-string, class-string> $handlers */
    public function __construct(
        private \Psr\Container\ContainerInterface $container,
        private array $handlers,
    ) {}

    public function dispatch(object $command): mixed
    {
        if (!isset($this->handlers[$command::class])) {
            throw new LogicException('No handler for ' . $command::class);   // wiring bugs fail loudly
        }
        $handler = $this->handlers[$command::class];

        return DB::transaction(  // one place for shared rules
            fn () => $this->container->get($handler)->handle($command)
        );
    }
}

// Admin button, nightly schedule, after an import — the same line:
$bus->dispatch(new RecalculateSchoolStats($schoolId));

How Laravel builds it inside: Laravel's Bus Dispatcher: dispatch() puts a job on the queue if it implements ShouldQueue, otherwise runs it now. Every job passes through the same middleware first (rate limits, "don't run twice at once"), which is the "shared rules" idea below.
