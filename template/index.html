Template Method

BehaviourGoF book

A recipe card with blanks: the steps are printed, you fill in "filling".

The rule to rememberSeveral classes run the same steps in the same order, only some steps differ → parent locks the order, children fill the gaps.

Without it: the pain

3 importers copy the same 5 steps. A fix to validation is made in one and forgotten in the others.

With it: the fix

One parent with a final import(). Each importer only writes the 2 steps that differ.

Reach for it when you see

  • Several classes with near-identical methods, small differences inside
  • A bug fix that had to be copied to 3 classes
  • Someone skipped a step (validation, logging) in one copy

Real job where it fits

Grades arrive from 3 school systems: different file format and column names, same import process.

Before: the code that hurts

final class SystemAImport { public function import($file) { /* read, map, validate, save, log */ } }
final class SystemBImport { public function import($file) { /* read, map, validate, save, log */ } }
final class SystemCImport { public function import($file) { /* read, map, validate, save */ } }  // forgot log

Build it yourself: the full Template Method pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

Abstract classGradeImport owns the template method
Template methodimport ) (marked final: the order of steps can never change
Abstract stepsread ), map() (each child MUST write them
HookafterImport ) (has a default: a child MAY replace it
Concrete classesCsvGradeImport, JsonGradeImport
<?php

declare(strict_types=1);

// ── Step 1: the abstract class with the locked recipe ──
abstract class GradeImport  // Abstract class
{
    /** @var list<array{student: string, score: int}> */
    public array $saved = [];

    final public function import(string $source): void  // Template method: final = nobody can change the order
    {
        $rawRows = $this->read($source);                    // 1. read the file      (differs per system)

        foreach ($rawRows as $raw) {
            $row = $this->map($raw);                        // 2. rename the columns (differs per system)
            $this->validate($row);                          // 3. validate           (same for everyone)
            $this->saved[] = $row;                          // 4. save               (same for everyone)
        }

        $this->afterImport(count($rawRows));                // 5. a hook
    }

    /** @return list<array<int|string, string|int>> one raw row per item, as the file gives it */
    abstract protected function read(string $source): array;  // MUST be written by each child

    /**
     * @param array<int|string, string|int> $raw
     * @return array{student: string, score: int}
     */
    abstract protected function map(array $raw): array;  // MUST be written by each child

    protected function afterImport(int $count): void  // hook: MAY be replaced
    {
        echo get_class($this) . " imported {$count} rows\n";
    }

    /** @param array{student: string, score: int} $row */
    private function validate(array $row): void            // private: children cannot skip it
    {
        if ($row['score'] < 0 || $row['score'] > 100) {
            throw new InvalidArgumentException("Score must be 0-100, got {$row['score']}.");
        }
    }
}

// ── Step 2: concrete classes. Each writes only the steps that differ. ──
final class CsvGradeImport extends GradeImport  // Concrete class
{
    /** @return list<array<int|string, string|int>> */
    protected function read(string $source): array
    {
        $rows = [];
        foreach (explode("\n", trim($source)) as $line) {
            $rows[] = explode(',', $line);                  // "S-1,Math,88" becomes ['S-1', 'Math', '88']
        }

        return $rows;
    }

    /**
     * @param array<int|string, string|int> $raw
     * @return array{student: string, score: int}
     */
    protected function map(array $raw): array
    {
        return ['student' => $raw[0], 'score' => (int) $raw[2]];   // System A: score is the 3rd column
    }
}

final class JsonGradeImport extends GradeImport  // Concrete class
{
    /** @return list<array<int|string, string|int>> */
    protected function read(string $source): array
    {
        return json_decode($source, true);
    }

    /**
     * @param array<int|string, string|int> $raw
     * @return array{student: string, score: int}
     */
    protected function map(array $raw): array
    {
        return ['student' => $raw['name'], 'score' => (int) $raw['mark']];   // System B: different names
    }
}

// ── Using it ──
$csv = new CsvGradeImport();
$csv->import("S-1,Math,88\nS-2,Math,74");

$json = new JsonGradeImport();
$json->import('[{"name":"S-3","mark":91}]');

try {
    $bad = new CsvGradeImport();
    $bad->import('S-4,Math,140');
} catch (InvalidArgumentException $e) {
    echo 'Rejected: ' . $e->getMessage() . "\n";           // validation could not be skipped
}

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

abstract class GradeImport
{
    final public function import(string $path): int  // the locked recipe
    {
        $raw  = $this->read($path);                            // differs
        $rows = array_map(fn (array $r) => $this->map($r), $raw);  // differs
        $this->validate($rows);                                // same for all
        DB::transaction(fn () => Grade::insert($rows));        // same for all
        Log::info('grades.imported', ['source' => static::class, 'rows' => count($rows)]);
        return count($rows);
    }

    abstract protected function read(string $path): array;  // must fill in
    abstract protected function map(array $row): array;  // must fill in

    private function validate(array $rows): void
    {
        foreach ($rows as $i => $row) {
            if (! is_numeric($row['score']) || $row['score'] < 0 || $row['score'] > 100) {
                throw new InvalidImport("Row {$i}: score must be 0–100.");
            }
        }
    }
}

final class SystemAImport extends GradeImport
{
    protected function read(string $path): array { return array_map('str_getcsv', file($path)); }
    protected function map(array $row): array    { return ['student_id' => $row[0], 'score' => $row[2]]; }
}

How Laravel builds it inside: Form requests. Laravel always runs the same steps in the same order: prepareForValidation(), then your authorize(), then validation with your rules(), then passedValidation(). You only write rules() and authorize(), and may override the two hooks.
