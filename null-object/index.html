Null Object

BehaviourNot in the book

A muted microphone: the meeting runs normally, your mic just sends nothing.

The rule to remember"Nothing" is a NORMAL case (no coupon, no logger) → pass an object that safely does nothing, instead of null.

Without it: the pain

if ($coupon !== null) is copied in the order, invoice, receipt and report. One place forgot: "Call to a member function on null".

With it: the fix

NoDiscount returns the total unchanged. Everyone just calls apply(). There is nothing to forget.

Reach for it when you see

  • The same null check in many places
  • "Call to a member function … on null" in your logs
  • An optional collaborator (logger, discount, notifier)

Real job where it fits

Checkout with an optional coupon. The discount is used by the order, the invoice, the receipt and the reports.

Before: the code that hurts

// copied in Order, Invoice, Receipt, MonthlyReport:
$total = $coupon !== null ? $coupon->apply($subtotal) : $subtotal;

// MonthlyReport forgot the check:
$total = $coupon->apply($subtotal);   // Error: Call to a member function apply() on null

Build it yourself: the full Null Object pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

Abstract objectDiscount the interface the caller depends on
Real objectPercentageCoupon does real work
Null objectNoDiscount same interface, safely does nothing
ClientCheckout calls apply() without ever checking for null
<?php

declare(strict_types=1);

// ── Step 1: the interface the caller depends on ──
interface Discount  // Abstract object
{
    public function apply(int $subtotal): int;

    public function label(): string;
}

// ── Step 2: the real object ──
final class PercentageCoupon implements Discount            // Real object
{
    public function __construct(private readonly string $code, private readonly int $percent)
    {
    }

    public function apply(int $subtotal): int
    {
        return (int) round($subtotal * (100 - $this->percent) / 100);
    }

    public function label(): string
    {
        return "{$this->code} (-{$this->percent}%)";
    }
}

// ── Step 3: the null object. Same interface, does nothing, never crashes. ──
final class NoDiscount implements Discount  // Null object
{
    public function apply(int $subtotal): int
    {
        return $subtotal;  // returns the total unchanged
    }

    public function label(): string
    {
        return 'no coupon';
    }
}

// ── Step 4: the client. No "if ($discount !== null)" anywhere. ──
final class Checkout  // Client
{
    public function __construct(private readonly Discount $discount)
    {
    }

    public function total(int $subtotal): string
    {
        $total = $this->discount->apply($subtotal);  // always safe to call

        return ($total / 100) . ' EGP (' . $this->discount->label() . ')';
    }
}

// ── Using it: decide ONCE, where the coupon is read ──
function discountFor(?string $coupon): Discount
{
    if ($coupon === null || $coupon === '') {
        return new NoDiscount();                            // "no coupon" is a normal case
    }

    if ($coupon === 'STUDENT') {
        return new PercentageCoupon('STUDENT', 10);
    }

    throw new InvalidArgumentException("Unknown coupon [{$coupon}].");   // a WRONG coupon is an error, not "nothing"
}

$withCoupon = new Checkout(discountFor('STUDENT'));
$withoutCoupon = new Checkout(discountFor(null));

echo $withCoupon->total(20000) . "\n";
echo $withoutCoupon->total(20000) . "\n";

// Never use a Null Object where "missing" is a bug: no payment method must throw,
// not silently charge nothing.

Highlighted lines are the ones that make it this pattern. Run it: php examples/null-object.php · Open the file on GitHub

Output
180 EGP (STUDENT (-10%))
200 EGP (no coupon)

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

interface Discount
{
    public function apply(Money $subtotal): Money;
}

final class NoDiscount implements Discount
{
    public function apply(Money $subtotal): Money
    {
        return $subtotal;  // does nothing, safely
    }
}

final class CouponDiscount implements Discount { /* percentage, expiry, limits */ }

// Decided ONCE, where the request is read:
$discount = $request->filled('coupon')
    ? $coupons->findValidOrFail($request->input('coupon'))   // a wrong coupon = 422, never ignored
    : new NoDiscount();  // "no coupon" is normal

// Order, Invoice, Receipt, Report — no null checks anywhere:
$total = $discount->apply($cart->subtotal());

// ✗ Never use it for something whose absence is a BUG:
//   no payment method → throw, don't pass a "NoPayment" that charges nothing.

How Laravel builds it inside: Laravel ships several null objects: the "null" cache driver (NullStore), the "null" broadcaster and the "null" log channel. Choosing one in config turns a feature off without a single if in your code.
