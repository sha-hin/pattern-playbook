Composite

StructureGoF book

Folders and files: a folder's size is the sum of what's inside, and folders can hold folders.

The rule to rememberYour data is a tree (parts inside wholes, any depth) → items and groups share one interface; a group asks its children.

Without it: the pain

Every function over the survey checks "is this a section or a question?" and recurses by hand.

With it: the fix

Section and Question both answer maxScore(). A section just asks its children. Depth stops mattering.

Reach for it when you see

  • instanceof checks to tell a group from an item
  • Recursive functions copied for every calculation
  • "Groups can contain groups" in the requirements

Real job where it fits

A survey has sections, sub-sections and questions. You need the max score, the question count, the rendering.

Before: the code that hurts

function maxScore(array $nodes): int {
    $total = 0;
    foreach ($nodes as $node) {
        if ($node instanceof Section) { $total += maxScore($node->children); }   // and again in
        else { $total += $node->points; }                                        // countQuestions(),
    }                                                                            // render(), export()...
    return $total;
}

Build it yourself: the full Composite pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

ComponentSurveyNode one interface for single items AND groups
LeafQuestion has no children
CompositeSection holds SurveyNodes, which can be Questions or other Sections
Clientcode that calls maxScore() on the top node, whatever the depth
<?php

declare(strict_types=1);

// ── Step 1: the Component. One interface for items and groups. ──
interface SurveyNode  // Component
{
    public function maxScore(): int;

    public function show(string $indent): void;
}

// ── Step 2: the Leaf. A single question. ──
final class Question implements SurveyNode  // Leaf
{
    public function __construct(private readonly string $text, private readonly int $points)
    {
    }

    public function maxScore(): int
    {
        return $this->points;                               // a leaf just answers
    }

    public function show(string $indent): void
    {
        echo "{$indent}- {$this->text} ({$this->points} pts)\n";
    }
}

// ── Step 3: the Composite. A section that holds questions OR other sections. ──
final class Section implements SurveyNode  // Composite
{
    /** @var list<SurveyNode> */
    private array $children = [];

    public function __construct(private readonly string $title)
    {
    }

    public function add(SurveyNode $node): static  // accepts a Question or a Section
    {
        $this->children[] = $node;

        return $this;
    }

    public function maxScore(): int
    {
        $total = 0;
        foreach ($this->children as $child) {
            $total += $child->maxScore();  // just ask each child; no instanceof
        }

        return $total;
    }

    public function show(string $indent): void
    {
        echo "{$indent}{$this->title}\n";
        foreach ($this->children as $child) {
            $child->show($indent . '  ');
        }
    }
}

// ── Using it: a tree of any depth ──
$timeManagement = new Section('Time management');
$timeManagement->add(new Question('Starts on time', 3));
$timeManagement->add(new Question('Finishes the plan', 2));

$classroom = new Section('Classroom');
$classroom->add(new Question('Explains clearly', 5));
$classroom->add($timeManagement);                           // a section inside a section

$survey = new Section('Teacher evaluation');
$survey->add($classroom);
$survey->add(new Question('Overall rating', 10));

$survey->show('');
echo 'Max score: ' . $survey->maxScore() . "\n";           // 20, counted through every level

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

interface SurveyNode  // one shape for items and groups
{
    public function maxScore(): int;
}

final class Question implements SurveyNode                // a leaf
{
    public function __construct(public readonly string $text, private int $points) {}
    public function maxScore(): int { return $this->points; }
}

final class Section implements SurveyNode                 // a group of nodes
{
    /** @var list<SurveyNode> */
    private array $children = [];

    public function __construct(public readonly string $title) {}

    public function add(SurveyNode $node): self { $this->children[] = $node; return $this; }

    public function maxScore(): int
    {
        return array_sum(array_map(
            fn (SurveyNode $child) => $child->maxScore(),  // no instanceof: just ask
            $this->children,
        ));
    }
}

$survey = (new Section('Teacher evaluation'))
    ->add((new Section('Classroom'))
        ->add(new Question('Explains clearly', 5))
        ->add(new Question('Manages time', 5)))
    ->add(new Question('Overall', 10));

$survey->maxScore();   // 20, at any depth

How Laravel builds it inside: Nested where groups in the query builder. where(function ($q) { ... }) stores a whole group as ONE condition, and when the SQL is built, a group compiles its own conditions inside brackets. Groups can hold groups: "status = ? and (total > ? or vip = ?)".
