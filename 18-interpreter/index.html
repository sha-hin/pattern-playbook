“Show Q5 only if Q3 ≥ 4 and the role is teacher”

Interpreter

New ticket

Follow-up questions that only some people see

From Mona Saleh, Head of Quality

If a student rates punctuality 2 or lower, ask them what would help. Only peers who rated the explanations 4 or higher should be asked about co-teaching. The principal gets a question only when something is low. We want to type these rules in the survey editor ourselves, for example: role = "peer" and q1 >= 4.

Why the quick fix is a trap

Without a rule language, each rule is PHP code that a developer writes and deploys:

the quick fix (we won’t do this)
function isVisible(string $code, array $answers, RespondentRole $role): bool
{
    if ($code === 'q7') return ($answers['q4'] ?? 99) <= 2;
    if ($code === 'q8') return $role === RespondentRole::Peer && ($answers['q1'] ?? 0) >= 4;
    if ($code === 'q9') return $role === RespondentRole::Principal && (/* ... */);
    // every new survey, every changed threshold: a ticket, a developer, a deploy
    return true;
}

The rules belong to the quality team, but they live in code only developers can change. The function grows with every survey and mixes the rules of all surveys.

The rules form a small language: comparisons joined with and, or, not and brackets. If we represent each sentence of that language as a tree of objects, the tree can evaluate itself.

The pattern: Interpreter

Remember itUsers need to express rules in a small language → represent each grammar rule as a class, build a tree of those objects from the text, and let the tree evaluate itself.

Each piece of the language is a class with one job: Comparison (q1 >= 4), AllOf (and), AnyOf (or), Not, and the operands AnswerTo (q1), Role and Literal (4, "peer"). Each one knows how to evaluate itself against a RuleContext (the answers so far and the respondent’s role). That tree of classes is the Interpreter pattern.

RuleParser turns the text into the tree. It is not part of the pattern, but you need one for users to type rules. Ours is a small recursive-descent parser: one method per grammar level, so and binds tighter than or, exactly as in PHP.

Use Interpreter for small languages like this one. For anything bigger, use an existing engine (Symfony ExpressionLanguage, JSON Logic) instead of growing your own.

  7. 7A comparison

    An unanswered question makes every comparison false, so a follow-up never appears because of a missing answer.

    src/Survey/Rules/Comparison.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey\Rules;

/**
 * `left OP right`, with OP one of = != < <= > >=.
 * An unknown value (an unanswered question) makes every comparison false.
 */
final readonly class Comparison implements Condition
{
    public const OPERATORS = ['=', '!=', '<', '<=', '>', '>='];

    public function __construct(
        private Operand $left,
        private string $operator,
        private Operand $right,
    ) {
        if (!in_array($operator, self::OPERATORS, true)) {
            throw new InvalidRule("Unknown operator \"{$operator}\".");
        }
    }

    public function isTrue(RuleContext $context): bool
    {
        $left = $this->left->valueIn($context);
        $right = $this->right->valueIn($context);

        if ($left === null || $right === null) {
            return false;
        }

        return match ($this->operator) {
            '=' => $left === $right,
            '!=' => $left !== $right,
            '<' => $left < $right,
            '<=' => $left <= $right,
            '>' => $left > $right,
            '>=' => $left >= $right,
        };
    }

    public function describe(): string
    {
        return "{$this->left->describe()} {$this->operator} {$this->right->describe()}";
    }
}

  8. 8and

    src/Survey/Rules/AllOf.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey\Rules;

/** `a and b`: true when every part is true. */
final readonly class AllOf implements Condition
{
    /** @var list<Condition> */
    private array $conditions;

    public function __construct(Condition ...$conditions)
    {
        $this->conditions = array_values($conditions);
    }

    public function isTrue(RuleContext $context): bool
    {
        foreach ($this->conditions as $condition) {
            if (!$condition->isTrue($context)) {
                return false;
            }
        }

        return true;
    }

    public function describe(): string
    {
        return '(' . implode(' and ', array_map(fn (Condition $c): string => $c->describe(), $this->conditions)) . ')';
    }
}

  12. 12The parser: text → tree

    tokenize() cuts the text into words, numbers, strings and operators. Then one method per level of the grammar: parseOr() calls parseAnd(), which calls parseUnary(). Because or is handled at the outermost level, and binds tighter. Every error names the position in the rule.

    src/Survey/Rules/RuleParser.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Survey\Rules;

/**
 * Turns the text an admin types into a tree of Condition objects.
 *
 * The grammar, from loosest to tightest binding:
 *
 *     rule       := and ( "or" and )*
 *     and        := unary ( "and" unary )*
 *     unary      := "not" unary | "(" rule ")" | comparison
 *     comparison := operand ( "=" | "!=" | "<" | "<=" | ">" | ">=" ) operand
 *     operand    := q1, q2...  |  role  |  a whole number  |  "text in quotes"
 *
 * The parser is not the pattern; it only builds the tree. The Interpreter pattern is the
 * tree itself: each class knows how to evaluate its own small piece of the language.
 */
final class RuleParser
{
    /** @var list<array{type: string, text: string, at: int}> */
    private array $tokens = [];
    private int $position = 0;
    private string $source = '';

    public function parse(string $rule): Condition
    {
        $this->source = $rule;
        $this->tokens = $this->tokenize($rule);
        $this->position = 0;

        $condition = $this->parseOr();

        if ($this->position < count($this->tokens)) {
            $this->fail('Unexpected "' . $this->tokens[$this->position]['text'] . '"');
        }

        return $condition;
    }

    private function parseOr(): Condition
    {
        $parts = [$this->parseAnd()];
        while ($this->accept('word', 'or')) {
            $parts[] = $this->parseAnd();
        }

        return count($parts) === 1 ? $parts[0] : new AnyOf(...$parts);
    }

    private function parseAnd(): Condition
    {
        $parts = [$this->parseUnary()];
        while ($this->accept('word', 'and')) {
            $parts[] = $this->parseUnary();
        }

        return count($parts) === 1 ? $parts[0] : new AllOf(...$parts);
    }

    private function parseUnary(): Condition
    {
        if ($this->accept('word', 'not')) {
            return new Not($this->parseUnary());
        }

        if ($this->accept('(')) {
            $inner = $this->parseOr();
            if (!$this->accept(')')) {
                $this->fail('Missing ")"');
            }

            return $inner;
        }

        $left = $this->parseOperand();
        $operator = $this->next('operator', 'a comparison (=, !=, <, <=, >, >=)');
        $right = $this->parseOperand();

        return new Comparison($left, $operator, $right);
    }

    private function parseOperand(): Operand
    {
        $token = $this->tokens[$this->position] ?? null;
        if ($token === null) {
            $this->fail('The rule ends too early');
        }
        $this->position++;

        return match (true) {
            $token['type'] === 'number' => new Literal((int) $token['text']),
            $token['type'] === 'string' => new Literal(stripcslashes(substr($token['text'], 1, -1))),
            $token['type'] === 'word' && $token['text'] === 'role' => new Role(),
            $token['type'] === 'word' && preg_match('/^q\d+$/', $token['text']) === 1 => new AnswerTo($token['text']),
            default => $this->fail("Expected a question code (q1), role, a number or \"text\", got \"{$token['text']}\"", $token['at']),
        };
    }

    /** @return list<array{type: string, text: string, at: int}> */
    private function tokenize(string $rule): array
    {
        preg_match_all(
            '/\s*(?:(?<number>\d+)|(?<string>"(?:\\\\.|[^"\\\\])*")|(?<operator><=|>=|!=|=|<|>)|(?<word>[A-Za-z_]\w*)|(?<paren>[()])|(?<bad>\S))/',
            $rule,
            $matches,
            PREG_SET_ORDER | PREG_OFFSET_CAPTURE | PREG_UNMATCHED_AS_NULL,
        );

        $tokens = [];
        foreach ($matches as $match) {
            foreach (['number', 'string', 'operator', 'word', 'paren', 'bad'] as $type) {
                if ($match[$type][0] === null) {
                    continue;
                }
                [$text, $at] = $match[$type];
                if ($type === 'bad') {
                    $this->fail("Unexpected character \"{$text}\"", $at);
                }
                $tokens[] = ['type' => $type === 'paren' ? $text : $type, 'text' => $type === 'word' ? strtolower($text) : $text, 'at' => $at];
                break;
            }
        }

        return $tokens;
    }

    private function accept(string $type, ?string $text = null): bool
    {
        $token = $this->tokens[$this->position] ?? null;
        if ($token !== null && $token['type'] === $type && ($text === null || $token['text'] === $text)) {
            $this->position++;

            return true;
        }

        return false;
    }

    private function next(string $type, string $expected): string
    {
        $token = $this->tokens[$this->position] ?? null;
        if ($token === null || $token['type'] !== $type) {
            $this->fail("Expected {$expected}", $token['at'] ?? null);
        }
        $this->position++;

        return $token['text'];
    }

    private function fail(string $message, ?int $at = null): never
    {
        $at ??= $this->tokens[$this->position]['at'] ?? strlen($this->source);
        throw new InvalidRule("{$message} at position " . ($at + 1) . " in: {$this->source}");
    }
}

  14. 14Rules typed by the quality team

    bin/survey-rules.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * Evalu8, chapter 18: admins write "show this question if..." rules as text.
 *
 *     composer dump-autoload
 *     php bin/survey-rules.php
 */

require __DIR__ . '/../vendor/autoload.php';

use Evalu8\Domain\RespondentRole;
use Evalu8\Survey\AnswerSheet;
use Evalu8\Survey\Question;
use Evalu8\Survey\Rules\InvalidRule;
use Evalu8\Survey\Rules\RuleContext;
use Evalu8\Survey\Rules\RuleParser;

$parser = new RuleParser();

// Follow-up questions, with the rules the quality team typed in the survey editor.
$followUps = [
    new Question('q7', 'What would help this teacher start on time?', visibleIf: $parser->parse('q4 <= 2')),
    new Question('q8', 'As a colleague: would you co-teach with them?', visibleIf: $parser->parse('role = "peer" and q1 >= 4')),
    new Question('q9', 'What should the principal discuss with them?', visibleIf: $parser->parse('role = "principal" and (q1 < 3 or q3 < 3)')),
    new Question('q10', 'Anything else?', visibleIf: $parser->parse('not role = "student" or q6 <= 2')),
];

echo "RULES, AS UNDERSTOOD\n";
foreach ($followUps as $question) {
    echo "  {$question->code}: {$question->visibleIf?->describe()}\n";
}

$respondents = [
    'a student' => new RuleContext(AnswerSheet::fromArray(['q1' => 5, 'q3' => 4, 'q4' => 2, 'q6' => 4]), RespondentRole::Student),
    'a peer' => new RuleContext(AnswerSheet::fromArray(['q1' => 4, 'q3' => 4, 'q4' => 5, 'q6' => 5]), RespondentRole::Peer),
    'the principal' => new RuleContext(AnswerSheet::fromArray(['q1' => 2, 'q3' => 4, 'q4' => 3, 'q6' => 3]), RespondentRole::Principal),
];

echo "\nWHO SEES WHICH FOLLOW-UP\n";
foreach ($respondents as $who => $context) {
    $shown = [];
    foreach ($followUps as $question) {
        if ($question->isVisibleTo($context)) {
            $shown[] = $question->code;
        }
    }
    echo '  ' . str_pad($who, 15) . (count($shown) > 0 ? implode(', ', $shown) : 'none') . "\n";
}

echo "\nTYPOS ARE CAUGHT WHEN THE RULE IS SAVED\n";
foreach (['q3 => 4', 'role = "peer" and', 'q3 >= 4 and (role = "peer"', 'score >= 4'] as $rule) {
    try {
        $parser->parse($rule);
    } catch (InvalidRule $e) {
        echo "  {$e->getMessage()}\n";
    }
}

How Laravel does it

Laravel has no rule-language component, but the Symfony ExpressionLanguage component (installable in any Laravel app) is a production-grade interpreter: it parses expressions into a tree of node objects and evaluates them, with caching of parsed rules.

Laravel
use Symfony\Component\ExpressionLanguage\ExpressionLanguage;

$language = new ExpressionLanguage();

$visible = $language->evaluate('role == "peer" and q1 >= 4', [
    'role' => 'peer',
    'q1' => 5,
]);   // true

Answer in your head, then open the answer.

Which part is the Interpreter pattern: the parser or the classes like Comparison and AllOf?

The classes. Each one represents one rule of the grammar and evaluates itself. The parser only builds the tree.

Why does a or b and c mean a or (b and c)?

The parser handles or at the outermost level and and one level deeper, so and groups first.

Why is an unanswered question treated as "false" in every comparison?

So a follow-up question can’t appear because an answer is missing, whatever the operator.
