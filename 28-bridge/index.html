Three notification types × four channels

Bridge

New ticket

Notifications over email, SMS, WhatsApp and in the app

From Ahmed Nabil, Product Owner

We send three notifications: results published (to teachers), low response rate (to principals) and survey reminders (to students and parents). Each user picks a channel in their profile: email, SMS, WhatsApp or the in-app inbox. Next quarter we add push notifications and one more notification type.

Why the quick fix is a trap

The first version made one class per notification per channel:

the quick fix (we won’t do this)
final class ResultsPublishedEmail { /* text + SMTP code */ }
final class ResultsPublishedSms { /* text again + SMS gateway code */ }
final class ResultsPublishedWhatsApp { /* text again + WhatsApp code */ }
final class LowResponseRateEmail { /* ... */ }
// ... 3 notifications × 4 channels = 12 classes
// next quarter: 4 × 5 = 20 classes

Every class mixes two unrelated things: the wording of one notification and the delivery code of one channel. A change to the SMS gateway touches three classes; a new notification needs four. The number of classes is the product of the two lists, and it grows every time either list grows.

There are two independent dimensions here: what to say and how to deliver it. Each should vary without touching the other.

The pattern: Bridge

Remember itTwo things vary independently (what × how) → split them into two class trees and connect them with one reference, so you write their sum, not their product.

The abstraction side says what to say: Notification, with ResultsPublished, LowResponseRate and SurveyReminder. The implementor side says how to deliver: the Channel interface, with EmailChannel, SmsChannel, WhatsAppChannel and InAppChannel.

A notification holds a channel. That single reference is the bridge. send() asks the notification for its Message and hands it to whatever channel it holds. Three notifications plus four channels is seven classes, and every combination works.

Bridge looks like Strategy from chapter 3 (an object holding an interface). The difference is intent: Strategy swaps one algorithm inside one class; Bridge separates two whole hierarchies that both keep growing.

  2. 2What is said, in two lengths

    Email and the inbox show the full text; SMS and WhatsApp need a short one. The 160-character limit is checked when the message is created, not by the SMS gateway at 2 a.m.

    src/Notify/Message.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Notify;

use InvalidArgumentException;

/**
 * What to say, in two lengths: a full version (email, in-app) and a short one (SMS, WhatsApp).
 */
final readonly class Message
{
    public const SHORT_LIMIT = 160;                         // one SMS segment

    public function __construct(
        public string $subject,
        public string $body,
        public string $short,
    ) {
        if (mb_strlen($short) > self::SHORT_LIMIT) {
            throw new InvalidArgumentException('The short text is ' . mb_strlen($short) . ' characters; the limit is ' . self::SHORT_LIMIT . '.');
        }
    }
}

namespace Evalu8\Notify;

/**
 * The Implementor side of the Bridge: HOW a message is delivered.
 * A channel knows nothing about which notification it carries.
 */
interface Channel
{
    public function name(): string;

    /**
     * @throws ChannelUnavailable when the recipient can't be reached on this channel
     */
    public function deliver(Recipient $to, Message $message): void;
}

  5. 5Channel: email

    It reuses the Mailer from chapter 6.

    src/Notify/EmailChannel.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Notify;

use Evalu8\Mail\Mailer;

final readonly class EmailChannel implements Channel
{
    public function __construct(private Mailer $mailer)
    {
    }

    public function name(): string
    {
        return 'email';
    }

    public function deliver(Recipient $to, Message $message): void
    {
        if ($to->email === null) {
            throw ChannelUnavailable::missing('email', $to, 'email address');
        }

        $this->mailer->send($to->email, $message->subject, $message->body);
    }
}

  10. 10The abstraction: what to say

    It holds a Channel (the bridge). send() is final: every notification is delivered the same way, and each subclass only writes its message.

    src/Notify/Notification.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Notify;

/**
 * The Abstraction side of the Bridge: WHAT to say. It holds a Channel, and that reference
 * is the bridge: any notification can travel over any channel.
 */
abstract class Notification
{
    public function __construct(protected readonly Channel $channel)
    {
    }

    final public function send(Recipient $to): void
    {
        $this->channel->deliver($to, $this->message($to));
    }

    abstract protected function message(Recipient $to): Message;
}

  14. 14Find a channel by the name in a user’s profile

    src/Notify/Channels.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Notify;

use InvalidArgumentException;

/**
 * Finds a channel by the name a user picked in their preferences ("sms", "email"...).
 */
final readonly class Channels
{
    /** @var array<string, Channel> */
    private array $byName;

    public function __construct(Channel ...$channels)
    {
        $byName = [];
        foreach ($channels as $channel) {
            $byName[$channel->name()] = $channel;
        }
        $this->byName = $byName;
    }

    public function named(string $name): Channel
    {
        return $this->byName[$name] ?? throw new InvalidArgumentException(
            "Unknown channel \"{$name}\". Available: " . implode(', ', array_keys($this->byName)) . '.'
        );
    }
}

  16. 16Send each notification over the channel each person chose

    bin/notify.phpnew fileGitHub
    <?php

declare(strict_types=1);

/*
 * Evalu8, chapter 28: any notification over any channel, with one class per side.
 *
 *     composer dump-autoload
 *     php bin/notify.php
 */

use Evalu8\Container\Container;
use Evalu8\Domain\EmailAddress;
use Evalu8\Notify\ChannelUnavailable;
use Evalu8\Notify\Channels;
use Evalu8\Notify\LowResponseRate;
use Evalu8\Notify\Recipient;
use Evalu8\Notify\ResultsPublished;
use Evalu8\Notify\SurveyReminder;

/** @var Container $app */
$app = require __DIR__ . '/../bootstrap/app.php';
$channels = $app->make(Channels::class);
$db = $app->make(PDO::class);

$hany = new Recipient('teacher-1', 'Hany Mostafa', new EmailAddress('hany@smouha.edu.eg'), '+201001234567');
$nadia = new Recipient('teacher-2', 'Nadia Fawzy', null, '+201117654321');
$principal = new Recipient('principal-smouha', 'Mrs. Amal Kamel', new EmailAddress('amal@smouha.edu.eg'));
$student = new Recipient('student-88', 'Youssef', null, '+201550000088');

// Each person's preferred channel comes from their profile. The notification classes don't care.
echo "RESULTS PUBLISHED\n";
(new ResultsPublished($channels->named('email'), '2026-T1', '4.13'))->send($hany);
(new ResultsPublished($channels->named('whatsapp'), '2026-T1', '2.70'))->send($nadia);

echo "\nLOW RESPONSE RATE\n";
(new LowResponseRate($channels->named('email'), 'Laila Samir', 2, 5))->send($principal);
(new LowResponseRate($channels->named('in-app'), 'Laila Samir', 2, 5))->send($principal);

echo "\nSURVEY REMINDER\n";
(new SurveyReminder($channels->named('sms'), 'Teacher evaluation 2026-T1', '20 Nov'))->send($student);

echo "\nUNREACHABLE ON THE CHOSEN CHANNEL\n";
try {
    (new SurveyReminder($channels->named('email'), 'Teacher evaluation 2026-T1', '20 Nov'))->send($student);
} catch (ChannelUnavailable $e) {
    echo "Not sent: {$e->getMessage()}\n";                // loud, so the reminder can go by SMS instead
}

echo "\nIN-APP INBOX\n";
foreach ($db->query('SELECT user_id, subject FROM inbox ORDER BY id')->fetchAll(PDO::FETCH_ASSOC) as $row) {
    echo "{$row['user_id']}: {$row['subject']}\n";
}

How Laravel does it

Laravel Notifications have the same two sides. Your notification class says what to send and lists its channels in via(); each channel class (mail, database, vonage, slack…) knows how to deliver. Any notification can use any channel.

One difference: in Laravel the notification formats itself for each channel (toMail(), toVonage()), so a new channel means a new method in the notifications that use it. Here a channel only needs the shared Message.

Laravel
final class ResultsPublished extends Notification
{
    public function __construct(private string $term, private string $score) {}

    /** @return list<string> */
    public function via(User $user): array
    {
        return [$user->preferred_channel];                 // 'mail', 'vonage', 'database'...
    }

    public function toMail(User $user): MailMessage
    {
        return (new MailMessage())
            ->subject("Your {$this->term} evaluation result")
            ->line("Your result is {$this->score}.");
    }

    public function toVonage(User $user): VonageMessage
    {
        return (new VonageMessage())->content("Your {$this->term} result is {$this->score}.");
    }
}

$teacher->notify(new ResultsPublished('2026-T1', '4.13'));

How is Bridge different from Strategy?

Strategy swaps one algorithm inside one class. Bridge separates two hierarchies that both grow, so their combinations don’t multiply into classes.
