Survey editor parts keep changing each other

Mediator

New ticket

The editor let me save a scored comment question

From Mona Saleh, Head of Quality

I changed a question to "comment" and the "count in score" box stayed ticked, so the report tried to average text. Another time I changed the scale to 1–7 and the preview still showed 1–5. The rules are simple: comments are never scored, scored questions use 1–5, the preview always shows the current question.

Why the quick fix is a trap

Each field was written to update the fields it affects:

the quick fix (we won’t do this)
final class QuestionTypeField
{
    public function __construct(
        private ScaleField $scale,
        private ScoredCheckbox $scored,
        private PreviewPanel $preview,
        private ValidationPanel $validation,
    ) {}

    public function choose(QuestionType $type): void
    {
        $this->value = $type;
        $this->scale->enabled = $type === QuestionType::Scale;
        $this->scored->enabled = $type !== QuestionType::Text;   // forgot to untick it
        $this->preview->render(/* ... */);
        $this->validation->check(/* ... */);
    }
}
// ScaleField, ScoredCheckbox and QuestionTextField each do the same with the others.

Every field knows every other field: six fields means up to thirty connections, and each rule ("comments are never scored") is split across several classes. The bug in the ticket is one of those pieces missing. Adding a field means editing all the others.

The fields shouldn’t talk to each other at all. They should report "I changed" to one object that knows the rules.

The pattern: Mediator

Remember itMany objects affect each other → they stop talking to each other and talk to one mediator, which holds every rule about how they interact.

Each field (a colleague) knows only the mediator. When the user changes it, it calls $mediator->changed($this). It doesn’t know that a scale, a checkbox or a preview exist.

QuestionEditor is the mediator. It creates the fields, and in changed() it applies every rule: what a type change enables or disables, then the preview and the list of problems. Each rule is written once, in one place, and the ticket’s bug becomes one line in one method.

The event dispatcher from chapter 22 is also a mediator, for the whole app: senders and listeners never know each other. This chapter’s mediator is the classic, local kind: one small group of objects with rules that are specific to them.

  3. 3The colleague base class

    A field holds its mediator and notifies it. If someone forgets to attach a field, it fails at once instead of silently ignoring the change.

    src/Editor/Field.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Editor;

use LogicException;

/**
 * A Colleague: one part of the question editor. It knows its mediator, nothing else.
 */
abstract class Field
{
    private ?EditorMediator $mediator = null;

    public bool $enabled = true;

    public function attach(EditorMediator $mediator): void
    {
        $this->mediator = $mediator;
    }

    /** Called by every setter after the user changes the field. */
    protected function notifyChanged(): void
    {
        if ($this->mediator === null) {
            throw new LogicException(static::class . ' is not attached to an editor.');
        }

        $this->mediator->changed($this);
    }
}

  10. 10The mediator: every rule in one place

    applyType() holds the enable/disable rules, including the line the old code forgot: a comment question unticks "scored". problems() holds the validation rules. refresh() runs after every change.

    src/Editor/QuestionEditor.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Editor;

/**
 * The concrete Mediator: every rule about how the editor's fields affect each other is here,
 * in one class, instead of being spread over the fields.
 */
final class QuestionEditor implements EditorMediator
{
    public const MAX_SCALE = 10;

    public readonly QuestionTextField $text;
    public readonly QuestionTypeField $type;
    public readonly ScaleField $scale;
    public readonly ScoredCheckbox $scored;
    public readonly PreviewPanel $preview;
    public readonly ValidationPanel $validation;

    public function __construct()
    {
        $this->text = new QuestionTextField();
        $this->type = new QuestionTypeField();
        $this->scale = new ScaleField();
        $this->scored = new ScoredCheckbox();
        $this->preview = new PreviewPanel();
        $this->validation = new ValidationPanel();

        foreach ([$this->text, $this->type, $this->scale, $this->scored, $this->preview, $this->validation] as $field) {
            $field->attach($this);
        }

        $this->refresh();
    }

    public function changed(Field $field): void
    {
        if ($field === $this->type) {
            $this->applyType();                             // only a type change enables or disables fields
        }

        $this->refresh();                                   // every change updates the preview and the problems
    }

    private function applyType(): void
    {
        switch ($this->type->value) {
            case QuestionType::Scale:
                $this->scale->enabled = true;
                $this->scored->enabled = true;
                break;
            case QuestionType::YesNo:
                $this->scale->enabled = false;              // the "scale" is fixed: yes or no
                $this->scored->enabled = true;
                break;
            case QuestionType::Text:
                $this->scale->enabled = false;
                $this->scored->enabled = false;
                $this->scored->checked = false;             // a comment can never count in a score
                break;
        }
    }

    private function refresh(): void
    {
        $this->preview->show($this->renderPreview());
        $this->validation->show($this->problems());
    }

    private function renderPreview(): string
    {
        $question = $this->text->value === '' ? '(no text yet)' : $this->text->value;

        return match ($this->type->value) {
            QuestionType::Scale => "{$question}  [1 … {$this->scale->max}]",
            QuestionType::YesNo => "{$question}  [Yes] [No]",
            QuestionType::Text => "{$question}  [__________]",
        };
    }

    /** @return list<string> */
    private function problems(): array
    {
        $problems = [];

        if ($this->text->value === '') {
            $problems[] = 'The question needs a text.';
        }
        if ($this->scale->enabled && ($this->scale->max < 2 || $this->scale->max > self::MAX_SCALE)) {
            $problems[] = 'The scale must end between 2 and ' . self::MAX_SCALE . '.';
        }
        if ($this->scored->checked && $this->type->value === QuestionType::Scale && $this->scale->max !== 5) {
            $problems[] = 'Scored questions must use the 1–5 scale, or teachers’ scores can’t be compared.';
        }

        return $problems;
    }
}

declare(strict_types=1);

/*
 * Evalu8, chapter 29: the question editor's fields talk only to the editor.
 *
 *     composer dump-autoload
 *     php bin/editor.php
 */

require __DIR__ . '/../vendor/autoload.php';

use Evalu8\Editor\QuestionEditor;
use Evalu8\Editor\QuestionType;

function screen(string $action, QuestionEditor $editor): void
{
    $onOff = fn (bool $enabled): string => $enabled ? 'on' : 'off';

    echo "\n> {$action}\n";
    echo "  preview: {$editor->preview->html}\n";
    echo "  scale: 1–{$editor->scale->max} ({$onOff($editor->scale->enabled)})"
        . '   scored: ' . ($editor->scored->checked ? 'yes' : 'no') . " ({$onOff($editor->scored->enabled)})\n";
    echo '  problems: ' . ($editor->validation->problems === [] ? 'none, Save is enabled' : implode(' | ', $editor->validation->problems)) . "\n";
}

$editor = new QuestionEditor();
screen('Open the editor', $editor);

$editor->text->type('Explains the lesson clearly');
screen('Type the question', $editor);

$editor->scale->setMax(7);
screen('Change the scale to 1–7', $editor);

$editor->type->choose(QuestionType::Text);
screen('Make it a comment question', $editor);

$editor->type->choose(QuestionType::Scale);
$editor->scale->setMax(5);
$editor->scored->toggle(true);
screen('Back to a scored 1–5 scale', $editor);

How Laravel does it

On the server, Laravel’s event dispatcher is the app-wide mediator (chapter 22). In a Livewire form, the parent component plays the role of this chapter’s mediator: child components dispatch events, and the parent applies the rules and updates the others.

Laravel
// Child component: only reports what happened
final class QuestionTypeSelect extends Component
{
    public string $type = 'scale';

    public function updatedType(): void
    {
        $this->dispatch('type-changed', type: $this->type);
    }
}

// Parent component: the mediator, the only place with the rules
final class QuestionEditor extends Component
{
    public bool $scaleEnabled = true;
    public bool $scored = true;

    #[On('type-changed')]
    public function applyType(string $type): void
    {
        $this->scaleEnabled = $type === 'scale';
        if ($type === 'text') {
            $this->scored = false;
        }
    }
}

Check yourself

Answer in your head, then open the answer.

A new field, "required question", must be disabled for comment questions. What changes?

A new RequiredCheckbox field, and one line in QuestionEditor::applyType(). No other field changes.

Where would you look to find every rule about how the fields affect each other?

Only in QuestionEditor. The fields contain no rules about each other.

What is the risk of a mediator, and how do you limit it?

It can grow into a "god object" that knows everything. Keep one mediator per small group (this one form), and keep logic that belongs to one field inside that field.
