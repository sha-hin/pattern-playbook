Scores of 140 got into the database

Value Object

New ticket

Hany’s average is 49.67 and the Ministry already has the CSV

From Mona Saleh, Head of Quality, Smouha Language School

Our scale is 1 to 5. Hany shows 49.67, and Nadia shows 1.50 although her students rated her 3. We also found an evaluation from a "studnet". Please make sure this can never happen again, whichever screen the answers come from.

Why the quick fix is a trap

The quick fix is an if before the INSERT:

the quick fix (we won’t do this)
if ($answer['score'] < 1 || $answer['score'] > 5) {
    continue;   // skip it
}

This has three problems. Answers will soon arrive from more places (a CSV import, an API, an admin screen), and each one needs the same if; the first place that forgets it lets 140 in again. continue drops the answer silently, so nobody knows it was lost. And the rest of the code still receives a plain string or int, so it can never be sure the value was checked.

We need the check to live in one place that every answer must pass through, and we need the result of that check to travel with the value.

The pattern: Value Object

Remember itA small object that wraps one value, checks it once when it is created, and can never change afterwards. If you hold one, it is valid.

Instead of passing the integer 4 around, we pass a Score object that contains 4. The only way to create a Score is its constructor, and the constructor refuses anything outside 1–5. So any function that receives a Score knows it is valid, without checking again.

Three rules make it work: it checks itself in the constructor, it can’t change (all properties are readonly), and two value objects with the same value are equal (we compare them with equals(), not by identity).

Value Object is not in the Gang of Four book. It comes from Domain-Driven Design (Eric Evans, 2003) and is one of the most used patterns in modern PHP.

  3. 3The Score value object

    The constructor is the gate: it accepts an int and refuses anything outside 1–5. final readonly class means nobody can extend it and nothing can change $value after creation.

    Form input is always a string, so fromInput() is a second, named way to build a Score: it accepts "4" and rejects "five" or "4.5" with a clear message, then hands over to the constructor.

    src/Domain/Score.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Domain;

/**
 * One answer on the 1–5 scale.
 *
 * If you hold a Score, it is valid: the constructor is the only way in,
 * and it refuses anything outside 1–5.
 */
final readonly class Score
{
    public const MIN = 1;
    public const MAX = 5;

    public function __construct(public int $value)
    {
        if ($value < self::MIN || $value > self::MAX) {
            throw new InvalidValue("A score must be between 1 and 5, got {$value}.");
        }
    }

    /**
     * Builds a Score from raw form input such as "4".
     */
    public static function fromInput(string $raw): self
    {
        $value = filter_var(trim($raw), FILTER_VALIDATE_INT);

        if ($value === false) {
            throw new InvalidValue("A score must be a whole number, got \"{$raw}\".");
        }

        return new self($value);
    }

    public function equals(self $other): bool
    {
        return $this->value === $other->value;
    }
}

  4. 4The role: an enum

    A role is one of a fixed list. PHP’s backed enum is exactly that: RespondentRole::from('student') works, and there is no way to create a studnet. Enums are value objects built into the language.

    src/Domain/RespondentRole.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Domain;

/**
 * Who answered the survey. A backed enum is PHP's built-in value object for
 * "one of a fixed list": there is no way to create RespondentRole::Studnet.
 */
enum RespondentRole: string
{
    case Student = 'student';
    case Peer = 'peer';
    case Principal = 'principal';

    public static function fromInput(string $raw): self
    {
        $role = self::tryFrom(strtolower(trim($raw)));

        if ($role === null) {
            throw new InvalidValue("Unknown respondent role \"{$raw}\".");
        }

        return $role;
    }
}

  5. 5The EmailAddress value object

    Same idea for emails. It also stores the address in lower case, so Hany@Smouha.edu.eg and hany@smouha.edu.eg are equal.

    src/Domain/EmailAddress.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Domain;

/**
 * A valid email address, stored in lower case so that two spellings of the
 * same address are equal.
 */
final readonly class EmailAddress
{
    public string $value;

    public function __construct(string $value)
    {
        $normalized = strtolower(trim($value));

        if (filter_var($normalized, FILTER_VALIDATE_EMAIL) === false) {
            throw new InvalidValue("\"{$value}\" is not a valid email address.");
        }

        $this->value = $normalized;
    }

    public function equals(self $other): bool
    {
        return $this->value === $other->value;
    }

    public function __toString(): string
    {
        return $this->value;
    }
}

How Laravel does it

Laravel validates the request first ('score' => ['required', 'integer', 'between:1,5']), which gives the user a friendly error. A value object is the second line of defence inside the app: it protects every path, including imports, jobs and tinker.

Eloquent can turn a column into a value object automatically. Enums need nothing but a cast; for your own classes you write a small cast class:

Laravel
final class ScoreCast implements CastsAttributes
{
    public function get(Model $model, string $key, mixed $value, array $attributes): Score
    {
        return new Score((int) $value);
    }

    /** @param Score $value */
    public function set(Model $model, string $key, mixed $value, array $attributes): int
    {
        return $value->value;
    }
}

// In the Response model:
protected function casts(): array
{
    return [
        'score' => ScoreCast::class,
        'role' => RespondentRole::class,
    ];
}

Check yourself

Answer in your head, then open the answer.

Why does Score check the range in the constructor and not in the code that saves answers?

Because the constructor is the only way to create a Score. Every path that creates one, now and in the future, goes through the check, and code that receives a Score never has to check again.

What does readonly protect against?

Changing the value after it was checked. Without it, $score->value = 140 would make a valid object invalid.

Why is the result printed as "Row 2: …" instead of skipping the row?

A skipped row is lost data that nobody knows about. Rejecting loudly lets someone fix the source.

The report, the emails and the CSV still run the same SQL three times. The next ticket adds a rule to that SQL.
