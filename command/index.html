Command

BehaviourGoF book

A restaurant ticket: the order is written down, so it can wait in line, be retried, or be torn up.

The rule to rememberAn action you want to run later, queue, retry, log or undo → turn the action into an object.

Without it: the pain

The controller runs a 40-second AI analysis. The user waits, the request times out, the work is lost.

With it: the fix

The action becomes a job object. The controller queues it and answers instantly; a worker runs and retries it.

Reach for it when you see

  • Slow work inside an HTTP request
  • "Retry it if the API fails" requirements
  • Undo / redo, or an audit trail of actions

Real job where it fits

After a survey closes, send all responses to an AI service for analysis (slow, can fail).

Before: the code that hurts

public function close(Survey $survey, AiAnalyzer $ai)
{
    $survey->close();
    $analysis = $ai->analyze($survey->responses);   // 40 seconds; timeout = lost
    $survey->saveAnalysis($analysis);
    return back();
}

Build it yourself: the full Command pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

CommandCommand an interface with one method: execute()
Concrete commandAnalyzeSurvey one action, packed into an object
ReceiverAiAnalyzer the object that does the real work
InvokerCommandQueue keeps commands now, runs them later, retries failures
<?php

declare(strict_types=1);

// ── Step 1: the Command interface ──
interface Command  // Command
{
    public function execute(): void;
}

// ── Step 2: the Receiver. Does the real work. ──
final class AiAnalyzer  // Receiver
{
    private int $calls = 0;

    public function analyze(int $surveyId): string
    {
        $this->calls++;
        if ($this->calls === 1) {
            throw new RuntimeException('AI service timeout');   // fails the first time, like real APIs
        }

        return "Survey {$surveyId}: teachers rate classroom time highest";
    }
}

// ── Step 3: a concrete command. The action, as an object. ──
final class AnalyzeSurvey implements Command  // Concrete command
{
    public function __construct(private readonly AiAnalyzer $analyzer, private readonly int $surveyId)
    {
    }

    public function execute(): void
    {
        echo $this->analyzer->analyze($this->surveyId) . "\n";
    }
}

// ── Step 4: the Invoker. Because the action is an object, it can wait in a list. ──
final class CommandQueue  // Invoker
{
    /** @var list<array{command: Command, attempts: int}> */
    private array $waiting = [];

    public function push(Command $command): void  // keep it now...
    {
        $this->waiting[] = ['command' => $command, 'attempts' => 0];
    }

    public function work(int $maxAttempts = 3): void  // ...run it later
    {
        while (count($this->waiting) > 0) {
            $job = array_shift($this->waiting);

            try {
                $job['command']->execute();
            } catch (Exception $e) {
                $job['attempts']++;
                echo "Attempt {$job['attempts']} failed: {$e->getMessage()}\n";

                if ($job['attempts'] < $maxAttempts) {
                    $this->waiting[] = $job;                // put it back to retry
                } else {
                    echo "Gave up after {$maxAttempts} attempts.\n";   // never silent
                }
            }
        }
    }
}

// ── Using it ──
$queue = new CommandQueue();

// The web request: queue the slow work and answer immediately.
$queue->push(new AnalyzeSurvey(new AiAnalyzer(), 42));
echo "HTTP 202: analysis started\n";

// The worker process (later): run it, retrying on failure.
$queue->work();

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

final class AnalyzeSurveyResponses implements ShouldQueue  // the action as an object
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 3;
    public array $backoff = [30, 120, 600];                     // wait longer after each failure

    public function __construct(public readonly int $surveyId) {}  // only data, so it can travel

    public function handle(AiAnalyzer $ai, SurveyRepository $surveys): void   // dependencies at run time
    {
        $survey = $surveys->findOrFail($this->surveyId);
        $surveys->saveAnalysis($survey, $ai->analyze($survey->responses()));
    }

    public function failed(Throwable $e): void                  // after the last retry: never silent
    {
        Log::error('survey.analysis.failed', ['survey' => $this->surveyId, 'error' => $e->getMessage()]);
    }
}

public function close(Survey $survey)
{
    DB::transaction(function () use ($survey) {
        $survey->close();
        AnalyzeSurveyResponses::dispatch($survey->id)->afterCommit();  // queue it, answer now
    });

    return back()->with('status', 'Analysis started.');
}

How Laravel builds it inside: Queued jobs are commands. dispatch(new AnalyzeSurvey($id)) turns the job object into text with serialize() and stores it in the queue. A worker process later turns it back into an object and calls handle(), retrying as many times as $tries allows.
