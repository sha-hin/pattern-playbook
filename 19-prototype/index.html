Prototype

New ticket

Editing next term’s survey changed this term’s survey

From Mona Saleh, Head of Quality

We copied the 2026-T2 survey to prepare 2027-T1 and added a homework question to Time management. Now the 2026-T2 survey, which 1,200 students already answered, also shows that question, and its scores changed.

Why the quick fix is a trap

The copy was made with PHP’s clone, which looked right:

the quick fix (we won’t do this)
$nextTerm = clone $thisTerm;
$nextTerm->rename('Teacher evaluation 2027-T1');
$nextTerm->section('Time management')->add(new Question('q7', 'Gives homework back within a week'));
// $thisTerm now has q7 too!

clone makes a shallow copy: a new root object, but its $children array still points to the same section objects as the original. Adding a question to the copy’s Time management section adds it to the only Time management section there is.

Rebuilding the survey from scratch avoids the bug but means re-typing 40 lines for every term. We want a real, independent copy that we then edit.

The pattern: Prototype

Remember itA new object should start as a copy of an existing, configured one → clone it, and make the clone deep where it must own its parts.

In PHP, clone creates the copy and then runs __clone() on the new object. Section::__clone() replaces each child section with a clone of it; each of those runs its own __clone() for its children. The result is a deep copy of every section, at any depth.

Questions are not cloned. They are readonly and can never change, so the original and the copy can safely share them, which also saves memory. Deep-copy what can change; share what can’t.

The surveys from earlier terms are the prototypes: configured objects you copy instead of building new ones from nothing.

  2. 2Copy, then change only what’s new

    The script copies this term’s survey, renames it, adds a question deep inside, and compares the two.

declare(strict_types=1);

/*
 * Evalu8, chapter 19: start next term's survey from a copy of this term's.
 *
 *     composer dump-autoload
 *     php bin/new-term.php
 */

require __DIR__ . '/../vendor/autoload.php';

use Evalu8\Survey\Question;
use Evalu8\Survey\Section;
use Evalu8\Survey\TeacherEvaluationSurvey;
use Evalu8\Survey\Visitor\QuestionCounter;

function questionCount(Section $survey): int
{
    $counter = new QuestionCounter();
    $survey->accept($counter);

    return $counter->questions;
}

$thisTerm = TeacherEvaluationSurvey::create();             // already answered by 1,200 students

// "Start from last term": copy it, then change only what's new.
$nextTerm = clone $thisTerm;
$nextTerm->rename('Teacher evaluation 2027-T1');
$nextTerm->section('Time management')->add(new Question('q7', 'Gives homework back within a week'));

echo "THIS TERM: {$thisTerm->title()}\n";
echo '  questions: ' . questionCount($thisTerm) . "\n";
echo '  Time management: ' . count($thisTerm->section('Time management')->children()) . " questions\n\n";

echo "NEXT TERM: {$nextTerm->title()}\n";
echo '  questions: ' . questionCount($nextTerm) . "\n";
echo '  Time management: ' . count($nextTerm->section('Time management')->children()) . " questions\n\n";

$sameSection = $thisTerm->section('Time management') === $nextTerm->section('Time management');
$sameQuestion = $thisTerm->children()[2] === $nextTerm->children()[2];
echo 'Sections shared between the two? ' . ($sameSection ? 'yes' : 'no, each survey has its own') . "\n";
echo 'Questions shared between the two? ' . ($sameQuestion ? 'yes, safely: a Question can never change' : 'no') . "\n";

How Laravel does it

Eloquent’s $model->replicate() is a prototype operation: it copies one row’s attributes into a new, unsaved model, without the primary key and timestamps. It does not copy relations; for a survey with sections and questions you replicate the children yourself, inside a transaction.

Laravel
$copy = DB::transaction(function () use ($survey): Survey {
    $copy = $survey->replicate(['published_at']);
    $copy->title = 'Teacher evaluation 2027-T1';
    $copy->save();

    foreach ($survey->sections as $section) {
        $copy->sections()->save($section->replicate());   // and so on for each level
    }

    return $copy;
});

Check yourself

Answer in your head, then open the answer.

What does PHP’s clone copy by default?

The object itself and its property values. Objects held in properties (or inside arrays) are not copied: the copy points to the same ones.

Why aren’t questions cloned in __clone()?

They are immutable. Nobody can change a shared question, so sharing is safe and saves memory.

When is __clone() called, and on which object?

Right after clone, on the new copy, never on the original.
