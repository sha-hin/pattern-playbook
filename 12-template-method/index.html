Import answers from Google Forms CSV, Excel and JSON

Template Method

New ticket

Answers from Microsoft Forms skipped validation and saved a score of 7

From Support desk

Some schools collect answers with Google Forms (CSV download), others with Microsoft Forms (JSON export). The two imports were written separately. The JSON one never checks that the teacher exists, and it saved a score of 7. Both must follow exactly the same rules.

Why the quick fix is a trap

Two importers, written months apart:

the quick fix (we won’t do this)
final class GoogleFormsCsvImport
{
    public function import(string $path): void
    {
        // read CSV → map columns → validate with value objects → check teacher → save
    }
}

final class MicrosoftFormsJsonImport
{
    public function import(string $path): void
    {
        // read JSON → map fields → save            (validation forgotten)
    }
}

The two classes share most of their steps (validate, check the teacher, save, report rejected rows) but each has its own copy. A rule added to one is missing from the other, and a third format next term means a third copy.

Only two steps really differ between formats: how to read the file and where each field is. The order of the steps and the validation must be the same for everyone.

The pattern: Template Method

Remember itSeveral classes follow the same recipe with a few different steps → write the recipe once in a base class (a final method) and let subclasses fill in only the steps that differ.

AnswerImport::import() is the template method: read → map → validate → save, always in that order. It is final, so no subclass can reorder it or skip validation.

The steps that differ are abstract methods: readRows() and mapRow(). Each format implements those two and nothing else. A hook is a step with a default that subclasses *may* replace: roleText() tidies the role label, and Microsoft Forms overrides it because it labels roles as "Peer (colleague)".

The base class calls the subclass, not the other way round. This is sometimes called the Hollywood principle: "don’t call us, we’ll call you".

  5. 5The base class and its template method

    import() is final and runs the steps in order. readRows(), mapRow() and sourceName() are abstract: every subclass must write them. roleText() is a hook with a default.

    Validation and the teacher check are private: subclasses can’t see them, so they can’t skip them.

    src/Import/AnswerImport.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Import;

use Evalu8\Domain\InvalidValue;
use Evalu8\Domain\RespondentRole;
use Evalu8\Domain\Response;
use Evalu8\Domain\ResponseRepository;
use Evalu8\Domain\Score;
use Evalu8\Domain\TeacherRepository;

/**
 * Template Method: import() is the fixed recipe every file format follows.
 * Subclasses fill in only the steps that differ: how to read the file and where each field is.
 */
abstract class AnswerImport
{
    public function __construct(
        private readonly ResponseRepository $responses,
        private readonly TeacherRepository $teachers,
    ) {
    }

    /**
     * The template method. `final`: the order of the steps, and the validation, can't be changed or skipped.
     */
    final public function import(string $path, string $term): ImportResult
    {
        $knownTeachers = $this->knownTeacherIds();
        $imported = 0;
        $rejected = [];

        foreach ($this->readRows($path) as $line => $row) {        // 1. read     (differs per format)
            $raw = $this->mapRow($row);                             // 2. map      (differs per format)

            try {
                $response = $this->toResponse($raw, $term, $knownTeachers);   // 3. validate (the same for all)
            } catch (InvalidValue $e) {
                $rejected[] = "row {$line}: {$e->getMessage()}";
                continue;
            }

            $this->responses->add($response);                       // 4. save     (the same for all)
            $imported++;
        }

        return new ImportResult($this->sourceName(), $imported, $rejected);
    }

    /**
     * Step 1: read the file. Keys are row numbers (or ids), so rejections can point at the right row.
     *
     * @return iterable<int, array<string, string>>
     */
    abstract protected function readRows(string $path): iterable;

    /**
     * Step 2: find our four fields in this format's row.
     *
     * @param array<string, string> $row
     */
    abstract protected function mapRow(array $row): RawAnswer;

    /** A name for messages, e.g. "Google Forms CSV". */
    abstract protected function sourceName(): string;

    /**
     * A hook: a step with a sensible default that a subclass MAY replace.
     * Forms tools label roles differently ("Peer (colleague)"); the default just tidies the text.
     */
    protected function roleText(string $label): string
    {
        return strtolower(trim($label));
    }

    /** @param array<int, true> $knownTeachers */
    private function toResponse(RawAnswer $raw, string $term, array $knownTeachers): Response
    {
        $teacherId = filter_var($raw->teacherId, FILTER_VALIDATE_INT);
        if ($teacherId === false || !isset($knownTeachers[$teacherId])) {
            throw new InvalidValue("Unknown teacher \"{$raw->teacherId}\".");
        }

        return new Response(
            $teacherId,
            $term,
            RespondentRole::fromInput($this->roleText($raw->role)),
            Score::fromInput($raw->score),
            trim($raw->comment),
        );
    }

    /** @return array<int, true> */
    private function knownTeacherIds(): array
    {
        $ids = [];
        foreach ($this->teachers->all() as $teacher) {
            $ids[$teacher->id] = true;
        }

        return $ids;
    }
}

  6. 6Google Forms: read CSV, map columns

    readRows() is a generator: it yields one row at a time, keyed by its line number in the file.

    src/Import/GoogleFormsCsvImport.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Import;

use RuntimeException;

/**
 * Google Forms → "Download responses (.csv)". The first line holds the question titles.
 */
final class GoogleFormsCsvImport extends AnswerImport
{
    protected function readRows(string $path): iterable
    {
        $file = fopen($path, 'r');
        if ($file === false) {
            throw new RuntimeException("Can't open {$path}.");
        }

        try {
            $header = fgetcsv($file, escape: '');
            if ($header === false) {
                return;
            }

            $line = 1;
            while (($values = fgetcsv($file, escape: '')) !== false) {
                $line++;
                if ($values === [null]) {
                    continue;                               // a blank line
                }

                /** @var array<string, string> $row */
                $row = array_combine($header, array_pad(array_map('strval', $values), count($header), ''));
                yield $line => $row;
            }
        } finally {
            fclose($file);
        }
    }

    protected function mapRow(array $row): RawAnswer
    {
        return new RawAnswer($row['Teacher ID'], $row['You are'], $row['Score (1-5)'], $row['Comment']);
    }

    protected function sourceName(): string
    {
        return 'Google Forms CSV';
    }
}

  7. 7Microsoft Forms: read JSON, map fields, replace the hook

    It overrides roleText() to translate its own labels, and calls parent::roleText() to keep the default tidying.

    src/Import/MicrosoftFormsJsonImport.phpnew fileGitHub
    <?php

declare(strict_types=1);

namespace Evalu8\Import;

use RuntimeException;

/**
 * Microsoft Forms → export as JSON: a list of submissions, each with an "answers" object.
 */
final class MicrosoftFormsJsonImport extends AnswerImport
{
    private const ROLE_LABELS = [
        'peer (colleague)' => 'peer',
        'principal / head' => 'principal',
    ];

    protected function readRows(string $path): iterable
    {
        $json = file_get_contents($path);
        if ($json === false) {
            throw new RuntimeException("Can't open {$path}.");
        }

        /** @var list<array{id: int, answers: array<string, string>}> $submissions */
        $submissions = json_decode($json, true, flags: JSON_THROW_ON_ERROR);

        foreach ($submissions as $submission) {
            yield $submission['id'] => $submission['answers'];   // the "row number" is the submission id
        }
    }

    protected function mapRow(array $row): RawAnswer
    {
        return new RawAnswer($row['teacher'] ?? '', $row['role'] ?? '', $row['rating'] ?? '', $row['feedback'] ?? '');
    }

    protected function sourceName(): string
    {
        return 'Microsoft Forms JSON';
    }

    /** This tool uses its own labels for roles, so this subclass replaces the hook. */
    protected function roleText(string $label): string
    {
        $text = parent::roleText($label);

        return self::ROLE_LABELS[$text] ?? $text;
    }
}

{
    echo "{$result->source}: {$result->imported} imported, " . count($result->rejected) . " rejected\n";
    foreach ($result->rejected as $reason) {
        echo "  {$reason}\n";
    }
}

report($app->make(GoogleFormsCsvImport::class)->import(__DIR__ . '/../data/google-forms.csv', CURRENT_TERM));
report($app->make(MicrosoftFormsJsonImport::class)->import(__DIR__ . '/../data/microsoft-forms.json', CURRENT_TERM));

How Laravel does it

Form requests are a template method: Laravel always runs prepareForValidation(), then your authorize(), then validation with your rules(), then passedValidation(). You fill in rules() and authorize() and may override the two hooks.

Packages like Laravel Excel use the same idea: you implement model() or collection(), and the package owns the reading, chunking and transactions.

Laravel
final class StoreAnswerRequest extends FormRequest
{
    public function authorize(): bool            // a step you must fill in
    {
        return $this->user()->can('answer', $this->route('survey'));
    }

    public function rules(): array               // another one
    {
        return ['score' => ['required', 'integer', 'between:1,5']];
    }

    protected function prepareForValidation(): void   // a hook you may override
    {
        $this->merge(['role' => strtolower(trim($this->input('role', '')))]);
    }
}

Check yourself

Answer in your head, then open the answer.

Why is import() declared final?

So no subclass can change the order of the steps or skip validation. The recipe is the one thing every format must share.

What is the difference between an abstract step and a hook?

An abstract step must be written by every subclass. A hook has a default implementation that a subclass may replace if it needs to.

A Typeform export arrives. What do you write?

One subclass with readRows(), mapRow() and sourceName(). Validation and saving come for free.

Admins want to preview the first rows of a file before importing it, and an Excel export with semicolons arrives. The reading code is locked inside each importer.
