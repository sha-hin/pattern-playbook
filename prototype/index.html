Prototype

CreationGoF book

"Make a copy" of a Google Doc: start from a full copy, then change the title.

The rule to rememberYou need "the same as this one, with small changes" → copy an existing object, deep-copy what it owns, share what it only points to.

Without it: the pain

Rebuilding a 40-question survey by hand, or a copy that shares questions so editing the copy changes the original.

With it: the fix

Copy the survey row, deep-copy its questions and options, keep pointing to the same school and author.

Reach for it when you see

  • "Duplicate", "copy from last term", "use as template" buttons
  • Copies that accidentally change the original
  • Rebuilding big objects field by field

Real job where it fits

Schools duplicate last term’s survey (40 questions, 160 options) and change the dates.

Before: the code that hurts

$copy = $original->replicate();
$copy->save();
// $copy has NO questions: replicate() copies the row only.
// Or worse: pointing the copy at the same question rows → editing one edits both.

After: how you implement the Prototype pattern in PHP

public function duplicate(Survey $original, string $newTitle): Survey
{
    return DB::transaction(function () use ($original, $newTitle) {    // all or nothing
        $copy = $original->replicate(['published_at']);  // copy the row (not its relations)
        $copy->title = $newTitle;
        $copy->save();                                        // school_id, author_id: shared on purpose

        foreach ($original->questions()->with('options')->get() as $question) {
            $newQuestion = $copy->questions()->save($question->replicate());  // deep copy owned children
            $newQuestion->options()->saveMany(
                $question->options->map(fn (Option $o) => $o->replicate()),
            );
        }

        return $copy;
    });
}
