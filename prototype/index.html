Prototype

CreationGoF book

"Make a copy" of a Google Doc: start from a full copy, then change the title.

The rule to rememberYou need "the same as this one, with small changes" → copy an existing object, deep-copy what it owns, share what it only points to.

Without it: the pain

Rebuilding a 40-question survey by hand, or a copy that shares questions so editing the copy changes the original.

With it: the fix

Copy the survey row, deep-copy its questions and options, keep pointing to the same school and author.

Reach for it when you see

  • "Duplicate", "copy from last term", "use as template" buttons
  • Copies that accidentally change the original
  • Rebuilding big objects field by field

Real job where it fits

Schools duplicate last term’s survey (40 questions, 160 options) and change the dates.

Before: the code that hurts

$copy = $original->replicate();
$copy->save();
// $copy has NO questions: replicate() copies the row only.
// Or worse: pointing the copy at the same question rows → editing one edits both.

Build it yourself: the full Prototype pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

PrototypeSurvey an existing object you copy instead of building from scratch
clonePHP's copy keyword copies the object, but objects INSIDE it are still shared
__clone()runs on the new copy, so it can copy what the copy should own a deep copy
Shared on purposeSchool both surveys belong to the same school
<?php

declare(strict_types=1);

final class School
{
    public function __construct(public readonly string $name)
    {
    }
}

final class Question
{
    public function __construct(public string $text)
    {
    }
}

// ── The Prototype ──
final class Survey  // Prototype
{
    /**
     * @param list<Question> $questions
     */
    public function __construct(
        public string $title,
        public readonly School $school,
        public array $questions,
    ) {
    }

    public function __clone(): void  // runs on the NEW copy, right after clone
    {
        $copies = [];
        foreach ($this->questions as $question) {
            $copies[] = clone $question;  // the copy gets its OWN questions
        }
        $this->questions = $copies;

        // $this->school is NOT cloned: both surveys belong to the same school.
    }
}

// ── Last term's survey ──
$school = new School('Smouha Language School');
$lastTerm = new Survey('Term 1 evaluation', $school, [
    new Question('Explains clearly'),
    new Question('Starts on time'),
]);

// ── "Start new term from last term": copy it, then change what differs ──
$nextTerm = clone $lastTerm;  // copy instead of rebuilding
$nextTerm->title = 'Term 2 evaluation';
$nextTerm->questions[0]->text = 'Explains clearly and checks understanding';

echo 'Original: ' . $lastTerm->title . ' / ' . $lastTerm->questions[0]->text . "\n";
echo 'Copy:     ' . $nextTerm->title . ' / ' . $nextTerm->questions[0]->text . "\n";
echo 'Same school? ' . ($lastTerm->school === $nextTerm->school ? 'yes' : 'no') . "\n";

// Delete the __clone() method and run again: editing the copy's question
// changes the original too, because both would share the same Question objects.

Highlighted lines are the ones that make it this pattern. Run it: php examples/prototype.php · Open the file on GitHub

Output

Copy:     Term 2 evaluation / Explains clearly and checks understanding

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

public function duplicate(Survey $original, string $newTitle): Survey
{
    return DB::transaction(function () use ($original, $newTitle) {    // all or nothing
        $copy = $original->replicate(['published_at']);  // copy the row (not its relations)
        $copy->title = $newTitle;
        $copy->save();                                        // school_id, author_id: shared on purpose

        foreach ($original->questions()->with('options')->get() as $question) {
            $newQuestion = $copy->questions()->save($question->replicate());  // deep copy owned children
            $newQuestion->options()->saveMany(
                $question->options->map(fn (Option $o) => $o->replicate()),
            );
        }

        return $copy;
    });
}

How Laravel builds it inside: $model->replicate() copies ONE row's columns into a new, unsaved model (without the id and timestamps). Related rows are not copied: the copy even points at the same loaded relation objects. Owned children like questions must be replicated by hand.
