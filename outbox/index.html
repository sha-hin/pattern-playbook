Transactional Outbox

BehaviourNot in the book

A sealed envelope in the outgoing tray: it leaves only if the paperwork is filed, and the courier keeps trying until it’s delivered.

The rule to rememberSaving data AND calling an outside system must never get out of sync → write the message in the same DB transaction; a worker sends it and retries.

Without it: the pain

Save, then call the API: the server crashes between the two lines. The data is saved; the partner never hears about it, and nobody knows.

With it: the fix

The message is a row saved in the same transaction. A worker sends unsent rows, retries failures, and logs them.

Reach for it when you see

  • "The order is saved but the email / webhook never went out"
  • Data save + external API call in the same request
  • Payments, partner syncs, webhooks that must never be lost

Real job where it fits

When an evaluation is approved, the ministry’s API must be notified. Never lost, never twice.

Before: the code that hurts

$evaluation->update(['status' => 'approved']);
Http::post($ministryUrl, ['evaluation_id' => $evaluation->id]);
// crash, deploy or timeout between these two lines → the ministry never knows

Build it yourself: the full Transactional Outbox pattern in plain PHP

No framework. Every part of the pattern is here, labelled with its role. Copy it, run it, change it.

Business write + outbox rowApproveEvaluation both saved in ONE database transaction
Outboxthe "outbox" table messages waiting to be sent
RelayOutboxRelay a worker that sends waiting messages and retries failures
Idempotent receiverMinistryApi ignores a message it has already processed
<?php

declare(strict_types=1);

// ── The external system. Unreliable, like real APIs. ──
final class MinistryApi
{
    /** @var array<string, true> */
    private array $alreadyReceived = [];
    private int $calls = 0;

    public function sync(int $evaluationId, string $key): void
    {
        $this->calls++;
        if ($this->calls === 1) {
            throw new RuntimeException('Ministry API: 503 Service Unavailable');
        }

        if (isset($this->alreadyReceived[$key])) {  // idempotent: a repeat does nothing
            echo "Ministry: already have {$key}, ignored\n";

            return;
        }

        $this->alreadyReceived[$key] = true;
        echo "Ministry: received evaluation {$evaluationId}\n";
    }
}

// ── Step 1: save the data AND the message in one transaction ──
final class ApproveEvaluation
{
    public function __construct(private readonly PDO $db)
    {
    }

    public function handle(int $evaluationId): void
    {
        $this->db->beginTransaction();  // ONE transaction for both writes

        try {
            $approve = $this->db->prepare("UPDATE evaluations SET status = 'approved' WHERE id = ?");
            $approve->execute([$evaluationId]);

            $message = $this->db->prepare('INSERT INTO outbox (message_key, evaluation_id) VALUES (?, ?)');
            $message->execute(["ministry-sync:{$evaluationId}", $evaluationId]);  // the message, saved with the data

            $this->db->commit();                            // both are saved, or neither is
        } catch (Exception $e) {
            $this->db->rollBack();
            throw $e;
        }
    }
}

// ── Step 2: the relay. A worker that runs every minute. ──
final class OutboxRelay  // Relay
{
    public function __construct(private readonly PDO $db, private readonly MinistryApi $api)
    {
    }

    public function run(): void
    {
        $rows = $this->db->query('SELECT * FROM outbox WHERE sent_at IS NULL AND attempts < 10')->fetchAll();

        foreach ($rows as $row) {
            try {
                $this->api->sync((int) $row['evaluation_id'], $row['message_key']);

                $sent = $this->db->prepare("UPDATE outbox SET sent_at = datetime('now') WHERE id = ?");
                $sent->execute([$row['id']]);
            } catch (Exception $e) {
                $failed = $this->db->prepare('UPDATE outbox SET attempts = attempts + 1, last_error = ? WHERE id = ?');
                $failed->execute([$e->getMessage(), $row['id']]);
                echo "Relay: will retry next minute ({$e->getMessage()})\n";
            }
        }
    }
}

// ── Setup: an in-memory SQLite database ──
$db = new PDO('sqlite::memory:');
$db->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$db->setAttribute(PDO::ATTR_DEFAULT_FETCH_MODE, PDO::FETCH_ASSOC);
$db->exec("CREATE TABLE evaluations (id INTEGER PRIMARY KEY, status TEXT DEFAULT 'submitted')");
$db->exec('CREATE TABLE outbox (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    message_key TEXT NOT NULL UNIQUE,
    evaluation_id INTEGER NOT NULL,
    attempts INTEGER NOT NULL DEFAULT 0,
    last_error TEXT,
    sent_at TEXT
)');
$db->exec('INSERT INTO evaluations (id) VALUES (42)');

$relay = new OutboxRelay($db, new MinistryApi());

// ── Using it ──
(new ApproveEvaluation($db))->handle(42);                   // the request saves both, sends nothing

$relay->run();                                              // minute 1: the API is down
$relay->run();                                              // minute 2: delivered

// If the worker crashed after sending but before marking it sent, it would send it again:
$db->exec('UPDATE outbox SET sent_at = NULL');
$relay->run();                                              // the receiver ignores the repeat

In a real Laravel project

The same pattern the way you would write it at work, using what the framework already gives you.

DB::transaction(function () use ($evaluation) {
    $evaluation->update(['status' => 'approved']);

    DB::table('outbox')->insert([  // same transaction: both or neither
        'idempotency_key' => "ministry-sync:{$evaluation->id}",      // unique index: never recorded twice
        'type'            => 'ministry.sync',
        'payload'         => json_encode(['evaluation_id' => $evaluation->id]),
        'attempts'        => 0,
        'created_at'      => now(),
    ]);
});

// Worker — schedule: ->everyMinute()->withoutOverlapping()
DB::table('outbox')->whereNull('sent_at')->where('attempts', '<', 10)->orderBy('id')->limit(100)->get()
    ->each(function (object $row) use ($ministry) {
        try {
            $ministry->sync(json_decode($row->payload, true), $row->idempotency_key);  // receiver ignores repeats
            DB::table('outbox')->where('id', $row->id)->update(['sent_at' => now()]);
        } catch (Throwable $e) {
            DB::table('outbox')->where('id', $row->id)
                ->increment('attempts', 1, ['last_error' => mb_substr($e->getMessage(), 0, 1000)]);
            Log::error('outbox.failed', ['id' => $row->id, 'error' => $e->getMessage()]);   // never silent
        }
    });

How Laravel builds it inside: With the "database" queue driver, a queued job is just a row in the jobs table. Dispatch a job inside DB::transaction() on the same connection, and the job row is saved in the SAME transaction as your data: the jobs table becomes your outbox, and queue:work is the relay.
